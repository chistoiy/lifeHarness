## 二、数据模型（DB v16 · 按日流水为中心）

约定：宿主库 `lifeharness.db`；`habit_` 前缀；软删除统一 `deleted_at`；时间戳 `INTEGER`（epoch ms）；**自然日一律 TEXT `'YYYY-MM-DD'`**（与 D13「日界线固定 00:00」一致，避免时区与跨天歧义）；JSON 列以 TEXT 存。

### 2.1 主表与子表

```
habits(
  id TEXT PK, name TEXT NOT NULL, icon TEXT NOT NULL,     -- HB_IC 线性图标 key（禁 emoji）
  type TEXT NOT NULL,                      -- pos | neg
  cat TEXT,                                -- 引用 habit_dict(kind='cat').name，非外键（改名走迁移）
  cycle TEXT NOT NULL,                     -- day | week | month
  week_days TEXT,                          -- JSON [0..6]，cycle=week 时的固定日；空=每天
  month_target INTEGER,                    -- cycle=month 的正向目标次数
  neg_limit INTEGER DEFAULT 0,             -- 负向：周期内触发上限（0=一次都不许）
  unit TEXT, goal REAL,                    -- 记录量单位（引用 habit_dict(kind='unit')）与每日目标量；unit 为空=纯布尔打卡
  group_rule TEXT NULL,                    -- all | half | any；NULL=非组
  source_kinds TEXT,                       -- JSON [manual|todo|pomo|read|schedule]（自动达成源）
  remind_at TEXT,                          -- 'HH:MM'；仅提醒锚点，不参与达成判定
  todo_id TEXT NULL,                       -- L10 自动生成的关联待办
  todo_form TEXT,                          -- normal | pomo（番茄 30 分钟档）
  start_date TEXT NOT NULL,                -- 开始跟踪日（口径分母起点）
  goal REAL NULL, streak INTEGER DEFAULT 0, best INTEGER DEFAULT 0,  -- streak/best 为**缓存列**，写入时重算，导入后按流水全量重算
  archived_at INTEGER NULL, created_at INTEGER, updated_at INTEGER, deleted_at INTEGER)
  索引：cat / type / archived_at / todo_id

habit_subs(id INTEGER PK, habit_id TEXT NOT NULL, name TEXT, unit TEXT, goal REAL, sort INTEGER)
  -- 组内子项；非组习惯 0 行

habit_entries(                             -- ★ 一天一条主记录（正/负同表；负向「未触发」也落行，value 可为 NULL）
  id INTEGER PK, habit_id TEXT NOT NULL, day TEXT NOT NULL,
  checked INTEGER NOT NULL DEFAULT 1,      -- 正向=已达成；负向=当日未触发/已规避
  value REAL NULL,                         -- 非组习惯的记录量（h.v）；NULL=只打卡无量
  origin TEXT NOT NULL,                    -- manual | auto-todo | auto-pomo | auto-read | auto-schedule | backfill | template
  check_at TEXT,                           -- 'HH:MM' 打卡时刻（自动源取源事件完成时刻）
  backfilled INTEGER DEFAULT 0,            -- 补记（统计需单列展示，UI 加 ring-amber）
  frozen INTEGER DEFAULT 0,                -- 宽限卡抵断签日：checked=0 但不断连
  note TEXT, created_at INTEGER, updated_at INTEGER,
  UNIQUE(habit_id, day))                    -- 同日二次写=UPSERT 改值，不新增
  索引：habit_id / day / backfilled

habit_entry_subs(id INTEGER PK, entry_id INTEGER NOT NULL, sub_id INTEGER NOT NULL, value REAL,
  UNIQUE(entry_id, sub_id))                -- 组打卡逐子项数值（h.sv[d][]）

habit_slips(                               -- 负向习惯的每次触发（h.slips）
  id INTEGER PK, habit_id TEXT NOT NULL, day TEXT NOT NULL, check_at TEXT,
  amount REAL,                             -- 「记一次触发」的量（55 分钟 / 1 杯）
  amount_text TEXT,                        -- 展示串（原型 amt：'1 杯 · 大杯'）
  reasons TEXT,                            -- JSON 情境标签（应酬/失眠/赶时间…）
  note TEXT, created_at INTEGER)
  索引：habit_id / day

habit_goal_hist(id INTEGER PK, habit_id TEXT, goal REAL, unit TEXT, sub_goal TEXT, effective_from TEXT NOT NULL)
  -- 目标变更历史：统计按「该日生效目标」判定达成，改目标不追改历史（原型 goalHist）

habit_freezes(id INTEGER PK, habit_id TEXT, day TEXT, used_at INTEGER, source TEXT DEFAULT 'grace')
  -- 宽限卡使用记录；每月配额由 habit.* 设置决定，不在表内计余额（按 月已用 计数推导）

habit_pend(id INTEGER PK, habit_id TEXT, day TEXT, src TEXT, value REAL, sub_values TEXT,
  created_at INTEGER, state TEXT DEFAULT 'pending')   -- pending | ok | no
  -- autoMode=需我确认 时的待确认队列；杀进程重启仍在（AC 要求）

habit_dict(id INTEGER PK, kind TEXT, name TEXT, sort INTEGER)
  -- kind ∈ cat | unit；改名=事务内回写 habits.cat / habits.unit / habit_subs.unit / habit_goal_hist.unit；
  -- 删除前 COUNT 引用 > 0 → 拒绝并提示「先迁移到…」，提供「迁移到…」选择器（原型 hbMgrDel/hbMgrMerge）
```

### 2.2 派生数据不落库（重要）

原型用 `h.w[7] / h.ex{back} / h.mDone / h.triggers / h.mAvoid / h.hrs` 等预置字段驱动渲染；Flutter 侧**全部由查询派生**，避免缓存与流水不一致：

- 某日是否达成 → `habit_entries(habit_id, day)` + 组规则 + 当日生效 `goal_hist`；
- 连续天数 → 按 day 倒序扫描，`frozen=1` 与**非计划日**均不中断（非计划日不计入分母，与 v3 会话口径一致）；
- 周/月/年计数、总量、日均、达成率 → 由 `hbCnt/hbTot/hbAvgPer/hbRate` 的 SQL/内存等价函数计算，**必须带 `hbEffDays` 截断**（口径开关生效点）；
- 热力图、时段分布、排行、纪录墙 → 统计页一次性查询后内存聚合，不建物化表。

### 2.3 迁移与守护

- v16 迁移只做 `CREATE TABLE` + 索引，不猜数据；写法与既有 v3~v15 逐版单段一致。
- 一致性自检（沿用既有 `databaseFactory` 测试范式）：导入/备份恢复后跑「streak/best 全量重算 == 缓存列」，不等则重算并记日志。
- 架构守护 R1/R4 习惯侧新增：`features/habit/**` 不得 import 其他 feature（经 `shared/linkage/habit_mounts.dart` 挂载，与 `read_mounts.dart` 同构）。

### 3.1 结构约定（已按用户批注定稿）

- **hero 卡**：今日达成 n/N + 进度条 + 连续最长 + 待确认计数（`pendN`）+ 日期行；**不含**「周/月/年统计」按钮（本轮按用户指令移除，统计走顶栏入口）。
- **筛选行**：状态与分类各为**一个下拉**（宽度收窄），非平铺 chips；分类下拉的选项来自 `habit_dict`，与自定义能力同源。
- **视图三态循环**：`列表 · 明细与操作` → `紧凑 · 一行一个` → `方块 · 完成度`（`HB_VIEWS`）。方块视图卡内为**完成度环 + 7 日点阵 + 待打卡时刻 + 补记角标**，不显示可点大按钮（点卡进详情，点格子打卡）。
- **今日全部达成横幅**：全部应打卡习惯完成后置灰收敛为一条庆祝横幅，不重复堆卡。
- **详情页**：顶栏承担编辑/更多（底部同名按钮已删，避免重复）；近 30 天为**月历**（日期数字 + 达成/数值圆点，点格看当日明细）。
- **统计页折叠**：首屏只给「周期 hero + 同期对比 + 记录量」，时段/热力图/分类/排行/组构成/负向/纪录墙收在「展开更多」内，避免长屏噪声。

## 五、口径与算法规范（开发必读，易错点集中）

1. **应打卡天数（分母）**：`cycle=day` → 区间内天数 ∩ 开始跟踪日之后（`spanFromStart` 开）；`cycle=week` → 区间内落在 `week_days` 的天数；`cycle=month` → `month_target` 与周期总天数的语义分离（月周期按「次」而非「天」）。
2. **达成率**：`rateBase=0` 按应打卡天数，`rateBase=1` 按周期总天数。**周/月/年一律先截断到 `min(周期天数, 已跟踪天数)`**（防年中新增被全年摊薄——用户点名要的逻辑）。
3. **日均**：分子=该期记录总量，分母=`hbEffDays`（同上截断）；组习惯**不跨单位求和**，按子项分别显示。
4. **同比/环比**：环比=上一相邻期，同比=去年同期；无历史数据时显示「—」而非 0%（避免误读为暴跌）。
5. **记录量取值**：指定周期取「该日生效目标」判达成（`habit_goal_hist`）；改目标不回溯。
6. **非计划日 ≠ 未完成**：既不计入分母也不打断连续（与并行会话 v3 口径一致，此处为全局统一口径）。
7. **补记（backfill）**：计入达成与总量，`backfilled=1` 单独出计数与占比；是否续连续连由「补卡计入连续天数」开关决定。
8. **自动达成**：`origin` 必写来源，`check_at` 取源事件完成时刻；`autoMode=需我确认` 时只进 `habit_pend`，不落 `habit_entries`。
9. **时钟回拨**：以 `max_seen_day` 水位线防护（第八章），回拨不重复计、不断连、不新增未来日记录。
10. **负向习惯的「触发日」是一等数据**：日历、流水、触发统计三处都必须显示（不得被 `checked=0` 的过滤条件剔除），配色 rose 中性事实色；「未触发」用正向 teal，不得用红色表达（AC「不羞辱人」）。
11. **动态 class 只进属性**：模板串里的状态样式（如「今日」高亮 ring）拼进 `class`，不得成为子节点文本（原型踩过：页面裸露出 `ring-1 ring-brand-500 …`）。

## 六、设置项清单（键名 / 默认 / 生效点）

原型 `HB_SET` → 落库键名统一 `habit.*`（存既有 `settings` KV 表，不散落 SharedPreferences）：

| 键 | 默认 | 生效点 |
|---|---|---|
| `habit.spanFromStart` | **true** | 日均/达成率分母只计开始跟踪日之后（`hbEffDays`）——**年中新增不被全年摊薄** |
| `habit.autoChk` | true | 自动达成源是否直接打卡（关闭后仅手动打卡，统计不受影响） |
| `habit.remindAll` | true | 全局提醒总开关（关闭后所有习惯静默，打卡照常） |
| `habit.rateBase` | 0 应打卡天数 | 达成率分母口径（0=应打卡天数 / 1=周期总天数） |
| `habit.weekStart` | 0 周一 | 日历与周统计分列方式 |
| `habit.grace` | 1（每月宽限次数） | 宽限卡配额；0=不用 |
| `habit.autoMode` | 0 直接打卡 | 自动达成处理（0=直接打卡 / 1=需我确认→待确认队列） |
| `habit.nightRemind` | true | 晚间未打卡提醒开关 |
| `habit.nightAt` | 1（20:00） | 晚间提醒时间（18:00/20:00/21:30/22:30） |
| `habit.dnd` | 1（22:00-08:00） | 免打扰时段，区间内不推送 |
| — 归档习惯 | 导航行 | 跳 `/habits?arch=1` |
| — 分类管理 | 导航行 | `habit_dict(kind='cat')` CRUD |
| — 单位管理 | 导航行 | `habit_dict(kind='unit')` CRUD |

另有**逐习惯字段**（不入全局设置）：`remind_at`、`source_kinds`、`todo_form`、`start_date`、`group_rule`、补卡「计入连续」偏好（`habit.backfillStreak`，默认 true）。

## 七、跨模块联动

- **L10 待办**（需求清单 V1.23 既有）：新建习惯可选「自动生成关联待办」（默认开）+ 形态（常规勾选 / 番茄档）；待办勾选或番茄结束**回写打卡**（`origin='auto-todo'|'auto-pomo'`）；反向解绑需二次确认并保留历史打卡。`habits.todo_id` 与 `todos.habit_id` 双向存，避免单侧丢链。

- **收集箱**：收集箱条目可分流为「新建习惯草稿」（预填名称），不自动落库。
- **插件化**：习惯模块保持内建（与待办/番茄强耦合）；仅**模板库**（`HB_TPL` 等价 JSON）走资源包（`assets/habit_templates/*.json`），便于后续社区扩展而不改代码。

## 九、风险与未决

1. **U-1 习惯「今日打卡」页骨架（已按产品口径收窄·仅本模块内部取舍）**：指 `p-habits` 这一页怎么排，**与 App 主页/仪表盘无关，也不涉及其他模块**。本计划事实源 `index_habitcheck.html` 用「hero + 一行筛选 + 三态视图（列表 / 紧凑 / 方块完成度）」；并行会话 `index-habbitcheck-v3.html` 用单张「周格矩阵」。**主会话默认按本文（三态视图）实现**；换周格只替换这一页的排布与打卡手势，§1.1 能力清单、§2 数据模型、§3.2 操作口径、§5 统计口径**全部不变**。两线共需的修复（`syncHabit` 写入今天所在列、周偏移用 `Math.floor` 不用 `round`）无论选哪个都采纳。
2. **组打卡的单位混算**：已在原型修掉（方块卡与 hero 不跨单位求和）。Flutter 侧必须沿用「按子项分别显示」，任何总量卡都要声明单位口径。
3. **达成率分母语义多解**：`cycle=month`（按月目标次数）与 `cycle=week`（固定日）与 `day` 三种分母不同构，单测必须三套各覆盖边界（首日即周期尾、整期未开始跟踪、归档中途恢复）。
4. **待确认队列的通知时机**：晚间提醒 + 免打扰 + 每日「晚确认」三者优先级需在批5 明确（建议：免打扰最高，其次用户自定义提醒时间，最后晚间默认）。
5. **DB 版本冲突**：并行会话的影音游计划也占 v15~v17 编号，实际建库时按 schema.dart 现状顺延，**以仓库为准**，本文 v16 为相对序号。
6. **截图级视觉 QA 已完成（2026-09-23）**，并据此修掉三处原型缺陷，Flutter 侧实现时按修正后的口径做：
   - `hbDots` 的「今日」高亮 class 曾泄漏成可见文本（页面裸露 `ring-1 ring-brand-500 …`）→ 已移入 class 属性。**实现侧对应规则**：动态类名拼接只能进 `class`，不要落进子节点文本（Flutter 里即不要把样式串写进 `Text`）。
   - **负向习惯的触发日必须在日历/流水里显性可见**：原型此前 `if(!g.ok) continue` 把触发日当「未记录」灰掉并从流水剔除，等于把最该看的数据藏了。现日历触发日＝rose 底 + 红点 + tooltip「触发 · N 单位」，图例「绿点=未触发 · 红点=触发」；流水触发日＝加粗 rose「触发 · 1 杯 / 70 分钟」。
   - **负向措辞与配色不得带评判感**（AC 第九章「不羞辱人」）：「未触发」是好状态，用 teal 正向色；「触发」用 rose 中性事实色，不加感叹或红色告警底。
