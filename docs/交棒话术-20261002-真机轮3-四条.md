## R3-1 · P0 系统「下载中心 → 用本应用打开」直接崩到路由错误页

现象：下载中心长按 epub → 其他应用打开 → 选 LifeHarness → 整屏白底
`GoException: no routes for location: content://com.android.providers.downloads.documents/document/999`，
只有一个「Home」钮，文件根本没进导入流程。

根因（已定位到机制，非猜测）：**冷启动**时 Activity 带着 VIEW intent 起来，Flutter 引擎把 intent 的 data
当作**初始路由**交给 go_router，`content://…` 不是任何已注册路由 → 直接 GoException 错误页。
我们那条 `lh/intents.takeEpubUri` 通道（`MainActivity.kt:64-70` 入队 + `open_with.dart:42` 根壳层消费）
根本没机会跑——**页面已经死在路由层**。热启动（App 已在运行）走 `onNewIntent` 才正常，所以 ⑥ 批当时
真机两态里只验过了热启动那一态，冷启动这态没验（清单 §「⑥ 真机两态」本就该覆盖，是我漏跑）。

修法（小、可测）：
1. `MainActivity` 里把「intent data 当初始路由」这条路掐掉：`configureFlutterEngine` 前
   `intent.data = null`（或覆写 `getInitialRoute()` 恒返回 `'/'`），**入队逻辑不变**，
   文件仍由 Dart 侧 `takeEpubUri()` 消费；
2. Dart 侧 `takeEpubUri` 返回的若是 `content://`，必须**先拷进 `cacheDir/lh_open/<原名>` 再返回文件路径**
   （现逻辑如此，但要确认冷启动路径也走到它，而不是拿到原始 URI 就往导入链丢）；
3. 兜底：go_router 加 `errorBuilder`，任何未知 location 落回首页 + 一条可读 toast，
   **不再把工程异常文案直接甩给用户**（这条是通用护栏，别的入口也可能撞）。

验收（必须两态都过）：
- 冷启动态：`am force-stop` → 下载中心点「打开」→ 选本 App → 应直接进导入向导/直接入库并定位书架，不出现错误页；
- 热启动态：App 在前台时同样操作 → 同结果；
- adb 复现脚本：`am start -a android.intent.action.VIEW -d "content://com.android.providers.downloads.documents/document/999" -n com.lifeharness.lifeharness/.MainActivity -t application/epub+zip`；
- release 清单 aapt 复核 intent-filter 仍在（发版门禁项）。

## R3-2 · P0 EPUB 精排丢失（图3 vs 图2 对照）

同一本《资治通鉴》：微信阅读（图2）是正常书籍排版——首行缩进、行距均匀、正文黑、注释小字灰、
标题层级分明；我们（图3）表现为：

1. **字距被拉散**：中文按 `justify` 两端对齐 + 字距/行距设置叠加，末行不满时整行字被拉开成"等宽格子"，
   读起来像表格；
2. **注释编号与注释体被当成正文**：`1`、`2` 顶到行首，注释整段用**绿色链接色**渲染（EPUB 里注释是
   `<a>`/`epub:type=note` 或带内部锚点，我们把所有 `<a>` 一律套 accent 下划线链接色），
   于是一页里大半是绿字，正文层级全丢；
3. **首行缩进与段距**：我们的 2 全角缩进是**自己加的**（`paraDisplayText(indent:)`），
   对本来就带缩进/自带 `text-indent` 的中文书会双重缩进或与之冲突；段间距也不跟 EPUB CSS 走；
4. **标题字号**：`<h1>~<h4>` 只按我们固定档位放大，未读书内 CSS 的 `font-size/line-height/text-align`。

修法（分两步，先止血再精修）：
- **第一步（止血，本批）**：① 注释/脚注链接（`epub:type` 含 `footnote`/`note`、或 `<aside>`、或类名含
  `note|footnote|annotation`）**按正文色 + 小一号**渲染，不再套链接绿；② 正文取消 `justify`，
  中文默认左对齐（保留两端对齐为外观设置项，默认关）；③ 书内自带缩进/`text-indent` 时不再叠加我们的
  2 全角缩进（按段判断，别一刀切）；④ 行内 `<a>` 只在**外链**（href 带 scheme 或跨章）时给链接色，
  站内锚点给正文色 + 下划线可选。
- **第二步（精修，下一批）**：读 EPUB 自带 CSS 的关键声明（`font-size`/`line-height`/`text-indent`/
  `text-align`/`margin`）落到段样式，用户外观设置优先级高于书内样式（保留"跟随原书排版"开关，默认开）。

原型先行：`index-bookshelf.html` 阅读器演示区补一张「中文古籍/注释体」样本屏（含脚注小字、站内锚点、
自带缩进段），与图2 并排对照，逐屏确认后再动实现（红线）。

## R3-3 · P1 AI 精化缺过程可见性

现状：跑精化时只看到「第 b/N 批」和一条进度条，**看不到每一批具体做了什么**，用户无法判断
"是在干活还是卡住了"，也无法核对建议来源。

要改成（面板段内进度卡 + 中心页精化段两处同构）：
- 每批一行明细（可展开列表，默认收起只显最近一批）：`第 i/N 批 · 本批 12 条（前 3 个词名预览）·
  建议 删2 改1 补0 · 用时 1.8s · 约 1.2k tokens`；
- 失败批显式给**归类原因**（超时 / 端点无响应 / 输出不合约定 / 未授权），并标「已跳过 · 不影响后续」；
- 顶部汇总随跑随累：`已出建议 删 x · 改 y · 补 z`，跑完直接进审阅；
- 中止/完成后保留这份明细，供事后在日志页按 `X-Ray 精化` 关键词追（日志一条记录＝一行，别刷多行）。

## R3-4 · 已定口径落档：划线不允许重叠，重叠以后者为准

覆盖《划线段内区间化方案-20261002.md》第四节的规则表（原表写的是"合并成一条"，**作废**）：

| 场景 | 采纳行为 |
|---|---|
| 新区间与旧区间**完全相同** | 撤销该划线（再点一次＝取消） |
| 新区间与旧区间**部分交叠** | **不合并、不共存**：旧行裁掉与新区间重叠的部分，剩余段各自保留（剩余不足 1 字则整行删除）；新区间独立成一条 |
| 新区间**完全覆盖**旧区间 | 旧行整条删除，只留新行 |
| 新区间落在旧区间**内部** | 旧行**裂为两段**（前后各留一段），中间归新行 |
| 同段内互不相交 | 各自独立成条 |

即：**任何时刻同一段文字只属于一条划线**，后画的赢。颜色/分类取新行；被裁剪的旧行若带笔记（thought），
笔记随剩余段保留，段被清空时笔记一并软删（进垃圾箱可撤销，与现有 `softDeleteQuote` 同语义）。
跨段选区按段拆开后逐段套同一规则。
