# 豆瓣抓取防封调研与验证记录（2026-09-26 · V1.45）

> 缘起：产品负责人要求评估 GitHub `calibre-douban` 能否复用，避免阅读模块爬取豆瓣被封号。
> 本文是**过程留档**：源码结论、本机实测数据、采纳/否决清单与遗留项，供接手人不再重复调研。

## 一、calibre-douban（fugary）源码结论

- 仓库形态：Calibre 桌面插件，核心全在 `src/__init__.py` 单文件（约 450 行，New Douban Books v2.3.0），**无库化、无服务模式，代码不可直接复用**（Python + Calibre Source/Option/prefs 框架）。
- 抓取面：搜索走 `www.douban.com/search?cat=1001`（结果页 `a.nbg` 反解 subject 链接）→ 线程池（默认并发 5）抓 `book.douban.com/subject/<id>/` 详情页；解析靠 microdata（`v:itemreviewed` 等），**与我们 `isbn_enrich.dart` 抓的是同一张页面**。
- 可移植手法（按防封价值）：① `douban_login_cookie` 用户自填登录态；② `random_user_agent()` 每次随机 UA；③ `is_prohibited` 检测 `<title>禁止访问</title>` 拦截页；④ calibre 的 `cache_isbn_to_identifier`/`cache_identifier_to_cover_url` 本地缓存；⑤ 检索词带作者（title+authors 失败再退 title）。
- 它没有的：请求节流（只有 0~0.1s 随机延迟）、熔断冷却、suggest 接口。

## 三、拍板（2026-09-26 会话）

1. 采纳四项移植：UA 池 / 熔断（403·429+拦截页文案，20 分钟，跨重启）/ suggest 带作者重试 + 搜索页兜底 / **登录 Cookie 选填**。
2. Cookie 口径：信任用户＋明示风险；只存 SharedPreferences（**不进 settings 表＝书架备份 JSON 与云快照都带不走**）、不进日志；输入即生效、可一键清除。
3. 多来源扩充：海外公开 API 实测不可达，**不做默认副源**；自建代理通道**否决**（用户原话「不建代理通道，用户自己搞定网络」）。多来源＝豆瓣多入口＋本地缓存。
4. 缓存：只存使用中最小字段集（防库膨胀/云备份体积，**不存整页快照**）；二次命中**必须询问**「用缓存 / 仍联网查询」，不许静默采用；设置页提供手动清除（带条数）。
5. UI 走保真流程：先改 `prototype/index-bookshelf.html`（设置两行 + 表单询问行），无头走查后产品负责人确认，再动 Flutter。
