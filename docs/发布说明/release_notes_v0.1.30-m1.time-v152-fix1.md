LifeHarness 预发布 v0.1.30-m1.time-v152-fix1 · V1.52 时间模块真机验收第二轮修复（需求 V1.52.1）

> 取代 v0.1.29-m1.time-v152（功能全量说明见该版正文）。本包只含四条真机反馈的修复 + 两处同批对齐原型的实现纠正。

【本版本内容】（提交见 git log 2026-09-28「真机反馈第二轮」行 · DB 无变更，沿用 v25，覆盖安装即可）
- **合并丢块（P0·数据损失）**：「⇧ 与上一个合并」会把两段一起弄没。根因＝合并块的身份归**较早那段**（与原型 `tpMerge` 同口径：保留早者的分类/备注），而实现无条件删掉传入的邻段，等于先删掉合并块要写回的那一行，随后的 update 命中 0 行。现在写死为「删的是非存活段」，存活段区间取两段并集；「⇩ 与下一个合并」同路径一并复验。
- **撤销当帧生效**：点「撤销」原先要再操作一次才看到恢复——闭包用的是弹层自己的 `ref`，而弹层在提示条出现前已关闭，`ref` 随 State dispose，`invalidate` 静默失效（数据回了、画面没刷）。现在闭包只依赖随 App 存活的根容器与日期，撤销落库后立即重刷四视图与账本。
- **提示条一定自动退场**：带「撤销」按钮的条会一直挂着。根因在框架：`SnackBar.persist` 的默认值就是「有没有 action」（`snack_bar.dart` 内 `persist = persist ?? action != null`），带按钮即永挂。现在显式 `persist: false`，撤销条 5 秒退场（比原型 toast 的 2.8 秒宽裕，保证来得及点撤销，属有意偏差）。
- **弹层内反馈改在弹层内显示**：校验拒绝类提示（补录结束晚于计时中起始、时长不足 2 分钟无法拆分、上下没有 30 分钟内可合并段、标签取所选分类默认标签）原先借道页面提示条——模态弹层下既被压在弹层与遮罩后头看不见、又不退场。现在写在弹层标题下方一行提示（✕ 红 / ✔ 主题色），点分类或再次操作即清。
- **时间滚轮可视 3 行**：`CupertinoPicker` 默认 `squeeze = 1.45`（框架注释「visually mimic iOS」）把可见行数放大成 高度 ÷ 行高 × 1.45，78px 高因此显示成 5 行。现在锁 `squeeze: 1.0`，与原型 `.wheelbox 78px / .witem 26px` 的等距 3 行一致。
- **一级分类显示名称**：6 列窄格（约 48dp）下 `ChoiceChip` 把文字挤到 0 宽（屏幕上只剩色点），且选中时把色点换成 ✓，与原型 `.tag-chip`（色点 + 名称 · 选中=强调色实底白字）不符。现在改自绘 `CatPill`：色点 7×7 + 名称（放不下才省略号），一级格最多 3 行、超出可滚（对齐 `.tp-catgrid` max-height 82px）；子分组同组件，色点沿用父级分类色 60%。

【已具备能力】时间模块四视图统一编辑弹层的破坏性操作闭环：拆分/合并/删除全部走「快照 + 一键撤销 + 当帧刷新」，合并双向与拆分都有真落库回归（不只测纯函数）；提示条在三条路径（页内 / 弹层内 / 弹层关闭后）都有明确退场时机。
