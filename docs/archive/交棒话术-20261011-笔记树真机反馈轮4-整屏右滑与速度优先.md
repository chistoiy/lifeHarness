# 交棒话术 2026-10-11 · 笔记树·真机反馈轮4（整屏右滑开树＋抬手速度优先）

> 来源＝6101 装机反馈两句：「**侧滑不生效**」＋「**Obsidian 的逻辑是整块屏幕只要右滑都可以打开侧边栏，改成这种逻辑**」。
> 追问回执（产品已选）：现象＝**整段没反应**（不是「出来但不跟手」）；抬手口径＝**速度优先＋三成位移兜底**。
> 与 6101 那批的关系＝同一手势面的续批，不是新模块：批2 把「开」做成了跟手，但**起手仍要求贴左边**（贴边判定带 110 系真机反馈轮2 为绕开 Android 系统返回所立），产品真机上从屏幕中段起手＝判定不成立＝整段没反应。本轮把起手面按 Obsidian 放开到整屏。

## 1 · 批次规格（唯一依据）

- **起手面**：`EdgeSwipeToOpen` 的起点判定带 110 **作废**，改为**整屏任意位置**右滑都算开树起手（字段保留，默认值＝整屏；判定带这条口径在真机反馈轮2 立、本轮由产品推翻，沿革记这里，勿在两处并存）。
- **起手阈值**：累计右移 56 → **24**（更早入树，跟手起步）。
- **抬手判定**（产品定「速度优先＋三成位移兜底」）：**本批实装后作废**，成因与收敛见 §1A——
  拖拽中途 push 弹层＝指针被 Navigator 取消，抬手这一帧我们根本收不到，所以「按位置/速度决定开或回弹」
  这条链路无处安放。开＝过阈即开并补间到底。
- **面板面上左滑收起**（对称）：**左甩 >500px/s 即关**；否则拖回剩不到七成＝关，不然弹回全开。
- **竖滚不误触**：保留「横向累计位移必须大于纵向」这条原判据不动（本轮不放宽这一条，否则斜着滚列表就会开树）。
- **代价与知情**：起手面放开后，在笔记卡上「向右拖」也会开树（卡片左滑进回收站方向相反、不受影响）。这条按产品明示意图执行，误触率随真机读数再调，不自行加回来。
- 其余：批量选择态仍不给该手势；树上就地动作/悬浮圆角卡/展开动画/按压反馈＝批1 批2 已交付，本批不动。

## 1A · 施工中的定位结论：**「开树跟手」在路由式弹层上做不到**（产品口径按此收敛，别按原句硬做）

- 面板随指推出＝「拖拽中途把弹层 push 出来，之后继续吃同一路指针」。批2 就是这么写的，实装不成立：
  **`NavigatorState` 在路由插入时会把在场指针逐个取消**（flutter/lib/src/widgets/navigator.dart:5822
  `_activePointers.toList().forEach(WidgetsBinding.instance.cancelPointer)`）。push 那一帧我们的 `Listener`
  收到 `PointerCancel`，之后的 move／up 再也不回来。
- 这正好解释了产品的「**侧滑整段没反应**」两条叠加成因：① 起手面还要求贴边 110（中段起手压根不 armed）；
  ② 过阈 push 后收到 cancel，此刻位移才刚过阈、速度又被旧代码记成 0 → 判定「不够开」→ 当场回弹。
- 本批的收敛形态：**过阈即开，开＝交路由自己补间到全开**（确定性、真机必成）；「面板随指」这条
  不在本轮硬做。**抬手位置/速度判定整体作废**（不是改成别的阈值，是这条链路拿不到抬手）。
- 仍成立的跟手：**弹层已在场时**在面板上左滑收起＝同一路由动画逐帧反向跟手（拖拽期间没有路由插入，
  指针不被取消）——这条是批2 交付面里唯一真实跟手的场合，本批保留并给它补了变异刀。
- **下一批（真·跟手开树）唯一可行形态＝常驻叠层**：抽屉不再走 `Navigator.push`，而是像 Scaffold 的
  `_DrawerController` 那样，面板与遮罩**常驻在树里**（拖拽期间只改可见性/位移，不插入任何东西），
  返回键与「点树外收起」要自己接（`PopScope`＋遮罩命中）。代价＝`_TreeDrawer` 内多处
  `Navigator.pop()` 要换成本地收起、六个入口与弹层层级要重排，属一整批的活。
  要不要做＝等产品一句（本批已把「右滑必开」这条恢复成可用状态）。

## 2 · 同批附带：底栏双指显隐的可行性评估（只评估，不施工）

产品另问：所有页面双指放大＝底部导航栏消失、内容占满底部；双指捏合＝导航栏占回、视图缩放回去，是否可行。评估结论与代价清单见本工单 §3，**UI 变更须先改原型并经确认**（AGENTS 禁令），本轮不动实现也不动原型。

## 3 · 双指显隐底栏评估（结论：可行，代价在三处，需先出原型样张）

- **机理成立**：壳层底栏在 `lib/core/router/app_router.dart` 的 `bottomNavigationBar`，五张 tab 共用一棵壳。做法＝在壳 body 外套一层**只观察不消费**的 `Listener`（与本批开树同一手法，不进手势竞技场），数在场指针：≥2 时取两指间距与起始间距之比，比值 >1.15 一段＝发「隐藏」，<0.87＝发「显示」；显隐落一个全局 provider，底栏用 `AnimatedSize`/`SlideTransition` 收放（〇B 微动档 150~180ms）。双指手势**不落在弹层/详情页**（那些路由本来没有底栏），所以冲突面天然小。
- **代价①（最大）＝布局重排**：底栏一消失，body 高度变大，五张 tab 各自的懒列表/宫格（笔记 masonry 列宽按视口算）会重算，可能闪一下；滚动垫 `ScrollPad` 与「贴底行」余量 `shellBottomSlack` 要跟着改，否则末行位置抖。
- **代价②＝误触发与可发现性**：双指在列表上很常见（手掌蹭到、捏合想缩放图片），底栏莫名消失会造成「东西去哪了」；恢复手势本身看不见，而禁令不允许写教学文案——需要靠一个可见线索（例如隐藏后底部一条细握把/角标），这条属设计决策，要产品先定形态。
- **代价③＝与既有双指语义撞面**：图片大图预览与阅读器插图已用 `InteractiveViewer`（真缩放）。它们在独立路由，不在壳内，按上面「只在壳 body 观察」的口径**不冲突**；但若日后在 tab 页内嵌大图，就要让子页优先、壳让路（留一个 opt-out 开关）。
- **建议路径**：先在壳原型 `prototype/index.html` 出一张「底栏收起态」样张＋捏合/放大的示意态，产品确认形态与那条形可见线索后，再按 §⚙ 面板开实现批（改动跨壳层＋五张 tab 的底部余量，属互斥面较大的批）。

读数（✓＝模拟器上真点出来）：① 屏幕**中部起手**右滑 360px＝开树 ✓（这就是产品那句「整块屏幕只要右滑都能开」）② 慢速短推 120px（44dp，速度远在判定线之下）＝也开 ✓（阈值 24 生效，不靠甩速）③ 竖滑滚列表＝不误开 ✓ ④ 面板面上左滑＝跟手收起 ✓ ⑤ 点树外＝收起 ✓ ⑥ 长按文件夹＝行尾就地出铅笔＋红垃圾桶、不叠白菜单 ✓ ⑦ 点另一行＝选中该目录并清动作态 ✓ ⑧ 悬浮圆角卡形态（留边·圆角·描边阴影·底部四钮）照原型 ✓。

**抓到一条用例永远测不到的真缺陷**：行内两钮命中区被 `constraints: BoxConstraints()`＋zero padding 压到图标尺寸，手指点在图标上实际落到整行＝变成「选中目录」而不是执行动作（删除那一下点不中）。widget 测试按 key 点中心必中，结构上抓不到这类"能点中但点不准"的问题。修＝下限 44×44（与 UX 审计 U6 同口径），用例改成断 `getSize` ≥40 **且故意点角落**（命中区缩回即红）＝提交 `f76cc51`，随复测包 **6103** 出。

**这条修复的模拟器二次确认没做成（如实记）**：换上新包后同一套 adb 注入里，长按那一步不再出行内动作态（试了 900ms 定点与 1300ms 带 2px 微移，截图里动作钮都没出现），于是"点角落删除"无从点起——**不能声称删除钮已在模拟器或真机上验过**。两个待分成因：① adb 注入的长压在这台 AVD 上不稳（同一坐标在旧包上出过动作态＝见 12/18 两张图）；② 更深一层＝**行的 InkWell 可能从子级 IconButton 手里抢走点击**（旧包那次我点的是图标视觉中心，仍然只清态不执行，光"命中区太小"解释不完整）。用例点中心必中＝两种成因都测不到，只能靠真手指。**装机门加一条**：长按文件夹 → 真手指分别点铅笔与垃圾桶各一次，看是否真开输入框／真摘掉夹；若仍"点了只变选中"＝成因②，修法＝动作钮包一层 `GestureDetector(behavior: HitTestBehavior.opaque)` 或让行 `onTap` 在命中动作钮区域时不响应。

流程结论（值得复用）＝本机模拟器可以承担「装机门里不依赖真机硬件的那部分」：手势起手面、误触、命中区、形态回显都能在十几分钟内跑完一轮，比等手机在场快得多；但**触觉反馈、系统边缘返回抢手势、真机手指尺寸**这三类仍只能真机验（模拟器 `input` 事件不产生震动，且导航栏形态与 HyperOS 不同）。
