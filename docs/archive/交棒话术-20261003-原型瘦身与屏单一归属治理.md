## 1 · 两个动机要分开（别混着论证）

- **动机 A＝省 token**：只需读侧工具（屏级切片器＋索引卡，见第 6 步），当天可用、零回归风险，**不必删任何屏**。
- **动机 B＝消灭双份事实源**：同屏八副本导致"改一处要改八处、回灌扯皮、并行互相覆盖"。这才是治理专项的真正理由，代价是完整的一套（漂移比对＋可达性分析＋闸＋规则同步）。

**本专项服务 B**；A 作为副产品在第 6 步收口。若第 6 步之后 token 痛感已消，B 仍可继续（它是工程正确性问题，与省不省 token 无关）。

## 2 · 归属模型：一张屏只有一个家

| 层 | 内容 | 家 | 别处允许什么 |
|---|---|---|---|
| **壳与跨模块** | 底栏/顶栏、今日仪表盘、待办、日程/日历、收集箱、我的/设置、日记与笔记入口层、跨模块联动演示 | `prototype/index.html` | 专版里只允许**占位屏**（见 §3 第 6 条） |
| **模块细节屏** | 记账 16 屏 14 弹层、阅读/书架（阅读器·X-Ray·导入）、健康、呵护、习惯、日子/物品/目标 | 对应模块专版 | `index.html` 只留**一张代表屏**（主屏）＋入口卡与角标，保跨模块流转可演示 |
| **历史与延后** | `v2.html`（非本系列产物，AGENTS 已禁动）、`index-v2.html`（便当格试做）、`index-media.html`（影音游延后裁定）、`index-sync.html` | 原地不动 | 归属表里标 `status: frozen/deferred`，**禁止当现行事实源回灌** |

回灌口径随之降级：模块屏定稿**留在专版**，`index.html` 只更新入口/角标/联动层——不再整屏回灌。

## 3 · 七个缺口与硬约束（动刀前逐条自检，缺一条不许开工）

1. **"删除"实为"合并后删除"**：同 id 已漂移，直接删七份会丢掉某份独有的后加功能。**必须先跑屏级漂移比对**（含弹层），产出"有实质差异的屏清单＋差异摘要"，差异屏要么先人工合并再定家，要么书面记"以 X 份为准、丢了什么"。
2. **统计单位必须含弹层与抽屉**：原型大量 UI 是 `div[id^=sheet]`、抽屉、二级弹窗（记账 14 弹层、阅读外观/X-Ray 弹层），只按 `<section>` 定归属＝删一半、重复还在。闸同时覆盖 `section[id]` 与 `div[id^=sheet]`。
3. **删屏必须连带删逻辑**：以"保留屏集合"为根做**可达性分析**（`onclick=`、`getElementById`、函数调用图），清掉只服务被删屏的函数与演示数据，输出"死函数计数"。只删 markup＝体积不降＋留死代码。
4. **深链与文档锚点不许断**：历史验收清单/工单/方案库都引用 `#p-xxx`、`?brNN=`。归属表兼作**重定向表**（被删屏→新家 URL）；doclint 现有死链守护只查文件，需加一条**锚点存在性**检查。
5. **并行窗口必须冻结**：健康线正在改 `prototype/index-health.html`（工作区 modified），影音游/legado 文档他会话在飞。瘦身单开批次窗口，期间**其他会话不动原型**；开工先核 STATUS 互斥面，否则删掉的屏会被旧副本写回来。
6. **占位屏口径要定死**（待拍板）：要么"明确不可达"（不进导航、深链直接 toast 指新家），要么**不留占位**、由 `navTo` 兜底 toast。含糊会让逐屏验收看到假屏、甚至被实现对成空页。
7. **规则要同步三处，否则下一会话按旧口径办**：AGENTS（本批已改一条）、开发计划书的回灌节、`docs/UI组件规范.md` 开头"事实源"表述。三处都指向本文件。

## 8 · 模块注册表与定位纪律（同批产出，服务"新增 / 微调 / 下架"三类操作）

### 8.1 注册表＝唯一驱动源

与 §4 第 2 步的 `_modules.json` 是**同一份数据**（放 prototype 下，不另建第二份），字段：
模块 id 与中文名 · 需求编号 · 专版原型文件 · 屏与弹层清单（家）· **`aliases`（人话别名，必填非空）** ·
入口三处（底栏 / 设置行 / 深链前缀）· 路由前缀 · DB 表与 schema 版本区间 · AI 能力点 id · 联动 `Lxx` ·
状态（现行 / 延后 / 作废）· 当前活工单。人读版由脚本生成一张 md 表进 INDEX——**JSON 是源，md 是产物，禁止手改 md**。

### 8.2 入口解析：自然语言与截图 → 四元组

开发者输入基本是"记账那个 hero 太挤""cc 页面标题""直接甩一张截图圈一下"，**不做关键词口令**。
内部一律解析成 `{模块, 屏/弹层, 组件, 意图}`，意图四类：新增能力 / 微调 / 下架 / 缺陷修复；
判不出意图就按最保守的一种走并明说"我按微调处理，不对请纠正"。

工具 `pfind.js`（放 tools 下）：`pfind <关键词 | --text "文案" | --shot x.png [--box x,y,w,h] | --lh LH-12>`
→ 返回 `{文件, 起止行, 关联函数, 关联 class, 共用点清单, 该屏的 check 脚本与测试文件}`。
入口支持中文别名、俗称、屏名、LH 组件号、深链、文件行号多种形态，模糊匹配靠 `aliases`。

截图定位三档：① 图里有可读文案 → `--text` 反查屏；② 只有形态 → 对照 LH 词典；③ 都不中 → 现截同屏比对。
**三档都不中就直说定位不到**，发 2–3 张候选截图让产品圈，不许硬猜。
每屏截图基线随 §4 第 2 步一起产出（落仓库外，不入仓），既是回执的渲染底也是圈选比对底。

### 8.3 分级回执（定位卡）：默认不阻塞

判定规则一句话：**改错对象的代价 ≤ 一次 `git revert` → 直接往下走；代价是丢数据、丢功能或返工一整批 → 先问。**

| 档 | 触发条件 | 动作 |
|---|---|---|
| **L0 默认**（约九成） | 目标唯一、锚点明确、只碰一屏 | 回一行**人话**摘要，不截图、不等确认，直接开工 |
| **L1** | 跨屏 / 共用组件 / 连带影响推得出 | 开工前一行摘要，做完一起收口，**不阻塞** |
| **L2 必须等** | 视觉或交互方案本身有分歧（原型门、逐屏验收）；不可逆或高代价（删屏、DB 迁移、下架、推送发版）；定位多义或失败 | 发圈红截图并停手待确认 |

L2 回执格式**两段式**：上半给人看——人话位置＋圈红截图＋"我理解你要改的是…"＋"这两处会一起变"，
**禁止出现 id／行号／类名／函数名**；下半留档——锚点与影响清单，标注"不用看"。
连带影响要翻译成功能语言：不说"同一 class 三处引用"，要说"这两屏会一起变"。

节流三条（防本机制反而变贵）：截图**按需生成**（L0/L1 一律不截）；图**不默认自读**（给链接，只在需自证"框对了"时读一次）；
**一批一卡**（同批多处改动，开头回一张合并定位表，不逐条往返）。

### 8.4 四道闸

1. **双向归属闸**（§4 第 3 步）：专版含他模块屏即红；index.html 含"家不在这"的细节屏即红；未登记的 section/sheet id 即红。
2. **注册表 ↔ 代码一致性闸**：状态"现行"的模块必须有 `lib/features/<id>/` 与路由注册；状态 `dropped` 的模块不得在 `lib/` 残留文件、不得在底栏/设置留入口（抓"下架不彻底"，本项目真出过）。
3. **勿复活闸**：修订史里已撤销的模块/能力名出现在现行 `lib/` 或 `prototype/` 即红（小工具 V1.58、影音游、Legado 三次踩坑）。
4. **别名非空闸**：注册表每个模块/屏/组件的 `aliases` 不得为空；`pfind` 查不到的 id 直接报错（防注册表空心化）。

诚实标注：1–4 可机检；**"是否真回了人话回执"无法机检**，属自觉项，靠 AGENTS 写死＋产品抽查，别假装是硬闸。

### 8.5 三条流程（内部分类，不是要人背的口令）

- **新增模块十二步**：需求清单编号 → 注册表建行（含 aliases）→ 专版原型新建，**从一开始分片** `src/screens + build` 装配单文件 → 路由/底栏/主题登记 → DB 表与迁移 → 架构闸白名单登记 → 建活工单 → 建验收清单 → STATUS 下一站 → 每屏截图基线 → `pfind` 自测可查 → 可选方案库沉淀。**新模块只有一次"零包袱"窗口，注册表与深链必须第一天就位。**
- **微调**：解析四元组 → 分级回执（L0/L1 直接干）→ 原型先行 → 逐屏确认（仅 L2）→ 实现 → 该模块 check 回归。
- **下架六处反向清单**：原型屏与弹层 · 注册表行标 `dropped` · 需求清单条目移入修订史 · 路由与底栏/设置入口 · DB 表处置三问（表怎么办/原型归档/同名入口）· AI 能力点与 prompts.json 及守护白名单登记项。漏任一处都是幽灵入口或死代码，且第 2、3 道闸正好抓得住。

### 8.6 与 §1 的分工

§1~§7 治的是"体积与双份事实源"；§8 治的是"改不动、改错对象、下架改不干净"。
注册表是两者共同的地基：**先有表，再删屏，再上闸**，顺序不能倒。
