# 排障批3：物品模块「二次付费记录无法单独删除」修复

> 状态：**已落地收口（2026-11-06）** · 承载提交见 §4
> 排查范围：用户报障（二次付费只能随物品整条删）＋ 同类「只增不改删」全模块排查

## 1. 结论（一句话）

事件时间轴补 `txn_id` 事件级流水关联（迁移 v51）＋ `extra` 类事件开放长按删除（联动流水同删），购入/回收/报废审计行维持不可改删。

## 2. 同类排查结论

| 断层 | 处置 |
|---|---|
| 二次付费不可删（用户报障） | **本批修**：长按 → LH-S31 确认 → 事件＋联动流水同删 |
| 回收/报废误操作无撤销 | **挂账**：涉生命周期回滚设计（成本池/决算反算），须先过需求门，不擅动 |
| 按次用量不可删 | 非 bug：I07（用量 UI）本身未建，属竞品评估件待办 |

## 3. 落地记录（2026-11-06）

- **模型/迁移**：`ItemEvent.txnId`（可空）＋ v51 `ALTER TABLE tItemEvents ADD COLUMN txn_id INTEGER`（media 批同款纯加列）。
- **仓储**：`addExtraPay` 返回事件 id 并新增 `backfillEventTxn`／`deleteExtraEvent`（只放行 extra 类；购入/回收/报废仍仅追加）。
- **联动（item_mounts）**：`_pushTxn` 返回流水 id → 二次付费写入后回填 `txn_id`；新增 `itemExtraPayDelete`：txn_id 精确删流水，**老数据无 txn_id 时按 同日＋同额＋同备注 兜底匹配**；确认弹窗文案说明「联动流水一并删除」。
- **UI**：`ItemTimeline.onExtraLongPress`（可选回调，仅 extra 行长按生效）→ 详情页接 LH-S31 确认 → 删除后 itemsTick 驱动成本池/日均由引擎实算回落。
- **测试**（守护读数）：
  - items_ui_test：录入用例改口径「联动生流水 · txn_id 精确回填」；「老事件兜底」用例全链路守护（长按→确认→事件与流水同删）。
  - items_repo_test：新增删除/兜底/类型守护（extra 之外不可删）三例。
  - 四波 ALL-GREEN（repo＋ui＋delete＋calc）；变异两刀各红其位、还原全绿（摘 UI 接线 → ui 红其位；摘兜底匹配 → repo/ui 红其位）。

### 测试环境留痕（非产品问题）

「录入用例」曾尝试同用例内续做长按删除：录账 bottom sheet 流程会在 widget 测试环境残留浮层（命中链 `Offstage`+`_RenderTheater`+`AbsorbPointer`）吞掉后续手势，且 `setSurfaceSize` 在本文件路由泵法下不生效（改直赋 `view.physicalSize` 亦未改变命中）。已将该段裁出、由「老事件兜底」用例承担删除链路守护——**不影响真机行为**。
