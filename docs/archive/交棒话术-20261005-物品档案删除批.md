# 物品档案删除批（2026-10-05 立 · 活）

## 1. 触发与背景

复测包 6070 真机走查（批五 T10 三条复验）造了一条测试物品「6070 · ¥199」，验完要清数据时发现：**物品模块没有任何删除口**——详情页只有「二次付费 / 回收·出售 / 报废」三个生命周期动作，`items_repository` 也只有 `recycle` / `scrap`（都只改 `status`＋追加审计事件，不删行）。产品当场拍板：这不是取证姿势问题，是**功能缺口**，物品档案要能删。

机上现状（本批开工前）：该测试物品仍在「使用中」，今日持有成本 ¥211.02/天、数码分类角标 3 件，**留作本批的验收样本**，不预先报废。

## 3. 现状事实（实读钉死，开工前复核锚点）

- `lib/core/database/schema/items.dart`：`item_profiles` 列 = id/name/icon/category/buy_date/price/expected_years/warranty/status/billing/mode/plan_units/unit/stop_pct/photo/source/source_txn_id/created_at/updated_at，**无 `deleted_at`**；子表 `item_events`（成本时间轴）、`item_usages`（按次用量）以 `item_id` 挂父。

### B. 数据层（DB v35 → v36，一次零数据风险迁移）

- `item_profiles` 加 `deleted_at INTEGER`（可空，默认 NULL）；迁移＝`ALTER TABLE ... ADD COLUMN`，**不扫历史、不动子表**（子表不加列）。
- 在册口径＝`deleted_at IS NULL`：物品列表/分类角标/成本统计/今日持有成本/「N 件物品计费中」/决算归档列表/按次用量读数——**全部走同一谓词**，漏一处就是回收站里的档案还在花钱。
- 子记录（`item_events`/`item_usages`）**不加谓词**：只在册父行下被聚合，父行软删即整体不可见；回收站行需要读数时按 `item_id` 直查（属白名单，逐条挂理由）。
- 软删父行不写 `item_events` 审计行（避免「时间轴仅追加」的口径被自删动作污染）；删除动作落**应用日志**（`AppLog.addKey('物品删除：#id 名 · 保留期内可恢复')`，与回收/报废同款）。

### C0. 回收站抽登记式接口（批2a · 2026-10-05 产品「并入吧，但要带完整的六类回归」）

**为什么要抽**：现状是「中心化枚举 + 三处 switch + 两处写死清单」，加一类要改六个地方（读源/恢复/彻底删除/刷新信号/到期清理/文案）。物品是第七类，同构补一遍＝把「加一类」的成本再付一次；先抽成登记项，之后第八类只登记一条。产品判定：并入本批，但**必须带六类全量回归**（行为一字不许变）。

**接口形状**（新文件 `lib/shared/trash/trash_specs.dart`）：

```dart
class TrashKindSpec {
  final TrashKind kind;
  final Future<List<TrashItem>> Function(Database db) rows;      // 读源：本类垃圾箱行
  final Future<void> Function(Ref ref, TrashItem it) restore;    // 恢复回调
  final Future<int> Function(Ref ref, TrashItem it) purge;       // 彻底删除；返回连带清除的在库摘录数
  final void Function(Ref ref) refresh;                          // 动作后把本模块读数刷回原位
  final Future<int> Function(Database db, int keepDays) purgeExpired; // 到期清理出口
  final List<ProviderListenable<Object?>> signals;               // 源模块写信号（回收站随之自失效）
  final String Function(TrashItem it)? restoreToastOf;           // 本类恢复回执（缺省走枚举文案）
}
final List<TrashKindSpec> trashKindSpecs;   // **有序**：到期清理按此序跑（先书行连带清，再摘录/书单）
```

- 六类现有实现**逐字搬进各自的登记项**，不改查询、不改文案、不改日志；`TrashRepository.items()`/`purgeExpiredByTable()`、`TrashService._restoreOne/_purgeOne/_refreshFor/restoreToastFor`、`trashItemsProvider` 的监听清单全部改为**遍历注册表**，三处 switch 摘除。
- 书籍连带口径保留：`purge` 返回连带清除数，服务侧汇总成 `TrashOpResult(purgedBookQuotes, hadBook)`——`hadBook` 由 `items.any(kind==book)` 得出，不再特判分支。
- 到期清理顺序是**语义**不是巧合（刚置孤的孤行不能本轮就被清走），注册表用 List 保序，注释随迁。
- 代价如实记：Dart 枚举穷尽 switch 本来是编译期护栏（加一类漏接线＝编译不过）。改成注册表后编译期不再知道，**必须靠守护补回**（见 E 组第 1 条），否则就是拆了自己脚手架。

### C. 回收站第七类（物品 · 批2b，接在 C0 之后）

- **只登记一条 `TrashKindSpec`**（`TrashKind.item` ＋ 读源/恢复/彻底删除/刷新/到期清理/信号/回执），不再碰任何 switch——这是 C0 抽完就该兑现的判据。
- `TrashKind` 增 `item('物品', Color(...))`；色与原型 `GT_K.item` 的橙点对齐（`bg-orange-400` ≈ `0xFFFB923C`）。
- 恢复＝清 `deleted_at`，`status`/`billing`/`mode` 原样不动（删除前后是同一份档案）。
- 彻底删除＝事务内删 `item_usages`＋`item_events`＋`item_profiles` 三表该档案的行；**`txns` 一行不碰**（拍板②），连带读数（时间轴条数·用量次数）进确认弹层。
- `purgeExpiredByTable` 随注册表自动扩到七表；日志行前缀口径一字不动、尾部追加人话明细（照批C⑦ 定式）。
- 统一屏分段 chips 自动多一枚「物品」；三入口计数同源（物品写信号进登记项的 `signals`，否则回收站进屏不重取的老坑复发）。
- 屏层文案「六类删除内容」→「七类删除内容」（与原型同步；`trash_guard_test` 钉入口位置那条随之改账）。

## 6. 验收判据（逐条可测）

1. 物品详情四钮齐、第四钮玫红描边，任意状态（含已报废）都给；点遮罩/取消不删任何东西（用例断库中行还在）。
2. 确认弹层三行后果读数与当次档案真实一致（时间轴条数、按次用量次数、关联流水条数），且明说流水保留。
3. 删除后：物品列表少一行、分类角标 −1、今日持有成本回落、今天页「N 件物品计费中」−1；回收站「物品」分段计数 +1 且行内副信息正确。
4. 回收站恢复 → 档案回原分类、原状态、计费继续；彻底删除 → 三表该档案行清零、`txns` 计数不变。
5. 到期清理：把保留档设到最短，冷启动后物品行随七表出口被清，日志明细带物品条数。
6. 记账页在物品删除前后金额不变（拍板②的反证）。
7. 机上那条测试样本「6070 · ¥199」用新功能删掉并彻底清除＝本批自证闭环。

## 7. 不做 / 边界

- 不做列表左滑删除（拍板④）；不做「删除时顺带删流水」（拍板②）；不给 `lhConfirm` 加结构化参数。
- 物品**没有**批量删除入口（回收站里可批量彻底删除/恢复，档案侧不做多选）。
- 回收站保留期沿用「记录管理」现档（默认 30 天），本批不新增独立档位。
- 已归档周期/决算报告的可见性只随父行软删，不单独做「回收站里的决算预览」。
