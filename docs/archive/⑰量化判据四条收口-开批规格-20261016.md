## 5 · 判据④：口径必须先拍板（本文给出一个可复核的初步量级）

**现状：这条判据自设立至今从未取过一次实测读数**，既谈不上达标也谈不上未达。

**⚠️ 排期池 §13 里写的量法是错的**：`tools/pslice.js --list` 会把 `--list` 当文件名而崩（`ENOENT: open '--list'`）。**正确用法是 `node tools/pslice.js <file.html> --list`**（文件参数在前）。

**初步量级（2026-10-16 实测·最大屏 `p-readerPage`）**：

- 屏体 12,679 字符＝中文 232 ＋ ASCII 字母数字 7,605
- 粗估 token ≈ `中文 + ASCII/3` ≈ **2,767**
- 同文件次大：`p-localImport` 5.2k／`p-xrwords` 4.7k／`p-readstat` 3.9k／`p-bookshelf` 3.9k

**结论倾向：最大屏很可能已在 4k token 线内**（2,767 < 4,000），但**这个数不能当达标凭据**，因为：

1. **粗估式未经真实分词器验证**——`中文1字=1token` 只是量级近似，真实分词器对 HTML 属性名、class 名、缩进空白的切法与之不同（且 class 名往往被切成多枚子词，真实值可能更高）。
2. **「改一屏」的边界未定义**——只读屏 HTML，还是含该屏专属的 `<script>`/`CSS` 引擎簇？同一屏在壳与专版可能有两份副本，算哪份？
3. **口径一旦变，跨批读数不可比**。

**⇒ 提请产品拍板三件事**，拍完才动测量：

| 待拍 | 选项 |
|---|---|
| 分词口径 | 字符折算（快·可比性差）／真实分词器（准·需定模型）／两者都记 |
| 一屏边界 | 仅屏 HTML／＋专属 script／＋专属 CSS／以上全含 |
| 还测不测 | 若实测全面达标，是否直接把判据④改为「回归监控项」而非「验收判据」 |
