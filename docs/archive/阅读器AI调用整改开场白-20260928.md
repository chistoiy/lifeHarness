## ③ 现状与两种改法（含代码）

现状（绕开统一通道）：

```dart
final ai = ref.read(aiServiceProvider);
final denial = await ai.gate('read.quote_insight');
if (denial != null) { setState(() => _err = denial); return; }
final r = await ai.request('read.quote_insight', {'quote': widget.quote, 'book': widget.book});
```

代价＝这条调用**没有发送前内容审阅、没有进度与取消、不落运行日志留痕、不进 token 台账、将来也不进 V1.53 的 `ai_calls` 使用记录**（用户在 AI 使用记录页看不到「阅读·摘录感想生成」这一条）。

**方案 A（默认推荐 · 零新增代码）**：直接换统一通道，审阅弹层与进度条由 AI 侧负责。

```dart
final res = await aiRunWithReview(context, ref,
    taskId: 'read.quote_insight',
    vars: {'quote': widget.quote, 'book': widget.book});
if (res == null) return;            // 门控拒绝 / 取消 / 失败都在通道内提示过
final text = res.requireText();
```

差异：`_run()` 目前是在面板里内联跑（`initState` 触发），换 A 后每次会先弹「发送给 AI · 摘录感想生成」确认层。若这条能力是**用户点一下才发起**的，A 就是正确形态；若是自动触发，A 会打断阅读，请走 B。

**方案 B（免审阅但同留痕 · 需 AI 侧配合）**：保留内联体验，由 AI 侧提供 `aiRunInline(context, ref, {taskId, vars})`——内部仍走门控 + `request` + 四态留痕，只是不弹审阅与进度。**这条要产品负责人点头并在《需求清单》§六 原则 4 记豁免依据**（当前原则 4 写死「发送前弹层展示完整发送内容可审阅」）。请你们在回复里选 A 还是 B，B 的话把触发时机（自动/点击）写清，我这边补通道再整改。
