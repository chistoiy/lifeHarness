**由此得四条设计红线（写死，后续会话不得擅改）**：

- **R-A · `AGENTS.md` 必须自包含**：ZCode 不展开导入 ⇒ 核心规则（必读指针＋禁令）必须写在入口件**本体**，不能只存在于被 `@import` 的文件里。
- **R-B · 不新建任何「第二规则目录」**（`.qoder/rules/`、`.trae/rules/`、`.devin/rules/`、`.cursor/rules/`、`.clinerules` 一律不建）：这些目录在各自工具里**优先级高于 `AGENTS.md`** ⇒ 另建一份＝制造第二事实源，违背单一归属。
- **R-C · `AGENTS.md` 有体量双顶**：Codex 32 KiB 硬顶 ＋ 每轮 prompt 全量注入 ⇒ 目标 **≤16 KB / ≤90 行**（现行守护五），新增内容一律用「净零行改写」手法。
- **R-D · 别名层只许写指针**：`CLAUDE.md`／`.cursorrules`（必要时 `GEMINI.md`）正文只写「唯一事实源是 `AGENTS.md`」＋极少数入口事实，**不许写规则内容**。

## 3. 目标架构：三层 + 一份入口

| 层 | 件（全部 git 跟踪） | 载入方式 |
|---|---|---|
| **入口层** | `AGENTS.md`（唯一事实源）＋别名 `CLAUDE.md` / `.cursorrules` | 每会话自动注入 |
| **规则层** | `docs/开发计划书.md` · `docs/UI组件规范.md` · `docs/高保真原型设计准则-20260925.md` | 按需（命中才读） |
| **知识层** | `docs/STATUS.md`（状态）· `docs/INDEX.md`（地图）· `docs/handoff/*`（规格）· `docs/排期池.md`（未排期）· `docs/archive/*`（归档）· **新增经验坑家（见 §7 步 A）** | 按需 |
| **工具本地层** | `.workbuddy/memory/YYYY-MM-DD.md`（会话流水）· Trae/Qoder/ZCode 各自的自动记忆目录 | gitignored，**只放本机临时，不承载任何项目规则** |

**判据（写进入口）**：**能跟着仓库走的知识 → 三层；只在这台机器有用的 → 工具本地层。** 一条规则若只住在工具本地层，就等于没有。

## 4. 诉求 1 落地 —— 无感切换工具

### 4.1 通用话术 —— 复用现有会话口令「开工」/「收尾」（不新造）

**本仓的通用话术不是一句新开场白，而是两个已经在用的口令**（定义唯一在 `AGENTS.md`「会话口令」「会话收尾仪式」两节，2026-10-13 确认继续复用）：

| 口令 | 何时说 | 语义（定义处＝`AGENTS.md`） |
|---|---|---|
| **开工** | 会话首句 | 读 `AGENTS.md` → `docs/STATUS.md` → 下一站行指向的活工单，按其规格依批次开工；无需背景复述。限范围写「`开工 <工单名>`」 |
| **收尾** | 会话末句 | 按 `AGENTS.md`『会话收尾仪式』六步执行；「收尾并推送」再追加双端 push |

> 同节另有第三个口令「**记一下 <主题>**」（把结论落进 `STATUS`/`INDEX`/变更日志），**一并复用**；本节只列与「进入／退出开发流程」直接相关的两个。

**为什么复用它而不是新造**：口令语义写在 `AGENTS.md`，而 `AGENTS.md` 是所有工具共读的底座 ⇒ **改口径只动一处，所有工具自动同步**；新造开场白＝又一个会漂移的事实源（违反回灌成句）。且这两节已在 **守护十五「必需锚点小节」清单**内 ⇒ 被删／被折叠即红灯。

**两种接入档（按工具能否读到 `AGENTS.md` 分）**：

- **档 1 · 零对白（读得到 `AGENTS.md` 的工具）**：25+ 工具自动注入、或开一次开关即可 ⇒ 会话直接说「**开工**」、结束说「**收尾**」，**不需要任何解释性对白**。
- **档 2 · 冷启动兜底（该工具首次未自动读到时）**：首句补一句 **「读 `AGENTS.md`，然后说『开工』」**；此后同档 1。可能用到者仅 **Trae（需开开关）／Gemini CLI（需配 `context.fileName`）／Claude Code（只认 `CLAUDE.md`，靠别名件承载口令指针）**。

**接入清单（新工具首次，最多三步）**：
1. 用工具打开本项目根目录；
2. 若需显式开开关（**Trae**：设置 › 规则 › 导入设置 › 打开「将 AGENTS.md 包含在上下文中」；**Gemini CLI**：把 `context.fileName` 指向 `AGENTS.md`），打开一次即可；
3. 首句说「**开工**」（档 2 工具则先补「读 `AGENTS.md`」一句）。

其余 25+ 工具（含 Qoder／ZCode／opencode／Cursor／Codex／Copilot）**零配置**，连第 3 句的兜底都可省。

### 4.2 别名矩阵（动作 = 只补指针，不写规则正文）

| 工具 | 认什么 | 本仓现状 | 动作 |
|---|---|---|---|
| AGENTS.md 系（含 Qoder / ZCode / opencode / Trae / Cursor / Codex / Copilot / Gemini / Jules / Aider / Zed / Warp / goose / Factory / Junie / Amp / RooCode / Kilo / VS Code / Devin） | `AGENTS.md` | 已有 | **零动作** |
| Claude Code | `CLAUDE.md` | 已有（3 条事实＋指针） | 保留，补 1 行口令指针 |
| Cursor（旧版） | `.cursorrules` | 已有（1 行指针） | 保留 |

**结论：别名层只需 `CLAUDE.md` ＋ `.cursorrules` 两枚指针**；`CLAUDE.md` 补一行「会话口令＝`开工`／`收尾`，语义见 `AGENTS.md` 同名节」（纯指针、不写规则正文，符合 R-D）。其余工具零配置即可开工。

### 4.3 防回潮纪律
- 别名件**只许写指针**，不许写规则内容。
- **禁止**新建 `.qoder/rules/`、`.trae/rules/`、`.clinerules`、`.windsurfrules`、`.cursor/rules/` 等第三份事实源；某工具确不认 `AGENTS.md` 时，只用一枚指针别名接入（见 §2 R-B）。

## 6. 诉求 3 落地 —— 瘦身 / 归档 / 按需 / 健壮

### 6.1 分层容器与流向

| 内容状态 | 容器 | 规则 |
|---|---|---|
| 现行状态 | `docs/STATUS.md` | 唯一状态源 |
| 现行规格 | `docs/handoff/*`（活） | 收口 `git mv` → archive |
| 已了结 | `docs/archive/*` | 只进不出 |
| 未排期 / 待定 | `docs/排期池.md` | 一件一行 |
| 无效 / 作废 | 删除，或入 archive 并标「已废」 | 不留双份 |
| 经验坑 | 经验坑家（§7 步 A） | git 跟踪 |
| 会话流水 | `.workbuddy/memory/YYYY-MM-DD.md` | 本机，不承载规则 |

### 6.2 体量棘轮（机制＝照抄色值棘轮：钉基线 · 只减不增 · 放宽须人审）

| 守护 | 对象 | 判据 | 现基线 |
|---|---|---|---|
| 十一 | `AGENTS.md` | 字符数 | 16.2 KB |
| 十二 | `docs/交接文档.md` | 字符数 | 198 KB |
| 十三 | `docs/需求清单.md` | 行数 | 562 行 |

> **口径更正（v1 作废）**：**不对 `.workbuddy/memory/MEMORY.md` 上棘轮**——它 gitignored，闸看不见它、守它也无意义。v1 的「守护十一查 `MEMORY.md`」条作废。

### 6.3 按需加载
三层读法（`AGENTS.md` → `STATUS` → `INDEX` → 活工单）是**跨工具通用**的按需模型，**不依赖任何工具的 import 机制**（ZCode 不支持 import 也能走）。

### 6.4 健壮性三闸（防「改坏 / 折叠丢失」）

| 守护 | 判据 | 拦的病 |
|---|---|---|
| 十四 | git 跟踪文档**不得出现 `.workbuddy/` 路径** | 入仓文档指向不入仓路径（换机即死链） |
| 十五 | `AGENTS.md` **必需锚点小节标题**齐全（清单＝开工先读／工单生命周期／环境事实／验证门禁／禁令／忽略清单／会话口令／会话收尾仪式／下指令口径） | 「规则折叠丢失」——小节被删或被合并后静默失效 |
| 十一 | `AGENTS.md` 字符数只减不增 | 注入件注水、每轮烧 token |

### 6.5 兜底
单一事实源 ⇒ 消除分叉型丢失；git ⇒ 任何改坏可 `git revert`；别名件内容固定且短 ⇒ 可随守护十五同套断言校验。
