## 二、⑥ 落地方案（本会话已勘察，直接照做）

**判「已导入」口径修正（与用户确认）**：批A后建议**与导入向导同口径**＝`EpubImportService.findDup`（归一书名+作者，`repo.findBookFor`），不再引入 md5——同一 App 两条导入路径两套判重会更糟。`books.md5` 列留给 X-Ray/备份校验做扩展点。若用户仍坚持 md5 优先，再做 md5→书名兜底两级。

1. **AndroidManifest.xml**（`android/app/src/main/AndroidManifest.xml`，activity 已 `singleTop`）：MAIN filter 之后追加两个 filter——
   - `VIEW` + `DEFAULT` + `BROWSABLE`，`<data android:scheme="content" android:mimeType="application/epub+zip"/>`；再补一条 `scheme="file"` 的 pathPattern `.*\.epub`（个别旧文件管理器）。
   - `SEND` + `DEFAULT`，mimeType `application/epub+zip`（EXTRA_STREAM 兜底）。
   - ⚠️ release 清单核对：本项目历史上出过「模板把 INTERNET 只放 debug」坑（memory `flutter-release-internet-permission`），发版前 `aapt dump xmltree` 核产物清单里的 intent-filter 也在。
2. **MainActivity.kt**（现为裸 FlutterActivity）：
   - `handle(intent)`：action VIEW 取 `intent.data`；SEND 取 `EXTRA_STREAM`；存 `pendingUri`。`configureFlutterEngine` 里注册 MethodChannel **`lh/intents`**：方法 `takeEpubUri`（取一次即清空）：把 content URI **拷到 `cacheDir/lh_open_epub.tmp`**（`contentResolver.openInputStream` copyTo），返回绝对路径 String 或 null。`onNewIntent` 同样 `handle`。
   - 校验：文件名非 `.epub` 结尾→返回 null（Dart 侧 toast「只支持 EPUB」）。
3. **Dart 接收链**：根 shell（`lib/app.dart` `MaterialApp.router` 处）挂 `AppLifecycleListener`（resumed）+ initState 各调一次 `takeEpubUri` → 有值即走 `handleOpenWithEpub(context, ref, path)`（新文件建议 `lib/features/read/presentation/open_with.dart`）：
   - 构造 `EpubPick(name: 原文件名或路径尾段, size: File(path).lengthSync(), path)`；`EpubDoc` 加载走 **`ref.read(epubDocLoaderProvider)`**（reader 测试同款注入位，单测免真文件）；
   - `findDup` 命中 → 弹「这本书已在书架」确认框（对齐原型 `?br57=dup`：书名/状态/进度 + 取消 / 前往书架定位）；
   - 未命中 → 弹「导入这本书？」（书名/作者/大小 + 取消 / 加入书架·预载）→ `EpubImportService.commit(...)`（draft 用 `EpubMetaDraft.from(doc)`；预载沿用 commit 内既有链路）→ 跳书架并定位。
   - 注意冷启动时序：首帧后再消费（弹层要挂到 shell Navigator，参照 `aiRootNavKey` 同源开合经验，避免 R14「弹层三成因」）。
4. **书架定位高亮**：`shelf_page.dart` 卡片补 `ValueKey('sh-tile-<id>')`；静态 `pendingLocateBookId` 或 provider；渲染后 postFrame 用 element 遍历找到该 key → `Scrollable.ensureVisible` + 一次性描边闪烁（1.6s，对齐原型 `.br-flash-loc` 3px accent 环）。列表按当前筛选找不到时 toast「未在当前视图找到该书」。
5. **测试**：`open_with` 单测注入 MethodChannel mock（`TestDefaultBinaryMessenger.setMockMethodCallHandler`）+ `epubDocLoaderProvider` override + fixture doc（不建真 epub 文件——memory `feedback-widget-test-no-real-async-io`）；两态弹层文案与按钮 key 钉死；`findDup` 命中/未命中各一例；定位失败分支一例。
6. **真机**：出 `--split-per-abi` 包；文件管理器/微信收到 epub→「其他应用打开」→ LifeHarness；两态各验一次；content:// 授权边界（部分管理器给 file:// 已 deprecated，报 Unauthorized 属正常→按 null 走 toast 兜底）。HyperOS 差异见 memory `adb-windows-device-automation`。
