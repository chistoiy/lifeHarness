# APK 包体还能不能再压 · 可行性实测（2026-09-30）

> 触发：V1.58 下架后用户问「包能不能再小一点」。
> 读数来源：`lifeHarness-v158rel` 工作树产出的 **0.2.3+4035 arm64 包**（已发布挂双端的那一枚），
> 用 `unzip -l` 逐条目实测；原始快照存 `.walkthrough/_inv3.txt`（临时取证区，不入库）。

## 一句话结论

**没有无损的口子了。** 包体 74% 是 Dart AOT 产物 + Flutter 引擎（这两块不由我们的构建配置决定），
剩下的 Java/Kotlin dex 只有 10%，而唯一还能拿刀的是**扫码那 15%**——那是功能取舍，不是打包技巧。

## 35.4 MB（arm64）实际构成

| 条目 | 字节 | 占比 | 能不能动 |
| --- | --- | --- | --- |
| `lib/arm64-v8a/libapp.so` | 16,909,232 | 42.6% | ✗ 我们自己 Dart 代码 + 三方包的 AOT 结果，release 模式已是最小档 |
| `lib/arm64-v8a/libflutter.so` | 11,107,920 | 28.0% | ✗ 引擎预编译产物，要减只能自编译裁剪版引擎 |
| `lib/arm64-v8a/libbarhopper_v3.so` | 4,946,720 | 12.5% | △ ML Kit 扫码内核 |
| `classes.dex` | 3,765,552 | 9.5% | △ Java/Kotlin 侧，R8 只管这块（见下） |
| `assets/mlkit_barcode_models/*`（3 个 tflite） | 880,888 | 2.2% | △ 随扫码来 |
| `libdartjni.so` + `NOTICES.Z` + `resources.arsc` + 字体 + 其余 470 条 | ≈2.0 MB | 5.2% | ✗ 胶水、许可清单与资源索引 |

**扫码相关合计 ≈ 5.83 MB / 15%**：全库只有 `lib/features/read/presentation/biblio/isbn_scan_page.dart`
一处引用 `mobile_scanner`（ISBN 扫码 → 豆瓣书目）。要拿掉这 15%，等价于砍掉扫码入口——属产品决策，
本文件不做主张，只把价签挂在这里。

## 已经生效的瘦身（不用再提）

- `--split-per-abi`：三包分治，arm64 机只下 arm64 那一枚（否则 fat 包 ≈ 44 MB）。
- 图标字体 tree-shaking：构建日志实测 `MaterialIcons-Regular.otf` 1,645,184 → 30,788（−98.1%），
  `CupertinoIcons.ttf` 257,628 → 1,084（−99.6%）。
- `minSdk 26` / 无 abi 冗余 / 资源未叠 `res` 变体：清单层没有明显浪费。

## 试过并判定为负收益：R8 / proguard

在 `lifeHarness-r8` 工作树用同源码开 `minifyEnabled true` 实跑过一轮：

1. 先炸：12 条 `Missing class com.google.android.play.core.**`（ML Kit 依赖 Play Core，
   Flutter 侧没有 keep 规则）→ 补 `-dontwarn com.google.android.play.core.**` 才过。
2. 过了以后**包体反而变大**：`classes.dex` 3.59 MB → 约 4.20 MB（当轮读数；那台实验工作树
   已在同日清理轮删除，原始构建日志未入库，所以这个数只作方向性结论，要精确复现按下面步骤重跑）。
3. 原因合理解释：dex 里大半是 Flutter embedding + ML Kit 的反射入口，keep 规则一加，
   能删的没多少，反而多出 R8 的 mapping/桩开销；而占包体 70% 的 `.so` 它碰都碰不到。

**处置：release 构建块维持现状，不开 R8。** 想再验证就在 `android/app/build.gradle.kts` 的
`buildTypes.release` 里加 `isMinifyEnabled = true` + `proguardFiles` 自行试一轮，别在发布工作树上试。

## 真要在意分发体积，可动的只有两条

1. **只发 arm64 单包**（现在 arm64 35.4 MB / v7a 32.6 MB / x86_64 37.9 MB）：现代安卓机基本 arm64，
   v7a 与 x86_64 是给老机和模拟器的。发版说明里写清「普通手机装 arm64 那一枚」即可，不必改构建。
2. **扫码降级为「按需」**：若哪天愿意接受扫码首启时再下载模型（Play Feature Delivery 走 AAB，
   我们是自分发 APK 用不了）——实际不可行；剩下的就是砍功能，回到第 15% 那条产品决策。

除这两条以外，包体由 Dart AOT + 引擎定死，构建配置层已无作为。
