## 0. 快速上手（接手人先读这里）

1. 读本文件「当前状态」与「下一步」。
2. 需求以 `docs/需求清单.md`（V1.18 冻结版）为**唯一依据**，不要臆测范围。评估结论见 `docs/评估报告-2026-09-19.md`；**四项确认门已于 V1.18 全部关闭（见 D12~D14）**。
3. 技术/排期以 `docs/开发计划书.md` 为准。
4. 视觉/交互以 `prototype/index.html` 为基准——**双击浏览器打开即可体验**（单文件、仅引 Tailwind CDN + Inter 字体、纯 UI 占位模拟无后端）。
5. 项目根：`d:\dev_workplace\flutter_te\lifeHarness`（V1.14 起），代码用 git 跟踪，提交遵循 Conventional Commits。
6. ⚠️ **模块预发布铁律（2026-09-19 起，2026-09-20 修订，详见《开发计划书》7.1）**：每完成一个大模块并推送 GitHub 后，必须同时创建 **prerelease**（`gh release create v0.1.0-m0.<版本> <apks> --prerelease`），notes 含功能描述 + 已知占位项，并**上传 release split-per-abi 最小体积 APK**（arm64-v8a/x86_64/armeabi-v7a 三包，勿再传 universal debug 大包）。已有示例：`v0.1.0-m0.calendar`（日程）、`v0.1.0-m0.v127`（保真对齐，首个 split 包实例）。漏发预发布视为模块未交付。
7. ⚠️ **UI 变更确认门（2026-09-19 起，详见《开发计划书》3.1）**：任何需求调整**涉及 UI 变动的，必须先修改高保真原型 `prototype/index.html`，交产品负责人验收并明确确认后**，才可升需求版本并进入 Flutter 开发。原型是 UI 的唯一事实源，禁止跳过确认门直接编码。
8. ⚠️ **交付门序与能力沉淀（2026-09-19 起，详见《开发计划书》5.1/5.2/2.1）**：新功能走十道门 SOP（评审→设计→原型确认→升版→计划→开发→测试→评审→推送→预发布），bug 修复走轻量轨道 B 但 UI/表变更仍过对应门；**架构守护测试**（`test/architecture_test.dart`，R1-R4：依赖方向 + 循环增量子句）红了不许合入；**每完成一个模块须把可复用能力按 `chistoiy/developSummary` 模板沉淀并推送**（含通用行为规范）。

9. ⚠️ **调测必须自带资源护栏（2026-09-20 起，源于一次真实事故）**：任何可能死循环/挂死的调测（跑测试、跑复现）**先设护栏再跑**——看门狗按峰值内存阈值（建议 1.5GB）或墙钟超时（建议 80~120s）**强杀 `flutter_tester.exe`**。禁止无护栏反复试跑疑似死循环的用例（曾把开发机内存吃到近满、系统卡死）。同时**优先用静态/只读取证**（读源码、文件扫描、编译期守护）下结论，能不跑就不跑。

- 隐私：日记/财务/物品为敏感数据，实现时严守《开发计划书》隐私红线。
- ⚠️ **测试挂死 ≈ 先怀疑死循环，别先怀疑死锁**（2026-09-20 事故）。本工程已在 `flutter test` 里踩过一次代价极高的坑：一处 `for` 增量子句漏写 `++` 导致**同帧同步死循环**，表现为"CPU 满核 + 内存涨到 20GB + `--timeout` 杀不掉"。判据与处置：
  - **判据**：`--timeout` 杀不掉 ⇒ 该 isolate 不让出事件循环（同步空转），不是等锁/等 IO，因此**不要**去查死锁、`pumpAndSettle` 收敛性、异步竞态。
  - **定位**：在被怀疑的点插"自终止护栏"（计数超阈值即**写绝对路径文件**再抛错——FakeAsync 下 stdout 缓冲不会 flush，`print` 取证会丢）。护栏落在 `build` 里却不触发时，说明循环在 `initState`/`layout`/非 build 路径，换点再插。日志用绝对路径（`flutter_tester` 的 CWD 未必是工程根）。
  - **修复**：构建定长列表一律 `List.generate(n, (i) => ...)`（无增量子句 = 该 bug 不可表示）；其次才是手写循环并确保 `i++` / `i += n`。
  - **守护**：`test/architecture_test.dart` **R4** 静态扫描 `lib/**`，裸标识符/字面量作增量即测试红（已用注入原 bug 验证会精准报出 `文件:行`）。新增/改动循环后请跑 `flutter test test/architecture_test.dart`（秒级）。
  - **调测护栏（以后跑任何可疑用例都先这么做）**：`--timeout` 靠不住，必须在**进程外**设两道闸——内存阈值 + 墙钟超时，超了直接 `taskkill /F /PID` 掉 `flutter_tester.exe`。本机 `tasklist`/`wmic` 取不到进程数据，量内存用 Dart 自带 `ProcessInfo.currentRss`（写进临时用例，跑完删）最稳。示例（Git Bash）：

    ```bash
    # 闸1：墙钟 90s；闸2（可选）：另开一个看门狗，峰值超 1.5GB 就 taskkill
    HTTP_PROXY= HTTPS_PROXY= http_proxy= https_proxy= NO_PROXY='*' \
      timeout -k 5 90 flutter test test/xxx_test.dart --concurrency=1 --no-pub
    # 事后确认无残留（否则会一直占内存/CPU）
    /c/Windows/System32/tasklist.exe | grep -i flutter_tester || echo "无残留"
    ```
  - **能静态就别跑**：读源码、文件扫描、编译期守护（R4）就能定性的结论，不要靠反复跑用例去逼近——每次试跑在这种 bug 上都是 20GB 级的代价。
