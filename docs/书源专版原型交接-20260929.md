## 3. 与既有能力的衔接（都在本副本内实现）

- **书架**：在线书与本地 EPUB 同一条渲染路径（`local=1` + `online=1`），封面右下角徽标**同位替换**——EPUB 显示「本地」，书源书显示「在线」；点封面同样直达阅读器并自动开始计时。
- **添加图书（先搜后加 `p-biblioSearch`）**：FAB 菜单新增「从书源搜索」（带上已输入的词），页内新增「在线书源」卡（发现页 / 管理两个直达）。豆瓣书目路径完全不变。
- **阅读器 `p-readerPage`**：顶栏副标题改显「在线 · 源名 · 已缓存 x/y 章」；八宫格新增「换源」磁贴；CFI 前缀按来源泛化（本地 `epub/2/…`，在线 `src/2/…`）；翻到未缓存章自动现取并计数，源失效则弹三选一。划线、书摘、计时、统计、目录抽屉全部复用，未新增第二套数据。
- **阅读设置 `p-readset`**：新增「在线书源」分组 13 行——启用总开关 / 书源管理 / 书源搜索 / 发现页 / 抓取任务 / 抓取间隔（200·400·600·1000ms）/ 单章重试（1·2·3·5 次）/ 断点续传 / 默认净化 / 仅 Wi-Fi / 源失效提示换源 / 净化规则 / 清除全部书源缓存。

## 4. 演示数据即预研实测（不是编的）

- 8 个源覆盖三档支持度：`纯规则可用`（笔趣阁，真站四段全通）、`部分规则`（就爱文学，缺 textNodes/tr!0/or 谓词 → 正文段落偏少）、`纯规则已熔断`（天天看小说，连续 3 次超时）、`已失效`（手机小说 404 / 得奇站点关闭 / 快书网域名停放）、`需 JS 引擎`（酷我，@js + JSON API，876 章）、`需渲染`（轻小说平台，ticket + WebCrypto）。
- 搜索「剑来」在笔趣阁返回 **19 条**＝预研真站实际条数；目录 **108 章**且演示了「最新在前 → 自动转正」；正文破 base64 `document.writeln` 混淆。
- 订阅统计「22 源 · 可用 5」＝XIU2 列表实测覆盖率。

## 6. 待产品逐屏确认（拍板后进开发）

1. **发现页是否做一级入口**：目前入口=阅读设置 + 添加图书页书源卡。若要做进书架顶栏或底栏，属共享面改动，需走变更单。
2. **在线书徽标是否替换「本地」**：现方案同位替换（避免两枚角标叠加）。若希望「本地 + 在线」双标并存，改一行即可。
3. **抓取任务是否独立成屏**：现为独立屏 `p-bsTask`（含调度卡 + 四态任务）。也可降级为设置页内嵌列表。
4. **净化规则作用域**：现为全局（对用户所有源生效，与源自带规则叠加）。是否要「按源单独一套」？
5. **源失效的处理节奏**：现为连续 3 次超时即本轮熔断 + 阅读中失败弹三选一。阈值与是否要做「源健康日报」待定。
6. **仅 Wi-Fi 的默认值**：现默认关（移动网络也可整本下载）。若默认开，下载入口需加一次提示。
7. **期 4 后置的界面表达**：@js / 需渲染的源在 UI 上置灰并注明原因（不隐藏）。是否改为「在管理页单列一节·待引擎」？
