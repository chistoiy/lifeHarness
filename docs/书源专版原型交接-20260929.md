## 3. 与既有能力的衔接（都在本副本内实现）

- **书架**：在线书与本地 EPUB 同一条渲染路径（`local=1` + `online=1`），封面右下角徽标**同位替换**——EPUB 显示「本地」，书源书显示「在线」；点封面同样直达阅读器并自动开始计时。
- **添加图书（先搜后加 `p-biblioSearch`）**：FAB 菜单新增「从书源搜索」（带上已输入的词），页内新增「在线书源」卡（发现页 / 管理两个直达）。豆瓣书目路径完全不变。
- **阅读器 `p-readerPage`**：顶栏**常驻「源」胶囊钮**（源名 + 健康点，异常源转黄/红），点一下就在阅读中开换源优先级表；目录抽屉标签行尾同信息角标；八宫格另有「换源」磁贴；底栏加「续抓」→ 批量预抓弹层；顶栏副标题显「在线 · 源名 · 已缓存 x/y 章」；CFI 前缀按来源泛化（本地 `epub/2/…`，在线 `src/2/…`）；**翻到未缓存章＝只取这一章**（看一章请求一章），取不到按优先级自动换源后续读、仍失败才弹四选一；「预取下一章」开关可在取回当前章后后台再取一章。划线、书摘、计时、统计、目录抽屉全部复用，未新增第二套数据。
- **阅读设置 `p-readset`**：新增「在线书源」分组 17 行——启用总开关 / 书源管理 / 书源搜索 / 发现页 / 抓取任务 / **书源校验** / 抓取间隔（200·400·600·1000ms）/ 单章重试（1·2·3·5 次）/ **自动换源** / **续抓默认档（20·50·100·200）** / **预取下一章** / 断点续传 / 默认净化 / 仅 Wi-Fi / 源失效提示换源 / 净化规则 / 清除全部书源缓存。

## 4. 演示数据即预研实测（不是编的）

- 8 个源覆盖三档支持度：`纯规则可用`（笔趣阁，真站四段全通）、`部分规则`（就爱文学，缺 textNodes/tr!0/or 谓词 → 正文段落偏少）、`纯规则已熔断`（天天看小说，连续 3 次超时）、`已失效`（手机小说 404 / 得奇站点关闭 / 快书网域名停放）、`需 JS 引擎`（酷我，@js + JSON API，876 章）、`需渲染`（轻小说平台，ticket + WebCrypto）。
- 搜索「剑来」在笔趣阁返回 **19 条**＝预研真站实际条数；目录 **108 章**且演示了「最新在前 → 自动转正」；正文破 base64 `document.writeln` 混淆。
- 订阅统计「22 源 · 可用 5」＝XIU2 列表实测覆盖率。

## 6. 待产品逐屏确认（拍板后进开发）

1. **发现页是否做一级入口**：目前入口=阅读设置 + 添加图书页书源卡。若要做进书架顶栏或底栏，属共享面改动，需走变更单。
2. **在线书徽标是否替换「本地」**：现方案同位替换（避免两枚角标叠加）。若希望「本地 + 在线」双标并存，改一行即可。
3. **抓取任务是否独立成屏**：现为独立屏 `p-bsTask`（含调度卡 + 四态任务）。也可降级为设置页内嵌列表。
4. **净化规则作用域**：现为全局（对用户所有源生效，与源自带规则叠加）。是否要「按源单独一套」？
5. **失效处理节奏**：现为「连续 3 次超时即本轮熔断 → 阅读中逐章现取失败先按优先级自动换源 → 全源皆失败才弹四选一」。待拍板：自动换源默认开？熔断恢复窗口（现=本轮跳过，是否要 30 分钟后自动试一次）？是否要「源健康日报」。
6. **仅 Wi-Fi 的默认值**：现默认关（移动网络也可整本下载）。若默认开，下载入口需加一次提示。
7. **期 4 后置的界面表达**：@js / 需渲染的源在 UI 上置灰并注明原因（不隐藏）。是否改为「在管理页单列一节·待引擎」？
8. **换源后的章节对齐口径**：现按「第 N 章」编号对齐（各源章数不同时标注「目录只到 x 章」）。是否要按章名模糊匹配？（预研实测：同一本书不同源章数与分章粒度会差 5%~20%）
9. **续抓默认档**：现 50 章（可选 20/50/100/200/全部），且「预取下一章」默认开。是否接受默认多取一章的流量代价（约 12KB/章）？
10. **校验的触发时机**：现为「导入后自动跑本次导入范围」+ 管理页手动入口 + 失败弹层跳转。是否再加「每天首次启动后台抽检 N 源」？（会引入定时网络请求，与「零埋点」口径不冲突但需明确）
11. **批量导入的规模上限**：现演示 46 源一次导入。真实现 200+ 源集合很常见，是否限制单次解析条数并分页预览？
