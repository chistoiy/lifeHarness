## 一、Flutter / Dart 编码约定

- 定长列表用 `List.generate`；禁三段式推导（漏 `++`＝静默 OOM），守护 arch_test R4。
- `Align(heightFactor:0)` 不改子件尺寸 ⇒ 判「收干净没」钉外层槽位；底栏槽高＝内容 70＋描边 1px（漏=假绿）。
- FakeAsync 里 `print` 会丢 → `File(绝对路径).writeAsStringSync(…,append)`。
- 轮族闭环点＝`didUpdateWidget` 里 `jumpTo`；改滚轮跑 `wheel_time_test.dart`。
- **加设置项必四处同步 `SettingsRepository`**（它逐字段读写 prefs，不走 toMap 整包）：常量 `_kX` ＋ `load()` 的「有用户配置」判据 ＋ `load()` 的 `fromMap` map ＋ `save()`。漏一处＝不持久化（2026-10-12 `myLayout` 差点漏）。
- **改版式/加顶部大卡会让页面变高** ⇒ 既有整页测试的「同屏假设」失效（`ListView` 懒构建，且目标元素可能在视口**上方**、越拖越远）；改后必跑 `widget_test` ＋受影响导航微测。
- 私有 widget 源码级判据别钉类名前缀串（多行调用会失配）⇒ 钉 `title: 'x'` 层；`EBUSY` 先 grep 查是否已半改。
- **页面新增读 `sharedPreferencesProvider`（或任一默认 `throw UnimplementedError` 的 provider）⇒ 该页全部既有 pump 测试立刻炸**：动手前必 `grep -rl "<PageClass>" test/` 列全 pump 方并批量补 override（2026-10-13 思维导图批3 一次撞 4 文件 13 处）。
- **「刀跑红」≠「红在预期位」**：红在 `loading ... [E]`/编译错＝**假红**，必看 `[E]` 那行是断言还是加载失败。**switch 表达式的变异刀禁删通配臂**（非穷尽＝整文件编译不过）；改「返回值」而非「删分支」。
- **`const Map` 键表跨域同名必撞编译错**（`default`/`accent` 在两个域各有）⇒ 键用 `kind:level` 双层＋取标签走 `label(kind, level)` 函数。
- **文件末行无换行时 `cat >> f <<EOF` 首行会粘到上一行尾巴**（doclint 报「超长行」但行号指向旧行，易误判）——追加前查末字节或追加后立刻目检 `tail`。
- **Dart raw string 不做插值**：`r'...${expr}...'` 里 `${}` 是**字面量**（2026-10-12 L3 回勾正则实锤红）；动态正则/SQL 片段必须**拼接构造**。同族：`trash_guard` 按语句**文本**判定谓词——谓词藏进 `$cond` 变量＝红灯，须内联进语句文本。
- **DB 迁移批＝version 常量与 migrations 最高键同批同步**（2026-10-12 6109 实锤：迁移语句落了 version 漏改 ⇒ 真机 onUpgrade 不触发 ⇒ 日记读写全断/编辑页卡死）。守护 S6（version=max键+1）＋S7（v43→v44 真升级）钉在 journal_test；**新迁移批必跑这两例**。假绿根源＝测试库走 onCreate 全量 DDL，升级路径平时零覆盖。
- **新增文档件先量 `docs/INDEX.md` 行数**（doclint 守护五硬闸 ≤130 行，2026-10-12 实测已顶满）：不能加行时把新档引用**折进既有相关行的行尾**（守护二只查 basename 子串），行数不变即绿。
- **规划/工单批引用「下一站才建的路径」写裸文件名**（如 `index-mindmap.html` 不带 `prototype/` 前缀）——doclint 零死链闸只认 `docs/|prototype/|tools/` 前缀的相对路径且要求文件真实存在（2026-10-12 首跑 5 红实锤）。
- **`flutter analyze <单文件>` 会漏判 `part of` 扩展文件**（2026-10-14 阅读批3 实锤：改 `reader_xray_panel.dart` 的私有常量族后单文件 analyze 报 "No issues found"，`flutter test` 编译却红在 `reader_xray_panel_learn.dart`）——改跨 part 共享的私有符号后**必跑 `flutter analyze lib` 全量判**（约 20~30s），别信单文件读数。
- **`static const` 色常量改吃 `context.tokens` 的函数后，同库所有 `const TextStyle(color: x)` 连同外层 `const Text/Padding/Icon` 全变非法**：批量去 const 可脚本按「行内含目标符号即去本行 const」，但 const 写在外层 widget 行的跨 case 仍要手工补（2026-10-14 阅读批3 32 处收敛实踩，两轮返工）。

## 二、调测纪律（铁律 9）

- 可疑用例设进程外护栏（墙钟＋内存即杀）；能静态判定就别试跑。
- **riverpod 冷读悬死（存量）**：裸容器冷读「watch 另一 async provider 的 .future」悬死至超时（V1.66 原体即悬·生产靠 widget watch 驱动）⇒ 容器用例先热读上游再读树；红时先跑「最小复刻探针＋分段 timeout」二分，别信第一嫌疑。
- **变异自证**：注入钉「被改的那一行本身」（改前唯一串消失为证），禁改后泛串；锚点命中=1；跑完回写＋md5 断言；工装放 `tmp/`。
- **变异刀要改「被守护的那份持久状态」**（2026-10-13 实锤）：改同语义的**另一处副本**＝假绿——只清内存旁路 `_liveDx/_liveDy` 而用例断言 DB 里的偏移，照绿。写刀前先问「被守护的值最终落在哪」。
- **变异判定器必须读每波日志**：只看 `ftest_waves` 的 stdout 尾行会把「红在预期位」判成 `RED-WRONG-PLACE`——**断言位置（哪条用例红）在 `tmp/gate_<tag>/w1-<file>.log` 的 `[E]` 行里**。
- **同族图标撞车＝定位歧义**：`find.byIcon(X)` 命中 2 个 ⇒ 整文件用例全红且报错与被测功能无关（布局钮 `account_tree_outlined` 撞工具条既有图标，7 例全红）。**同类图标必须给稳定 `ValueKey`**，别靠图标定位。
- **工装坑**：① 脚本起 flutter 别写 `bash`（命中 WSL＝秒退假结果），用 Git Bash 绝对路径＋finally 回写；python subprocess 同坑（shell=True=cmd.exe）。② 判 ListView 懒构建别数子件→钉 `childrenDelegate`。③ AppToast 撤销窗口 static→用例末 `clearToasts(tester,ms:120)`。④ LF/CRLF 混用→锚点按实际换行构造。⑤ InkWell 长按先走 Feedback.forLongPress（mock 多一条 null）⇒断言用 `contains`。⑥ 刀跑绿≠有效：用例没走被改路径＝假绿，核「红/绿位」。
- **工时账**：`mark` 只能段首打、不能回填。谁作的 md5/mtime 谁作证。
- **跑测试前必须清代理（2026-10-14 6133 轮实测 10 分钟）**：沙箱代理会让 `flutter_tester` 起不来——现象是**每波都在 loading 阶段红**：`Failed to load "...": Unable to connect to flutter_tester process: WebSocketException: Invalid WebSocket upgrade request`（HTTP 400）。这是**环境假红，不是回归**。`tools/ftest_waves.sh` 自身**不清代理**，必须在外层清：`HTTP_PROXY= HTTPS_PROXY= http_proxy= https_proxy= NO_PROXY=* bash tools/ftest_waves.sh …`；同理 `flutter analyze`/`flutter test` 单跑也一样。判据：**红在 loading ＝环境；红在断言/`[E]` 行 ＝真回归**（与"变异判定器必须读每波日志"同一条纪律）。
- **别让 gradle 编译与 flutter 测试并行（2026-10-14 6133 轮实测）**：`tools/kotlin_check.sh` 的 `:app:compileFlutterBuildRelease` 与 `flutter test` 会互抢 flutter 工具链，表现为 kotlin_check **卡在 compileFlutterBuildRelease 六分钟零增长**（dart 进程 CPU≈0）＋测试波次假红。**两者一律串行**；卡住时清场三连＝`Stop-Process` 清 dart/dartaotruntime ＋ 停后台任务 ＋ `gradlew.bat --stop`。
- **`flutter test` 必须一文件一波，禁合波/混场（2026-10-11 V1.64 批1 首爆 + 当日轻件 3 合波二次实锤）**：多文件同场跑时 **pump 套件跨文件于同一 isolate 互踩**（与「全 app widget 测试必须拆独立文件」同族）——首爆 8 件混场 `flutter test` **挂死 40 分钟零输出**；父 bash 被杀后 `dart`/`flutter_tester` **残骸继续占场**，下一轮在无形态里空转（读数全是假红）。所以批内增量**一律** `tools/ftest_waves.sh <批次名> <文件…>` **一文件一波**＋每波 `--timeout 90s`，且**开跑前先探场拦残骸进程**。
- **「照抄 STATUS 表头」类旧口径会过期**：文档里写死的定量描述（行数/字符数/体量）一旦被瘦身推翻就成了假事实，改规则时顺带扫一遍（2026-10-14 实测 AGENTS.md 里「STATUS 表头一行近 3 万字符」早已失效——2026-10-08 瘦身后单行 ≤1200）。
- **原生悬浮窗/浮层的「位置更新去重守卫」不能拿「即将使用的目标值」比**（2026-10-15 6136 实锤，整轮返工）：典型错法是「先构造 params（构造时已写入目标 x/y）→ 再判 `if (params.x == targetX) return`」，守卫**恒为真**，于是每个 `ACTION_MOVE` 都在第一行返回、窗口从未被移动过——用户报「拖动不跟手 / 拖不动」，而代码读起来完全正常，极易误判成手感或性能问题（往 slop 阈值、加插值方向跑偏）。**正确做法＝另存「上一次真正应用的位置」字段**（`appliedX/appliedY`），在 `addView` 成功后播种。同族提醒：**触摸阈值判定与「吃掉阈值」必须同一帧完成**，否则起步有一段粘滞（手指先滑一段才开始追），app 内 `GestureDetector` 天生无此问题，原生需手工补 `slopBase = down - sign(d) * slop`。

- **hpick 横滑**：首尾 `.hsp` 弹性占位是「最近中心」前提；设置类数值用左右滑。
- **动手前查屏归属**（判据 `prototype/_modules.json` 的 `screens[].home`）；壳留有迁出后的**孤儿同名 DOM/函数** ⇒ 先 `grep 'id="'` 验（笔记列表在 `prototype/index-bookshelf.html`，编辑页在 `index.html`）。
- **多线共享面**：并行互相混入；提交按线拆＝`git apply --cached --recount`（纯线 hunk 整摘；混线「-X/+Y 改写组」任一 + 行属对方 ⇒ 丢 + 行、-X 转上下文）；暂存版 `git show :path` 目检后 commit。新屏登记 `proto_registry.js --write --add-missing`（`prototype/_modules.json` 须对齐其序列化口径过逐字节自证）——**本机 `core.autocrlf=true` ⇒ 工作区 `_modules.json` 是 CRLF、git 里是 LF，脚本按 LF 做 pristine 自证必 `REFUSE …首个差异第 1 字符`；解法＝先 node 把文件 `\r\n`→`\n` 归一（autocrlf 下不产生行尾 diff，实测仅 +新增条数）再跑脚本**（2026-10-12 思维导图 4 弹层入册实锤）。

- **专版必须自带 hash 深链**（`mmBoot()` 读 `location.hash` 决定落地屏 ＋ `hashchange` 监听）：壳靠 `LH_REDIRECTS` 落到 `#p-xxx`，没它深链进不去屏；顺带让校验工装能走 hash 驱动，**避开注入脚本与原型 `DOMContentLoaded` 抢时序**（原型监听注册在前⇒注入裸跑必被覆盖，诊断里 page 恒初始屏而内容已渲染＝假象）。

- **注册表 `dev` 字段**：原型先行阶段必写 `notStarted` —— 闸2 只对 `status=current && dev=delivered` 查 `lib/features/<id>` 是否存在，写 delivered 会红。
- **自定义拖拽守卫别用 `hasPointerCapture`**：捕获失败时它恒 false ⇒ `pointermove` 永远进不来（down/up 都到、move 一次不进）。改用自有 `dragging` 标志，`setPointerCapture` 包 try/catch。拖动中只改该元素位置＋重画连线，**不重建 DOM**（否则闪）。静态截图证明不了「拖得动」⇒ 工装要**真发 pointer 事件**验「状态已写＋坐标已变＋连线跟随」。
- **改 STATUS 长行前先算净增减**：单行 ≤1200 硬闸（`python tools/status_set.py --check`），一次只改一处必然来回超；把多处改动合到一次替换里再验。
- 新建专版的自检工装可抄 `tools/mm_check.js`（F1 结构闸 ＋ 变异自证）＋ `tools/mm_shot.js`（F2 注入 ＋ F3 真 390 矩阵 ＋ **逐张对位断言**：视口/屏态/弹层态/色档/节点数，防假绿）。
- **内嵌 HTML 字符串里的收尾标签必须转义**（`'<\/script><\/body><\/html>'`）：注入式工装用 `SRC.replace('</body>', '<script>…</script>\n</body>')`，若 JS 字面量里有裸 `</body>` ⇒ **第一次命中它**、探针被塞进字符串 ⇒ 整页 script 瘫（2026-10-12 `buildExportHtml` 实锤 `mmSelect is not defined`）。自查＝`grep -c '</body>'` 必须＝1。同族坑＝模板字面量里写 `'\n'`（反引号）会变实换行断字符串，须 `\\n`。
- **树/放射布局的纵向间距必须按节点实测高逐节点累加**（`nodeH(id)` 用 `H_OV` 实测覆写），禁用常量行高 `row*(NODE_H+GAP)`——多行节点渲染高 ~116px 而兄弟仍按 54px 排 ⇒ 叠压（2026-10-12 截图实锤）。
- **`proto_registry` 只登记 `screens[].id` 的块 size/hash**：改块内部内容**不漂**；**新增弹层/屏必须 `--write --add-missing` 入册**（否则 protogate 闸1 与 registry 反向扫描双红）。
- **多形态布局的通用口径（2026-10-13 思维导图批4 实锤）**：① `ratio/比例` 维度**不参与挑算法**——「横向预览」不是第四套算法，而是「同一结构＋另一种列排」（与 `both` 共用分支，照原型 `layout()`）；② **「默认态零视觉变化」的实现手段是默认形态的引擎一字未改**，靠状态层选对实例达成，不是靠参数凑；③ **连线/装饰的画法必须由布局引擎声明**（枚举随结果带出），渲染层不许猜——横向/放射套纵向阶梯公式＝斜穿节点；④ **多引擎共用的可见性口径（折叠）必须抽一份索引**，各写一份遍历早晚漏判一处；⑤ 想让变异刀能直接断言画法分派，把画法抽成**顶层纯函数返回点列**，别只留在 `paint()` 里。
- **嵌套 JSON 序列化（2026-10-13 批5 `.xmind` 实锤）**：自写编码器时**子节点必须返回「已序列化片段」而非 String**——返回 String 会被外层再包一层引号，产出「字符串里装 JSON」的坏结构，消费端（XMind）打不开。**断言必须验子节点是对象，只查根节点发现不了**；发现这类问题最省事的手段＝**先把产物打印出来看**（`print` 出 content.json 一眼看出）。

- **「点勾圈直接闭环」必然要写库，别指望绕开 C5（2026-10-15 批3 实做）**：待办 2×2 的勾圈要真闭环，就绕不开一次 `UPDATE todos`。C5「禁 widget 直读 sqlite」的**意图是读数单一真源**，不是「不许写」。正确姿势＝把这条登记成**窄例外**并写进冻结档：C5 补一句「只写不读，单条幂等 `UPDATE … WHERE id=? AND done=0`」，同时上守护——**剥注释后**判源码里不得出现 `SELECT`/`QUERY`/`RAWQUERY`（不剥注释的话，本文件自己写的说明文字会把自己判红，与「扫标签不扫全文」同族坑）。配套三件套：① `exported="false"`（否则任意 app 能改你的库）；② `goAsync()`（写库是同步 IO，不 hold 住会被判 ANR）；③ 失败入队 `pending_toggles` ＋ App 启动补写（桌面没有 Toast，失败必须留痕可追查，否则用户只看到「点了没反应」）。
- **分隔符别用 `|`／`\n`（2026-10-15 实做）**：往 SharedPreferences 里塞结构化行数据（待办清单这种），分隔符用**控制字符** `U+001E`（条目）/`U+001F`（字段）。`|` 是待办标题里的合法字符，`\n` 会被 SharedPreferences 与布局两头反复转义 ⇒ 行数据整列错位，而这种 bug 只在真机上表现为「标题乱码」，极难定位。另外行数上限这类常量**禁两处各写一个数字**：Dart 的 `kWidgetTodoRows` 与 Kotlin 的 `TODO_ROWS` 必须相等并写进守护断言——布局只预留三行，多了会被静默裁掉。
- **RemoteViews 只认白名单控件，裸 `<View>` 会让整张卡「载入窗口小部件时出现问题」（2026-10-15 8150 装机实锤）**：待办 2×2 用 `<View android:layout_weight="1"/>` 当吸余高的 spacer，桌面直接显示系统报错卡。Launcher 日志是 `InflateException: Class not allowed to be inflated android.view.View` ——**RemoteViews 只允许固定白名单里的类**（LinearLayout / FrameLayout / RelativeLayout / GridLayout / TextView / ImageView / Button / ImageButton / ProgressBar / Chronometer / AnalogClock / ViewFlipper / ListView / GridView / StackView / AdapterViewFlipper），`android.view.View`、`Space`、`ViewStub`、`<include>` 都不在其中。安全的 spacer＝**空 `LinearLayout`（match_parent 宽 + 0dp 高 + weight=1）**。守护＝扫小组件布局的标签名做白名单校验，**必须先剥 XML 注释**（本仓习惯在注释里写「为什么不能用 `<View>`」，不剥注释就自指红，与「扫标签不扫全文」同族坑）。同族注意：`res/layout/lh_widget_config.xml` 是配置 Activity 自己的布局，不归 RemoteViews 管，那里的 `<View>` 分隔线没问题——**白名单只约束 provider 用 RemoteViews 下发的布局**。
- **小组件预览图：MIUI **只认 `previewImage`**，`previewLayout` 被完全忽略（2026-10-15 8151/8152 两轮装机实锤）**：第一轮以为「`previewImage=ic_launcher` 压过了 `previewLayout`」，**删掉 previewImage 只留 previewLayout** —— 结果更糟：MIUI 直接回落应用图标，四枚在「添加小部件」里**长得一模一样**（实测截图确认）。正解＝**两个都给**：`previewLayout`（Android 12+ 标准口径，给原生桌面）＋ `previewImage`（指向**真预览图**，给 MIUI 这类只看图的桌面）。预览图不能指望系统帮你渲染，得**自己生成**：本仓 `tools/gen_widget_previews.py` 按 `lh_widget_*.xml` 的真实结构/字号/色值用 PIL 画出 PNG，浅档放 `drawable-nodpi/`、深档放 `drawable-night-nodpi/`（C6 跟随系统深浅色，同键名不同值）。两个工程细节：① `S`（px per dp）取 4 即可——缩略图约 250px，取 6 会让八张图涨到 800KB+，取 4 只有 550KB；② 生成脚本必须进仓库（`tools/`），否则那批 PNG 就成了没有来源的二进制，下次没人知道怎么改。**判断口径**：凡「预览」相关字段并存，先确认宿主到底听谁的——Android 官方说 previewLayout 优先（API 31+），厂商桌面（MIUI）实测相反，**只能靠装机看**；而「删掉一个字段」这种修法一定要真机复验，别停在推理上。
- **`android:configure` 把「添加时弹配置页」和「长按菜单的『编辑』项」绑死了（2026-10-15 产品改口实做）**：小组件元数据写了 `android:configure`，系统会在**两个**时机拉起那个 Activity —— ① 用户从系统「添加小部件」拖到桌面时；② 长按已放置的小组件 → 菜单里的「编辑」。产品嫌 ① 多一步打扰，但**没有只留 ② 的办法**：删掉 `configure` 两个一起没，留着 ① 也一起在。判据＝**先问「配置能力在 App 内是否已有等价入口」**：本仓四枚总开关 + 隐藏金额在设置页里全都有，所以删 `configure` 不丢能力，代价只是长按菜单少一项，可以接受。反过来，若某个配置项只有那个 Activity 能给，就**不能删**，得改成让 Activity 秒退（但「是否新增流程」在系统侧无可靠信号，别赌）。
- **给「今天/我的」这类锚栏目做「至少留一个」约束，别用 `bool` 返回（2026-10-15 实做）**：底栏开关原本返回 `bool`，只有一种拒绝（满 5 个）。改成「锚栏目可关其一、禁两个都关」后就有**两种**拒绝，合成一个 `false` 会让 UI 只能瞎猜提示语。正解＝返回枚举 `NavToggleResult { ok, maxReached, needAnchor }`，UI 按值分派不同 SnackBar。另外**约束必须落在 controller 里**（UI 只负责提示）：被拒时**不得改动偏好**，否则「画成关、实际还开着」＝另一种形态的死开关。
- **多枚小组件的 requestCode 别按实例编号分（2026-10-15 实做）**：`PendingIntent` 的相等性**忽略 extras**，同一 `requestCode` ＋ `FLAG_UPDATE_CURRENT` 会让多个桌面实例共用同一个 Intent 对象。若各实例数据来源相同（都是同一份快照），共用反而正确；反过来按实例编号分散 requestCode，实例被删重建后会留下一批永远命中不到的 `PendingIntent` 槽位。判据＝**先问「实例之间的数据会不会不同」**，不会就别分。
