## 1 · 时间列实况（2026-10-15 全 schema 枚举·96 表）

> 枚举脚本 `tmp/timecols.py`（gitignored）；结论：**主体是毫秒时间戳 INTEGER，但存在三类异形**，
> 时间维度必须逐单元声明用哪一列，**不许自动猜列**。

| 类别 | 例 | 处置 |
| --- | --- | --- |
| 毫秒时间戳（主体） | `created_at`／`updated_at`／`started_at`／`ended_at`／`deleted_at`／`last_read_at`／`check_at` | 可直接比大小 |
| 业务日期（无时间时分） | `next_date` TEXT／`start_date`／`target_date`／`due_date`（记账 `tLedgerTxns` 用 `created_at`，`tLedgerRecur.next_date` 是 TEXT） | 归一为当天 00:00–23:59 比较 |
| **「几号」列（无年份，不可筛）** | 记账 `ledger_accounts.bill_day`／`repay_day` ·呵护 `care_vaccines.done_day` ·`care_cycle_pred.ov_day` ·习惯 `habits.week_days`（周几） | **一律排除出时间维度**（该维度不参与筛选，随所属单元恒全量） |
| **纯维度表（恒全量）** | `ledger_categories`／`ledger_tags`／`ledger_accounts`／`ledger_merchants`／`ledger_debts`／`ledger_wishes`／`care_carers`／`care_custom_events`／`habit_dict`／`habit_subs`／`days.day_preps`／`diary_templates`／`note_folders`／`mindmap_folders`／`media_dict`／`media_list_items`／`book_list_items`／`book_toc_nodes`／`book_dict`／`ai_calls`／`xray_entity`／`xray_mention` 等 | 恒全量（否则导出的数据残缺＝评估件 §8.6·2 表闭包的同类问题） |

**逐单元主时间列（唯一事实源＝`lib/shared/linkage/export_units.dart` 新增 `timeColumn` 字段）**：

- `read` ＝ `books.created_at`（**注意**：是建档时间不是阅读时间；`book_sessions.started_at` 是阅读时间——
  口径须产品点头，见 §2 待拍板 Q1）｜`journal` ＝ `journal.created_at`｜`health` ＝ `health_*` 各表 `created_at`
  （`health_sleep` 用 `bed_time`）｜`ledger` ＝ `ledger_txns.created_at`｜`care` ＝ `care_logs.created_at`
  ｜`habit` ＝ `habit_entries.check_at`｜`goals` ＝ `goals.created_at`｜`items` ＝ `item_events.event_date`
  ｜`media` ＝ `media_items.created_at`｜`xray` ＝ `xray_userdict.create_time`｜`mindmap` ＝ `mindmaps.created_at`
  ｜`ai` ＝ `ai_calls` **无时间列** → 恒全量（该单元时间维度不生效，面板须明说而不是静默忽略）。

**⚠ 口径空白（评估件 §8.5 只写「吃 `created_at`／`date` 列」未定哪个）**：

- **Q1** `read` 单元按 `books.created_at`（建档日）筛，还是按 `book_sessions.started_at`（阅读日）筛？
  后者需跨表子查询（`books.id IN (SELECT book_id FROM book_sessions WHERE …)`），复杂度高一档。
  **默认取前者**（建档日，与其他 11 单元「记录创建时间」的统一口径一致），要改需产品点头。
- **Q2** 「全部」档以外的筛选，**子表随主表走还是各自独立筛**？默认＝**子表随所属主表走**
  （`books` 命中即带其 `book_quotes`／`book_reviews`／`book_list_items`，避免半截数据）；要「各自独立筛」需产品点头。
- **Q3** 预估体积的折算口径：默认＝按筛选后行数占全表行数比线性折算（与批2「子集 DB 粗估＝实测基线 × 行数占比」同源，
  UI 带「约」字，不做逐行字节扫描）。

## 4 · 批4（部分恢复·A1 整组替换）规格要点 · 批3 收口后才开工

- 恢复侧读 manifest `scope`：无 `scope` 或 `scope.modules` 为空＝**全量替换**（现路径一字不动）；
  有 `scope`＝**按模块整组替换**：只对 `scope` 涉及的表先 `DELETE`（或 DROP 重建按批1 终态 DDL）再灌入，
  其他模块表**一行不动**。
- **恢复前 UI 必须明说两件事**（AGENTS「点了必须有看得见的变化」）：① 覆盖范围＝哪几个模块；
  ② 该模块本机数据会被包内版本覆盖 ·已有 safety 快照可回退。
- 真机门三条：① 子集恢复后其他模块数据逐条对账（数量与内容）；② safety 快照真能回退；
  ③ 子集包反复恢复幂等（第二次不产生重复行）。
- 变异刀：摘 `scope` 分流判据 → 必红（子集包误走全量替换＝全库清空）。
