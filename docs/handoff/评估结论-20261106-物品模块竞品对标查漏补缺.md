# 评估结论 · 物品模块竞品对标查漏补缺（2026-11-06）

> 口径：**评估件非施工工单**（只读评估，动工须产品点单）。对标对象＝GitHub 成熟开源物品/资产管理 app 六家；现状回源＝2026-11-06 对 `lib/features/items` 全量盘点＋需求清单模块 9 对照。差距分级 **P0~P3 可勾选**；**凡动 UI 先过原型门（产品点单→样张→确认→实现），涉及新字段/新表的批先走需求门修订模块 9 定义**。三源冲突优先序与屏单一归属照 `AGENTS.md`。

## 0. 定位校准（先说结论）

本模块的独特定位＝**「每日成本核算引擎」**：三计费（直线/按次/止损线）、成本池、决算报告与回收率、仅追加审计时间轴——对标六家**全都没有或只有初级形态**（仅 Snipe-IT 有多法折旧，面向税务；Homebox 折旧栏明标 No (manual)）。这是差异化壁垒，查漏补缺不动它。

反过来，竞品把「**实物资产属性**」做成一等公民——东西在哪（位置树）、长什么样（照片）、凭证在哪（发票/说明书附件）、借给谁（借出）、何时保养（维护）、三秒找到（搜索/条码）——本模块几乎全空：照片是 toast 占位、搜索框不存在、品牌/序列号/备注无字段、位置/借出/保养（L14 未落）全缺。**缺口不在账务深度，在实物侧**。

## 2. 现状清单（回源 2026-11-06）

**已强（不动）**：三计费引擎＋双口径、实时重算、仅追加成本时间轴（审计不可删改）、生命周期四操作（二次付费/回收两分支/报废决算/软删进回收站第七类）、统计六件套（今日合计/月支出/件均/Top5/分类环/6 月柱＋钻取）、L12 记账联动（升级建档/付费/回收自动流水）、L13 保修→提醒中心派生、JSON 备份纳入、决算分享卡、回收站 V1.61 全口径。

**已空（对标缺口）**：照片仅 UI 占位（`photo` 列预留恒空·点击 toast）；列表无搜索框、排序内部固定、筛选仅分类胶囊；档案无品牌/序列号/物品级备注/标签；无位置概念；无借出归还；**L14 保养↔日程待办需求已列未落**（时间轴仅 buy/extra/recycle/scrap 四类）；扫码未接物品（flutter_zxing 仅 read 模块 ISBN 在用）；按次用量数据层 `addUsage` 已建**零 UI 调用方**（按次模式仅按计划次数静态摊算）；CSV 导出无。

## 3. 可补全清单 I01~I14（可勾选·动工前过门）

- [ ] **I01 照片落地**：建档/详情拍照＋相册选图，本地存储写 `photo` 列（保险理赔最硬证据＝照片；先单图，多图列 I14）

- [ ] **I05 位置（房间→收纳位两层树）**：Homebox 核心心智；回收站恢复口径须带回原位置（联动 V1.61「回原分类原状态」语义扩展）

## 4. 明确不立项 X01~X06（别照抄）

- **X01 多用户/家庭协作**（Kept/Homebox 核心）——单机 app 定位外
- **X02 3D 地图/平面图**（Kept 特色）——过度工程
- **X03 QR 标签打印**——依赖打印机生态，手机场景不闭环
- **X04 耗材库存量/有效期/购物清单**（Grocy 域）——与「价值核算」定位冲突
- **X05 webhook/自动化生态**——服务器产品域
- **X06 搬家打包工作流**（Kept 特色）——低频

## 5. 交叉引用（已在既有台账·不重复立项）

L12 记账联动已落；L13 保修提醒已落；L14 保养未落＝本件 I06 对应；照片 AI 识别 V2 规划行＝I12 对应；物品插件化试点＝架构线（计划书插件平台机制）另议，不属本件。

## 6. 建议批次与开工顺序

- **批A（P0＝I01~I04）**：档案实证能力补齐——I03 需求门先行→原型样张→实现；I01/I02/I04 纯 UI 走原型门
- **批B（P1＝I05~I09）**：管家能力——I05/I08 涉及本地文件与树结构，注意与笔记挂载/图片存储清理的既有基建复用

- 每批照常：⚙ 执行面板→原型门→实现→批内增量＋变异刀；schema 变更批注意 DB 迁移链与复测包攒批口径
