## 前置 A · 适用范围与需求冲突裁决（开工前必读）

### A.0 适用范围澄清（防止代码模型自造）

本模块 ＝ **NFC 卡片**（物理标签的写入与触发）＋ **卡片数据管理**（App 内增删改）。以下内容**不属于本模块**，代码模型**一律不得实现**：

| 疑似需求 | 归属 | 处置 |
|---|---|---|
| `lh://` scheme 注册与解析 | 桌面模块批 1 | **不适用**；本模块只**消费**其白名单通道 |
| 快捷方式 / 小组件 / 通知动作按钮 | 桌面模块 | **不适用** |
| HCE 模拟卡（手机当卡被刷） | — | **明确不做**（须 `HostApduService` ＋ 常驻前台服务，与「零常驻服务」冲突） |
| NFC 支付 / 银行闪付 | — | **明确不做** |
| Mifare 私有指令 / 扇区加密 / 卡内口令 | — | **明确不做**（须私有 SDK；NDEF 层无此能力） |
| 只用 UID 的裸卡（门禁卡/公交卡/身份证/社保卡/银行卡） | 本模块**批 3 可选** | **首批不做**；做也只支持「App 在前台且亮屏时贴卡」，**不支持冷启动与锁屏**（Android 无 UID 卡的清单级分发通道，见 C25/B27）；这类卡多为只读 ⇒ **只登记指纹、不写卡** |
| 后台常驻巡检 / 前台服务 | — | **明确不做**（触发靠系统 NDEF 分发，见 C4） |
| 卡片云端同步 / 跨设备共享 | — | **明确不做**（零网络红线） |
| iOS / 桌面端 NFC | — | **不适用** |

> **红线**：代码模型若在本模块实现「HCE／NFC 支付／卡内加密或口令／常驻前台服务／第二套 NFC 插件／把 UID 轨做成冷启动或锁屏可用」，视为需求越界，判不合格。（UID 轨本身＝**批 3 可选**，口径见 C25。）

### A.1 需求冲突裁决表（逐条定音）

| # | 冲突/歧义 | 各方说法 | **冻结裁决（唯一口径）** |
|---|---|---|---|
| C1 | 卡片身份存哪 | 标签里存动作 vs 标签里存编号 | **标签只存编号**：单条 NDEF URI 记录 `lh://nfc/<cardId>`；名称/动作/图标全在本机表。理由：「改卡片数据」若靠重写标签，用户每改一次都得再贴一次卡（体验断点）；存编号后改数据**零贴卡** |
| C2 | 身份取 NDEF 还是 UID | UID 更「硬」、NDEF 可读可写 | **NDEF URI 为准**（`lh://nfc/<id>`）。UID 只作排障（不入日志正文，见 C11）。理由：`ACTION_NDEF_DISCOVERED` 由系统分发，**App 未运行时也能拉起**；UID 只能靠前台 `readerMode` 拿到，冷启动整条断 |
| C3 | 「增删改」到底改什么 | 用户原话「增删改 NFC 线圈卡片数据」 | 三件都落 **App 内记录**：**增** ＝ 新建卡片（并把它写进一张标签）／**删** ＝ 删记录（原标签变「未绑定」，可重绑）／**改** ＝ 改名·**换目标**（**不重写标签**）。「写入卡片」是独立动作，只在换卡/换机/卡损坏时用 |
| C4 | 触发要不要常驻服务 | — | **不需要**：Manifest 注册 `ACTION_NDEF_DISCOVERED`（`scheme=lh`＋`host=nfc`）→ 系统分发，冷启动即接住；前台由 `handle(intent)` 接住（`launchMode=singleTop` 已在）。**零前台服务、零轮询、零定时器** |
| C5 | 前台贴卡会不会打断正在编辑的内容 | — | 设**用户开关**「贴卡先确认再执行」，**默认关**（＝直接执行，与 `lh://` 冷/热启动同语义）。开则每次先出 `lhConfirm`。这是尼尔森 #3「用户控制与自由」的落点；**不做**代码侧「脏态」判定 |
| C6 | 同卡连续触发 | 天线贴住不动会反复回调 | **去抖 3 秒**：同一 `cardId` 3 秒内只执行一次；命中去抖窗口**不执行**（不震动、不计次）。窗口起点＝上次成功执行时刻。**V3 反馈分级（取 A 案·见 B43）**：窗口内**第二次**出 `AppToast`「刚刚触发过，等一下」，**第三次起**静默 |
| C7 | 卡片进不进回收站 | 全 app 八类删除内容有回收站 | **不进**。卡片只有一行记录、误删重绑一次即恢复；删前走 `lhConfirm` 并列明后果。理由：回收站加第十类的级联成本 ≫ 收益 |
| C8 | 卡片要不要进备份包 | 多数纯本机数据进包 | **进包**，**不加进 `excludeTables`**。理由：恢复备份后同一张物理标签仍可用（编号未变），这是「换机后卡片还能用」的唯一路径 |
| C9 | 卡片动作从哪来 | — | **只许引用桌面模块 §2.0 动作表**（`lib/core/platform/desktop_actions.dart` 编译期常量）；本模块**不新增动作、不写第二份跳转逻辑** |
| C10 | 动作能不能带参数（预填金额/分类） | `lh://ledger/add?amount=12` 先例 | **首批不做**。首批卡片只绑动作、不带参数；参数能力登记为**可选-批 3**，届时在同一动作表处扩展 |
| C11 | 卡号写不写进日志 | 敏感参数不入日志（桌面模块先例） | 卡号**不入日志正文**（只记「已触发卡片」不带 id）；排障需要时走 `debug` 级，与 UID 一同脱敏为**后 4 位** |
| C12 | 写卡是否要求标签空白 | — | **不要求**，但**必须先读后写**：读到合法 NDEF → 二次确认「覆盖后原内容会消失」；读到本 App 的另一张卡 → 文案升级「这已经是「X」卡片」（只可取消）；读到非 NDEF/认不出 → 按空白处理直接写 |
| C13 | 卡片图标可否自定义 | — | **不可**。卡片图标 ＝ **所绑动作的图标**（与动作表同源，线性 SVG）；首批不设图标选择器、不计入偏好 |
| C14 | 卡片归属分组 | 桌面模块归「外观与交互」组 | **同组**：`p-profile`「外观与交互」组内，紧邻「桌面与快捷方式」**下一行** |
| C15 | 卡片是否占用首页宫格 | 宫格已 15 枚 | **不占宫格**（低频管理面，不是内容模块）；入口唯一 ＝「我的 › 外观与交互」 |
| C16 | 新建卡片与写卡是否必须连做 | — | **否**：新建保存即落库（状态「未写入」），随后**自动进入写卡流程**，用户可当场取消；列表行内保留「写入」入口随时补写 |
| C17 | 触觉反馈 | 全 app 只许四锚，新增须产品拍板 | 首批**不加触觉锚**（写卡成功/触发成功均不震）；要加须按 `UI组件规范.md` 〇B 单独立项（挂 P1） |
| C18 | 卡片能不能绑「有状态目标」 | 产品追加＋参考 App 实测＝NFC 卡绑时间分类做 toggle | **能**。卡片目标分四类：`nav.*`（动作表 7 枚·跳路由）／`timer.cat`（**时间分类**·toggle 计时）／`read.book`（**书架某本书**·toggle 阅读会话）／`timer.duration`（定时长·可选-批3）。**目标表（§2.0）取代 V1 的「单一动作表」口径**；C9 收窄为「`nav.*` 类仍只引用动作表，不得各写一份跳转」 |
| C19 | 第二次触发算「结束」还是「开始」 | 产品原话「第一次＝开始，第二次＝结束该事件」 | **一律 toggle**：判据＝该卡目标**当前是否正在进行中**。进行中 → 结束；未进行 → 开始。**不做「按贴卡次数计数」**（次数与真实状态必然漂：中途在 App 内手动结束过、跨天、App 重启都会错位） |
| C20 | 时间卡 toggle 与时间模块既有单活规则的关系 | `TimeBlockDao.startTiming()` 自带「先收口上一段」（全局单活）；`activeTiming()` 注释即写「全局单活」 | **完全继承既有实现，本模块零仲裁**：开始＝`startTiming(day, nowMin, catId, catName)`；结束＝`endTiming(activeTiming().id, nowMin)`。贴「学习」卡时若在跑「运动」，按既有规则自动收口「运动」再开「学习」 |
| C21 | 阅读卡「第二次触发＝阅读完毕」的准确含义 | 产品措辞 | **＝结束本次阅读会话并落盘**（`endSession(bookId)`），**不是**把书标成「已读完」。理由：① 「读完」是**书的属性**不是会话的属性，误触不可逆；② 结束时按 `read.autoAsk` 走既有「记进度」弹层，用户可在那里把进度推到 100%。**卡片不提供「标记读完」** |
| C22 | 有状态卡要不要回执 | 桌面模块口径＝贴卡命中不给 toast | **要**：`timer.cat` / `read.book` 触发后**必须**给一行 `AppToast`，并复用既有结束路径（阅读侧＝`endReadPillTimer`，含 autoAsk 弹层）。理由：状态变化在贴卡瞬间**不可见**，回执是唯一确认信号。**`nav.*` 类默认不给 toast**（与桌面模块一致）；**V4 例外（2026-10-17 产品令）＝`nav.ledger`（记一笔）贴卡后给一行「已打开记一笔」**——跳进全屏编辑页后页面上没有任何「卡被认出」的痕迹，用户分不清生效还是误触 |
| C22-V3 | 回执文案口径 | **V3 纠错（代码回查）** | **文案以被复用函数为准，逐字沿用 `endReadPillTimer` 既有四态**：开始阅读《书名》／**《书名》已结束计时 · N 分钟**／**《书名》计时已取消**（第四态 V2 漏列）／时间卡「开始「分类」计时」／「已结束「分类」· N 分钟」／**第五态**（目标已失效但计时在跑）「已结束计时 · N 分钟」且**不报分类名**。**本模块不为对齐文案去改 `endReadPillTimer`**（单源红线优先）。依据：`timer_bar_overlay.dart:87-92` 实码 |
| C23 | 卡片要不要显示「进行中」 | — | **要**：卡片行在目标进行中时加「● 计时中」标记。判据**同源**：时间卡＝`activeTiming()?.catId == ref`、阅读卡＝`runningSession()?.bookId == ref`；**卡片自身不持久化任何计时态**（唯一源＝各模块库） |
| C24 | 目标被删（分类删掉／书删掉） | — | 卡片行标「已失效」（琥珀）；贴卡 → `AppToast`「这张卡绑的分类/书已经不在了」＋**不执行**、不自动重绑、不改卡片数据 |
| C25 | 非 NDEF 卡（门禁卡类）能不能绑 | 参考 App 支持 | **批 3 可选**，走**双轨识别**：轨 A＝NDEF URI `lh://nfc/<id>`（能力全：可冷启动分发）；轨 B＝**UID 指纹** `uid:<sha256(tag.id) 前 8 字节 hex>`（**仅 App 前台且亮屏**，须 `enableReaderMode` 前台分发）。两轨共用同一张卡片记录（`tag_key` ＋ `tag_kind`） |
| C26 | 锁屏/息屏能不能贴卡 | 参考 App 明说做不到 | **做不到，不承诺**：Android 锁屏下不向应用派发 NFC 事件（含 NDEF 分发须解锁回到前台）。方案只承诺「**解锁后**、App 在前台或可被系统拉起时」触发；UI 明写一行边界说明（§5.7），**不做**任何绕行尝试 |
| C27 | 要不要给卡片选型建议 | 参考 App 有 | **要**（一行灰字，**非教学文案**——属能力/器材说明，与「小部件读数可能略有延迟」同族）。**V3 改写法**（见 B41）：**UI 首选只列 NTAG213/215 ＋ 外型（硬币圆卡／身份证方卡）＋ 价格 0.5~2 元**；**字节数不写 UI**（工程口径写工单），NTAG216 保留在工单（更贵更小众，与「好买」相悖）。容量核算见 C33 |
| C28 | 卡片目标选择器的形态 | — | **扁平三区块单选**（快捷动作 / 计时分类 / 阅读书目），**不嵌套二级弹层**；三区块之间**互斥单选**（一张卡只能有一个目标）；区块内列表各取各的源（动作表 / 分类表 / 书架） |
| **C31** | 卡片「写入态」存哪（V3 补·H1） | 全档 5 处要求写入态，DDL 无列可承载 | Ddl 增 **`written_at INTEGER`**（**NULL＝未写入**，毫秒时间戳＝最后成功写入时刻）。**判定只读本列**，**不靠读标签反推**（写入态是历史事实，反推不可行）；写卡成功→置 now；换卡覆盖写入→覆盖 now；删行即随之消失 |
| **C32** | 触发点的 `host`/`ref` 从哪来（V3 补·H2） | §4.4 要求复用 `endReadPillTimer`，但它签名要 `(BuildContext, WidgetRef)`；而触发点在 `app` 组合根，**不在 build 作用域内** | `nfc_mounts` 两个转发口**内部自取**（不接受外部传 context）：① `ref`＝`ProviderScope.containerOf(rootContext)` 转 `WidgetRef`（先例＝`sys_pill_sync.dart:102` 批B 走根 Navigator）；② `host`＝根 `NavigatorState.context`（`navigatorKey.currentContext`），**须首帧后才取**。`context.mounted` 为假 ⇒ **本轮只落库、放弃弹层与 toast**，**不回滚不重试**。详见 B31 |
| **C33** | 卡片 `id` 生成规则（V3 补·H4） | §5.7 容量核算按 8 位短 id 算，实现若用 uuid 会让该数字**当场失真** | 入库生成 **12 位 base62 随机串**（`0-9a-zA-Z` ＋ `Random.secure()`）。**禁 uuid／时间戳／自增**（长度不可控、可枚举、泄露创建顺序）。标签上**可印 8 位短码**（id 前 8 位）供人眼识别，**短码绝不作判据**（B33） |
| **C34** | 模块归属口径（V3 补·H6） | 需求清单写「独立模块」，但四屏 `home` 均为 `index.html`（归 settings 家），注册表 grep nfc 0 命中 | **代码归属＝独立 feature 目录** `lib/features/nfc/**`；**屏归属＝settings 家 `index.html`**（原型已在位，**不迁专版**）。`docs/模块注册表.md` 由 `gen_registry.py` 生成，**禁手改**；要出现 nfc 行须改 `prototype/_modules.json` 并重跑生成器 |
| **C38** | `lh://` 立为**寻址契约**核心（V3·C 组·最高优先） | 产品 2026-10-15 提议 | **L1 寻址层立为唯一真源**：URI 形态统一 `lh://<ns>/<key>[/<arg>…]`，**ns 全部取自一张常量表**（与动作表同源生成，禁散落字面量）；所有外围入口（快捷方式／铺桌面／小组件／NFC）**必须引用 L1**；新功能一律**加 ns** 不进既有 ns；外围功能**禁**直接 import feature 业务方法（守 R1）。详见 §前置 A.3 |
| **C39** | 分发层**不设**「统一」KPI（V3·反向裁决·防过度设计） | 怕「统一架构」冲动伤到平台语义与热修链路 | 分发 action **按各自平台语义选择**，`lh://` 只约束 L1。**明确豁免三类**：① **NFC**（平台派发 `ACTION_NDEF_DISCOVERED`，**App 不可选**）；② 不开 App 的后台动作（service／自定义 action）；③ 既有 `content`/`file` 打开方式（属 EPUB/MD 通路，**禁并入 `lh` 命名空间**）。**验收反向条文**：代码模型若把 NFC 强行改成 `ACTION_VIEW`、或把悬浮窗既有 `ACTION_PILL_*` 改走 URL、或新造第 4 类自定义 action 承载功能型动作 ⇒ **判越界**。依据：`MainActivity.kt:688-692` 悬浮窗刻意不走 `lh://`，且是 6133/6135 热修承载的真机链路 |
| **C40** | 带参动作三级分级（V3·防「静默写错数据」） | `lh://ledger/add?amount=38.5` 若免确认直接记账，**链接被转发/篡改即产生错误流水** | **导航类**（`nav.*`）→ 可带参直接执行；**写入类**（记账／打卡／计时起停）→ **带参只做预填，提交须 App 内确认**；**删除类** → **一律不进 URL**（禁出现删除语义） |
| **C41** | 「可预先登记目标」原则（V3·2026-10-15 13:09 产品指正） | V2 曾误判「带 id 的目标做不了 NFC 卡」 | 一个目标能配 NFC 卡，**当且仅当其 id 满足「用户可在写卡时预选并写入卡片表」**。首批只配两类（产品 V2 已追加）：`timer.cat`（`categories.id`）／`read.book`（`books.id`）——两者**同构**，仅 id 所属库不同。**禁**为满足「URL 化」而从外部硬传 id（会引入 R1 跨模块取数、跨机失效、参数注入三重问题）。**`timer.cat` 与 `read.book` 逐字节同构**（§2.0 目标表两行对称＋C23 判据同源＋B23「只存 id 不存名」）。批 3 扩 `habit.item`／`media.item` 须加 `target_kind` 枚举，属新增需求 |
| **C42** | NFC 总闸（V3·D 组·H/参考 App 对照） | 参考 App 有「开启 NFC 计时首选项」总闸；我方 V2 只有两个明细开关 | 保留双明细开关（粒度更细、可单独关某一类）＋ **新增一条总闸** `nfc.enabled`（默认**开**）。**总闸关闭时贴卡完全静默无反应**（不报错、不弹提示、不震动、不计次）——否则用户关了却有反应会当成 bug。层级：**总闸 ＞ 明细开关**，任一关即不触发 |

### A.3 `lh://` 寻址契约（L1 唯一真源 · V3 新增 · C38/C39）

> **来源**：产品 2026-10-15 提议「以 URL Scheme 为核心，NFC／快捷方式等皆为其外围功能」。
> **采纳但精确到层**：不是「URL 为核心」，而是「**`lh://` 寻址契约（L1）为唯一真源，分发（L2）各随平台**」。
> **一句话判据**：**凡「进 App 的路」由平台决定 ⇒ 不可统一；凡「进 App 之后做什么」由本项目决定 ⇒ 必须统一。**

**三层架构**

```
L0  动作表（desktop_actions.dart）        ← 唯一真源：动作 id ⇄ 名称 ⇄ 路由 ⇄ lh:// path
     │  全模块复用，禁各写一份
     └─→ L1 寻址契约：lh://<ns>/<key>[/<arg>…]   ★ 唯一需要「所有外围功能共用」的一层
            ns = inbox|todo|journal|ledger|items|habit|today|nfc|…（取自一张常量表）
     │
L2  分发（各路自选，允许不同 action）            ← 不强求统一（C39）
     长按菜单／铺到桌面／小组件 → ACTION_VIEW + lh://
     URL Scheme                → ACTION_VIEW + lh://
     NFC 贴卡                  → ACTION_NDEF_DISCOVERED（data 仍是 lh:// URI）  ← 平台定死
     悬浮窗按钮                → 自定义 action + extra（既有 ACTION_PILL_*，不动）
     App 内 FAB                → 直接调 Dart 函数（零序列化）
     后台 isolate 动作          → service / 自定义 action
     全部汇聚 ↓
L3  Dart 消费：takeLaunchRoute 单次消费 → 同一份解析／校验／去抖／回执实现
```

**收益**：L1 单一真源（行为不分叉）＋ L3 单一消费（校验／去抖／回执只有一份）＋ L2 各按平台语义自由（不跟平台打架）。

**C39 豁免三类（验收反向条文）**：① NFC（`ACTION_NDEF_DISCOVERED`，**App 不可选**）；② 不开 App 的后台动作；③ 既有 `content`/`file` 打开方式（属 EPUB/MD 通路，**禁并入 `lh` 命名空间**）。
**判越界**：把 NFC 强行改成 `ACTION_VIEW` ／ 把悬浮窗既有 action 改走 URL ／ 新造第 4 类自定义 action 承载功能型动作。

**C40 带参三级分级**：导航类可直接执行；写入类**只预填、提交须 App 内确认**；删除类**一律不进 URL**。

## 1. 模块目标

**一句话核心目标**：让**一张物理卡片**成为 lifeHarness 的「摸一下就开始、再摸一下就结束」的物理开关——卡片既能跳去记一笔，也能**直接起停一段时间分类的计时或一本书的阅读**；卡片的名字与目标在 App 里随改随生效、**不必重写标签**。

**业务价值**：
1. **把记录动作从「点两下」压到「摸一下」**：床头贴「睡眠」、书桌贴「学习／那本书」、玄关贴「记一笔」——物理位置即入口，直击记录摩擦最高的一段。**尤其解决计时场景**：计时最怕「忘了按开始/结束」，卡就贴在做事的位置上（C27 张贴建议）。
2. **补上场景化与无障碍入口**：开车/做饭/睡前等不便看屏的场景，摸卡即落一次记录。
3. **复用 `lh://` 底座，边际成本低**：寻址、解析、投递、兜底全继承桌面模块，本模块只加「卡片数据层 ＋ 写读 UI」。
4. **零云依赖、零新增网络面、零常驻服务**：纯本地，契合项目隐私与功耗红线。

### 2.2 批 2 · 写卡与触发（必选-批2）

| # | 功能 | 验收标准 |

| F2-1 | 写卡（原型 `sheetNfcWrite`） | 前台分发读标签 → 构造**单条 NDEF URI 记录** `lh://nfc/<cardId>`（`cardId` 12 位 base62·C33）→ 写入；成功后**写 `written_at=now`**（C31，不跳列表不关弹层，**B39：弹层保留等用户完成命名绑定**）并把该行写入态置「已写入」；**写完不自动跳任何屏**。⚠ **写卡成功后 3 秒内同卡贴卡只更新写入态、不执行**（B39） |

### 3.2 跳转关系

```
「我的」p-profile
  └─[点击行]→ /nfc（p-sub-nfc）
        ├─[「新建卡片」/ 空态虚线行]→ sheetNfcEdit（新建态）→[保存]→ sheetNfcWrite（写卡）
        ├─[点卡片行]→ sheetNfcEdit（编辑态）
        │        ├─[「写入卡片」]→ sheetNfcWrite
        │        └─[「删除卡片」]→ sheetNfcDel →[确认]→ 回列表（行数与入口计数随动）
        └─[返回 / 系统返回]→ 回「我的」（栈顶 pop，不新增栈）
外部：贴 NFC 标签（系统 NDEF 分发 / 批3 前台 UID 轨）
  └─→ MainActivity.handle(intent) → takeLaunchRoute → app 组合根
        ├─ 命中 `nav.*` 卡   → context.go(动作路由)（冷启动无返回栈）
        ├─ 命中 `timer.cat` 卡 → toggle：查 `activeTiming()` → `endTiming` 或 `startTiming` ＋ 回执
        ├─ 命中 `read.book` 卡 → toggle：查 `runningSession()` → `endSession`＋autoAsk 或 `startSession` ＋ 回执
        ├─ 未绑定卡 / 陌生 UID → go('/nfc') ＋ 打开 sheetNfcEdit（绑定态）
        └─ 目标已失效 → AppToast ＋ go('/')
```

- 管理屏为**全屏栈页**（同 `p-sub-desktop`/`p-sub-notify`），顶部自带返回，**不占底栏**。
- 写卡/绑定层关闭后回管理屏；**不产生新栈**。

### 3.3 返回与状态保持

| 场景 | 行为 |
|---|---|
| 管理屏返回 | `pop` 回「我的」；改名/换目标**已即时落库**，返回不丢 |
| 写卡层系统返回 | 等同「取消」：关层回列表，卡片保持「未写入」，**不 toast**（B7） |
| 贴卡冷启动 | 直达目标屏，**无返回栈**（回 `/`） |
| 贴卡热启动（singleTop） | 复用实例，`go(动作路由)` 替换栈顶，不堆栈 |
| 写卡中 App 切后台 | 写卡层保持打开态；回前台继续等待（30s 超时照算） |

| **① 我的卡片** | 行 ＝ 图标块（**目标类图标**：导航／计时／阅读三种）＋名称＋副文案「目标 · 用过 N 次」；目标**进行中**时副文案前加「**● 计时中**」（品牌色·C23）；右侧写入态：未写入＝`写入` 小钮／已写入＝灰字「已写入」；点行体 → 编辑态弹层；右上「新建卡片」＋「共 N 张」计数 |
| **② 贴卡行为** | `贴卡先确认再执行`（默认关）／`未识别卡片提示绑定`（默认开）；切换即时落偏好，**无 loading** |
| 空态 | 虚线描边行 ＋ 居中灰字「还没有卡片 · 点这里新建」，点击＝新建（LH-L04 定式） |
| 行卡样式 | 与「桌面与快捷方式」同款（`card`＋`set-ic`＋底部 1px 分隔线），**禁新造控件** |

### 4.2 新建/编辑卡片层

- **字段顺序**（自上而下）：① 卡号提示行（**仅绑定态**）② 名称输入 ③ **目标三区块** ④ 主钮「保存」
- **名称**：文本框，硬限 12 字（B14）；留空 → 点保存时框下出红字「起个名字」并保持层打开（B13）
- **目标三区块**（C28·**扁平单选，无二级弹层**）：
  - 「**快捷动作**」＝动作表 7 枚
  - 「**计时分类**」＝时间模块分类列表（经 `nfc_mounts` 取；多级分类显示父级路径，B23）
  - 「**阅读书目**」＝书架书目（经 `nfc_mounts` 取；显示在读数·B24）
  - 三区块**互斥单选**（一张卡只能有一个目标）；默认选中第一区块第一项
  - 区块内无数据时（例如书架为空）→ 该区块整块隐藏并给一行灰字（「书架里还没有书」），**不显示空 chips**
- **编辑态额外两行**（目标三区块之下、主钮之上）：「写入卡片」行（右侧显示「已写入/未写入」）／「删除卡片」行（红线文字）
- **保存**：新建态 → 保存后层切到 `sheetNfcWrite`；绑定态 → 直接关层回列表（**不写标签**）；编辑态 → 关层回列表

### 4.3 写卡层状态机（唯一真相）

```
idle ──[进入层]──→ waiting（把卡片贴到手机背面）
waiting ──30s 无卡──→ 关层（B7·不 toast）
waiting ──读到标签──→ reading
reading ──只读────────→ err_readonly（B3）──[换卡]──→ waiting
reading ──非 NDEF─────→ err_nonndef（B4）──[重试]──→ waiting
reading ──空白/本机空卡→ writing
reading ──已有内容────→ occupied ──[覆盖写入]─→ writing ／ [取消]─→ 关层
reading ──本机另一张卡→ occupied_own（「这已经是「X」卡片」，仅可取消）
writing ──成功────────→ done（层内对勾，1.2s 后自动关层回列表）
writing ──失败────────→ err_capacity（B5）／ err_broken（B6）──[重试]──→ waiting
```

- 层内文案随状态**在同一行位替换**，只出当前状态，不堆历史。
- 写卡中「取消」仍可点：中断写入并关层（卡片保持「未写入」）。
- **演示开关**（原型）：控制台 `nfcWriteSim('ok'|'readonly'|'nonndef'|'capacity'|'broken'|'occupied'|'occupiedOwn')` 驱动各档，供无头回归与人工走查。

### 4.4 贴卡触发（两制）

**导航卡（`nav.*`）**——与 V1 一致：

- **冷启动**：系统拉起 App → 直达动作目标屏，**无返回栈**、无中转 loading（与 `lh://` 同语义）
- **热启动/前台**：`singleTop` 复用实例 → `go(动作路由)` 替换栈顶
- **无回执**（同桌面模块口径）

**有状态卡（`timer.cat` / `read.book`）**——C18~C23：

- **toggle 判据（唯一）**：目标当前否进行中（时间卡＝`activeTiming()?.catId == target_ref`；阅读卡＝`runningSession()?.bookId == target_ref`）
  - **进行中 → 结束**：时间卡 `endTiming(activeId, now)`；阅读卡 `endSession(bookId)` 并**复用 `endReadPillTimer`**（toast ＋ 按 `read.autoAsk` 弹「记进度」）
  - **未进行 → 开始**：时间卡 `startTiming(day, nowMin, catId, catName)`；阅读卡 `startSession(bookId)`
- **必有回执**（C22）：四种文案——「开始「学习」计时」／「已结束「学习」· 42 分钟」／「开始阅读《书名》」／「《书名》已结束 · 23 分钟」
- **单活完全继承**（C20/B20）：时间卡开始前若在跑另一段，由 `startTiming` 自带收口（**本模块零仲裁**）；阅读卡同理。回执只报当前这一件
- **不回 App 不回首页**：触发后**不跳屏、不弹层**（除了阅读结束时的 autoAsk 记进度弹层）——用户贴完卡继续干自己的事，靠悬浮胶囊看时长
- **去抖、确认开关、未绑定引导、失效目标**与导航卡同规则（§前置 A.2）

**通用**：

- **总闸优先（C42）**：`nfc.enabled` 关 ⇒ **完全静默无反应**（不报错、不弹提示、不震动、不计次），**先于下面所有判定**（含去抖、确认、绑定引导）
- **确认开关打开时**：先出 `lhConfirm`（标题＝卡名，正文＝目标名），确认才执行
- **去抖**：3 秒窗口内同卡**不执行**（不震动、不计次）；**窗口内第二次出 `AppToast`「刚刚触发过，等一下」，第三次起静默**（C6-V3/B43·取 A 案）
- **host/ref 自取（C32·V3）**：有状态卡需要弹层/toast 时，`nfc_mounts` 内部自取——`ref`＝`ProviderScope.containerOf(rootContext)`、`host`＝根 `NavigatorState.context` 且**须首帧后才取**；`context.mounted` 为假 ⇒ **本轮只落库、放弃弹层与 toast**（B31），**不回滚不重试**。先例＝`sys_pill_sync.dart:102`
- **分发与解析合流（C36/C37·V3）**：NFC 的 `ACTION_NDEF_DISCOVERED` data 交**同一条** `ACTION_VIEW` 解析分支与 `takeLaunchRoute` 通道（C39 豁免①：分发 action 平台定死，**但解析与消费只有一份**）；id 须做 12 位 base62 校验、非法静默丢弃、**不得回显**（B35）
- **id 未命中降级（B35）**：查不到该 id ⇒ 走 B8「未绑定引导」口径，**禁**掉进 `unknownRouteFallback`（那是页面，会把内部寻址暴露成用户可见的报错页）

### 4.5 动画

- 写卡等待：层内**呼吸圆环**（1.6s 循环，`ease-in-out`）——**本模块唯一允许的循环动画**，离开层即停
- 写卡成功：一次性对勾（200ms），随后 1.2s 自动关层
- 写卡失败：无弹跳，文案就地红字替换（200ms 淡入）
- 卡片行按下：`active:scale-[.98]`（与既有行卡一致）
- 新建卡片插入列表：无入场动画（与设置类列表一致）

### 4.6 加载与反馈

| 场景 | 反馈 |
|---|---|
| 保存卡片 | 无 loading（本地写） |
| 写卡成功 | 层内对勾 ＋ 自动关层；列表行写入态改「已写入」 |
| 写卡失败 | 层内文案，**不 toast** |
| 贴卡命中（`nav.*`） | 目标屏自身回执；**不额外 toast** |
| 贴卡命中（`timer.cat` / `read.book`） | **必有 `AppToast` 一行**（四种文案见 C22）；阅读结束按 `read.autoAsk` 追加「记进度」弹层，**不另跳屏** |
| 未绑定卡 | 落屏 ＋ 绑定表单，**不 toast** |
| 目标已失效（分类/书已不在） | `AppToast` 一行（「这张卡绑的分类/书已经不在了」）＋回 `/`，**不自动重绑**（C24） |
| 失效目标 | `AppToast` 一行 ＋ 回 `/` |
| 系统 NFC 未开 | 层内一行 ＋「去设置」；**不 toast** |

## 6. 开发约束

### 6.1 Flutter 实现限制（架构红线）

- **目录**：`lib/features/nfc/`（`domain/nfc_card.dart`｜`data/nfc_repo.dart`｜`data/nfc_tag_io.dart`｜`presentation/nfc_page.dart`｜`presentation/nfc_sheets.dart`）；路由**仅加一行** `/nfc`（本模块路由表，**不动其他路由**）
- **跨模块唯一出口（本批新增·守 R1）**：`lib/shared/linkage/nfc_mounts.dart`——对外只存**四个转发口**：`nfcCategoryOptions()`（分类列表）／`nfcBookOptions()`（书目列表）／`nfcToggleTimer(catId, catName)`（时间卡两向）／`nfcToggleRead(bookId)`（阅读卡两向，内部复用 `endReadPillTimer`）。**⚠ V3（C32）**：后两个转发口**内部自取 `ref`/`host`**，**不接受外部传 context**（先例＝`sys_pill_sync.dart:102`）。`features/nfc/**` **禁止 import 任何 `features/calendar/**`、`features/read/**`**；反向也禁止（守护 `architecture_test` R1）
- **动作表只读引用**：`nav.*` 类一律取 `lib/core/platform/desktop_actions.dart`；**禁**在本模块再写一份动作/路径常量
- **禁 feature 直连**：本模块与各业务 feature **互不直连 import**；跳转只用动作表 `path` ＋ 既有事件总线（守 R1）
- **`lh://` 解析只在原生**：Dart 侧只消费动作 id / 卡号，**不接触原始 URI**（与桌面模块 C13 同口径）
- **偏好键**：`nfc.confirmBeforeRun` / `nfc.promptUnbound`（**仅加 `nfc.*`，不改既有键**）
- **禁新造弹层容器/确认框/空态/toast**（复用 §5.5）
- **DB**：新表只进**基础 DDL** ＋ `nfc.mig` 聚合，**不在老口径语句表加语句**（老库直升不撞 duplicate column——v45/v47 的既有教训）
- **备份/恢复三处登记（C8-V3·V3 补·H3，缺一即视为未进包）**：① **不加 `excludeTables`**（全量实表差集自然收）；② **`lib/shared/linkage/export_units.dart` 新增 `ExportUnit(id:'nfc', tables:[DbSchema.tNfcCards])`** —— 不登记则**子集备份不导出该表**（子集走 `exportTablesForModules` 差集法，未登记＝归属不明＝不收），而子集备份是 V1.66 批 2 刚拍板的主推路径；③ **`lib/core/backup/db_overview.dart` 表元数据补 `'nfc_cards': (label:'NFC 卡片', module:'NFC')`** —— 不登记则概览屏不显示、恢复报告无中文标签
- **零新增网络面**：不得引入任何联网能力的插件

### 6.2 原生（`android/**`）实现限制

- **Manifest 改动面（唯一三处）**：① `<uses-permission android:name="android.permission.NFC"/>`；② `<uses-feature android:name="android.hardware.nfc" android:required="false"/>`；③ `MainActivity` 加 `ACTION_NDEF_DISCOVERED` intent-filter（`<data android:scheme="lh" android:host="nfc"/>`）。**不动**既有 5 组 intent-filter（EPUB/MD/SEND 通路一字不改）；**不重开** `flutter_deeplinking_enabled`
- **`MainActivity.kt` 改动面**：`handle()` **仅加 `lh://nfc/*` 分支**（取 path 末段作 cardId，**做 12 位 base62 校验·B35**，投给桌面模块批 1 的 `lh/launch` 通道 `takeLaunchRoute`，**与 `ACTION_VIEW` 共用同一解析分支**·C36）；既有 `lh/intents` 一字不改；`ACTION_PILL_END/NOTE` **一字不改**（悬浮窗刻意不走 `lh://`·C39 豁免②）
- **插件**：`nfc_manager`（内部即 `NfcAdapter` 封装）；**不引第二套 NFC 插件**；零网络、零前台服务
- **UID 轨（批3 可选）**：只在 `/nfc` 屏处于前台时 `enableReaderMode`，**离开屏立即停**；不在 Application/常驻处注册；`tag.id` **只算指纹不入日志**（同 C11）
- **Kotlin 收口**：动 `android/**` 的批**必须**跑 `bash tools/kotlin_check.sh`（`flutter analyze` 盖不住 Kotlin）
- **图标**：线性 SVG → 矢量 drawable；**禁 emoji、禁彩块**

### 6.3 性能要求（秒开 / 缓存 / 功耗）

| 项 | 规格 |
|---|---|
| 管理屏 | 秒开；卡片列表本地表查询 O(N)（N ≤50 量级），**不做分页** |
| 贴卡→落到屏 | 冷启动不额外加时（解析在原生、一跳到 Dart）；热启动 ≤100ms 内 `go` |
| 去抖 | 内存窗口（**不落盘、不查库**） |
| 功耗 | **无定时器常驻、无后台巡检、无前台服务**；NFC 读取只在写卡层（或批3 UID 轨的 `/nfc` 屏）打开期间进行，离开即停 |
| 有状态卡触发 | 只做两次库读写（判进行中 ＋ 起/停），并发悬浮胶囊 tick 照旧；**触发不重建页面**（不跳屏） |
| 系统 | 触发靠系统 NDEF 分发，App 不持有 NFC 监听 |
| 包体 | 新增 `nfc_manager` 增量小（估 <200KB）；DB 加一张表 |
| 隐私 | 卡号不入日志正文（C11）；卡片数据全本地、零网络 |

## 7. 参考实现对照（他 App 的「NFC 计时」）与落地口径

> 来源：产品 2026-10-15 提供的他 App 官方 FAQ 截图（NFC 计时）。他只做「NFC→时间分类计时」一件事，本项目把它归入更大的「卡片＝目标」模型（§2.0）。

| 他 App 的做法 | 本项目落地 | 差异与理由 |
|---|---|---|
| 先「空白卡写入」→ 再贴一次进编辑页绑分类（两步） | 「新建卡片」（选目标）→ 保存 → **自动进写卡层**（一步）；若用户想「先写卡后绑定」，贴未绑定卡走 B8 即等价 | 少一次贴卡；两条路都通。**V3 补 B39 防坑**：写卡成功后弹层**保留不自动关**，且 3 秒内同卡贴卡**只更新写入态不执行**——否则用户「卡已贴好但还没填名称就去摸手机」会在填名称过程中误触发 |
| 有一个「开启 NFC 计时首选项」**总闸**开关 | **V3 采纳 C42**：保留双明细开关 ＋ **新增总闸** `nfc.enabled`（默认开），关时**完全静默无反应** | 粒度比它细，但缺总闸用户无法一键全关、「关了还能触发」会像 bug |
| 列表行＝**彩色块 ─ 链形符 ─ 行为徽标** | **V3 部分采纳 B42**：加一枚**目标徽标 chip**（用目标类名），与 C23「● 计时中」共存；**不采纳多色块** | 多色＝每类一套色，违 `UI组件规范.md` 〇B 色值棘轮且深浅态各配一套 |
| FAQ 明说「**息屏贴卡会有震动反馈**，说明息屏不监听 NFC」 | **V3 采纳 B40**：锁屏边界文案**必须点出震动** | C26 结论本就一致，但它给了**用户可感知的原因**。「震了没反应」是本模块最可能的差评来源；只写「不派发事件」是开发者语言 |
| 非空白卡（门禁卡/身份证/社保卡/银行卡）直接贴 → 自动跳编辑页绑分类 | **批3 可选**：前台 UID 轨（C25/B27） | 这类卡多为只读⇒**只登记指纹不写卡**；且**不承诺冷启动与锁屏**（Android 无 UID 卡的清单级分发通道） |
| 图片中「卡片写入页」放在「我的 › NFC 卡片 › 右上角」 | 本项目入口＝「我的 › 外观与交互 › NFC 卡片」，按钮＝右上「新建卡片」 | 位置一致（都归设置侧）；本项目不占宫格（C15） |
| 卡片绑「时间分类」或「时长」 | 同口径：`timer.cat` 为**必选**，`timer.duration`（定时长）降为**可选-批3** | 分类＝他 App 的主体用法；定时长属番茄类，不混进首批 |
| 张贴位置：书桌＝学习／床头＝睡眠／卫生间＝洗漱 | 同思路，但**位置属用户自组织**，只给一行示例灰字（§5.7） | 项目禁教学文案，不做引导蒙层 |
| 卡片选型：ntag213/215/216、硬币大小的圆卡、0.5~2 元 | §5.7 登记同口径＋容量核算 | 写入量小（≈30 字节），213 绰绰有余 |
| 「为什么不能息屏刷」＝安卓限制 | C26 同口径，**UI 必显一行** | **不做绕行尝试**（无公开通道），也不以此削减承诺之外的实现 |
