## 1 · 为什么判据③ 必须改口径（不是没达标，是刻度错了）

**判据③ 原文**（治理档 §5）：`lib/features/read/**` ≤4 万行。

**现状**：49,020 行／105 文件，缺 9,020 行。

⑱ 已逐条实测原文列的三条降行路径，**结论是全为零**：

| 路径 | 实测 | 可省行数 |
|---|---|---|
| 死代码清理 | `dart analyze lib/features/read`＝**0 warning/0 error**（仅 3 条 info） | **0** |
| 重复 widget 抽取 | 同名 widget 类跨文件重复 **0 个**；跨文件重复 ≥8 行块 95 个全抽完 | **≤344** |
| 废弃样式回收 | 零引用顶层常量 **0 个** | **0** |

> 死代码零的结论已用**变异自证**钉住：往 `epub_cache.dart` 注水一个私有函数与一个私有 class，分析器如期报 2 条 `unused_element`；复原后回 0 warning。**不是分析器没这能力。**

**理论上限 344 行，对 9,020 行缺口是 4%。剩下 8,676 行是真在跑的代码。**

### 1.1 产品追问「改阅读功能时会不会全量进上下文」——实测结论：不会

这是把口径从「体量」换到「负担」的关键依据。实测三个真实改动场景（read 模块总量 162 万字符／105 文件）：

| 改动场景 | 符号定位命中 | 实际需读 | 占全量 |
|---|---|---|---|
| 改阅读器选区操作栏 | 2 个文件 | 4.9 万字符 | **3.0%** |
| 给 EPUB 缓存加字段 | 3 个文件 | 7.5 万字符 | **4.6%** |
| 改 X-Ray 生词本面板 | 7 个文件 | 14.5 万字符 | **9.0%** |

**上下文不是按模块加载，是按文件加载的。** 而单次命中量能压到 3~9%，**恰恰因为文件已经拆开了**——若当初 49,020 行塞在一个文件里，改任何一行都得整读。

**⇒ 总行数不是负担来源，单次改动要触碰的量才是。** 这是判据③ 必须换刻度的实质理由。

### 1.2 关键更正：「单文件 ≤1,200 行」这道闸**已经存在**（⑱ 收尾时未核，本单核出）

`test/size_budget_test.dart` 已有 `lineBudget = 1200` 的单文件行数闸，且 **`read` 的登记项已清零**（批 6b/6c 三刀拆 part 全部还债：刀1 `read_sheets_b3` 1341→442、刀2 `read_stat_page` 1259→453、刀3 `reader_page` 1226→1047）。

**⇒ 当前 read 最大 12 文件全在 990~1,188 行，全部在默认面内。这道闸现在就是绿的。**

**本单不新建任何行数闸**——这是修正上一轮口头建议里「要新建一道单文件闸」的错误认知，那道闸已经在跑。

## 2 · 口径重定方案（产品已拍板 ①）

### 2.1 治理档 §5 判据③ 原文划改

| | 内容 |
|---|---|
| **原口径** | `lib/features/read/**` ≤4 万行（总量） |
| **新口径** | **① 单文件 ≤1,200 行**（已有闸 `size_budget_test.dart`，read 登记清零＝已达标）＋ **② 单模块 import 扇入**（新增维度，本批**只报数不设闸**） |
| **废止** | 总量 ≤4 万行（缺口 9,020 行不可达，且该刻度与真实上下文负担脱钩——见 §1.1） |

**② 为什么扇入才是直接度量**：单文件 ≤1,200 行限制了「一次打开多大」，但没限制「一次改动要打开几个」。全仓实测（439 个有 import 的 `.dart`）：

```
中位数 6  ·  平均 7.5  ·  P90 15  ·  P99 25  ·  最大 42
超 30 个 import 的文件：3 个
超 40 个 import 的文件：2 个
超 50 个 import 的文件：0 个
```

**越线三件**（本批只登记留账，不动代码）：

| 文件 | import 数 | 性质 |
|---|---|---|
| `lib/features/read/presentation/reader/reader_page.dart` | **42** | 全仓最高；批6c 刀3 已拆到 1047 行，但扇入未治 |
| `lib/main.dart` | **41** | 应用入口，天然要引全部模块；**属结构性，不建议治** |
| `lib/core/router/app_router.dart` | **31** | 路由集中注册，同上 |

**本批动作**：`tools/fanin_report.js` 出一次全仓扇入清单并归档读数；**不设判红闸**（产品 22:06 拍板③）。

### 2.2 明确不做的事（防假达标）

- ❌ **不删注释、不删空行凑行数** —— 数字好看了，代码一行没变，维护成本一点没降。
- ❌ **不把代码挪到别的目录凑总量** —— 行数掉了但一行没消失，只是换抽屉。
- ❌ **不删 `feature_size_budget_test.dart` 的 `'read': 49020` 登记** —— 该闸是**只许减不许增**的棘轮，作用是「防止继续长大」，与判据③ 的 4 万线是两件事。删了它才真出事。
