## 一、现状核查：互动三钮到底通到哪

| 能力 | 结论 | 依据 |
|---|---|---|
| 点亮（心形 like） | **有落库、有视觉态，但无任何消费出口** | INS 卡 → `repository.setFlags` → `dao.setFlags` → `journal_entries.liked` |
| 收藏（星形 star） | 同上 | 同上（`journal_entries.starred`） |
| 评论（气泡） | **未实现 · 纯占位** | `ins_card.dart` 评论钮＝`AppToast.show('评论/批注 · 规划 V1.x')` |
| 分享 | **未实现 · 纯占位** | `ins_card.dart` 分享钮＝`AppToast.show('分享日记卡片 · 规划 V1.x')` |
| 回望计数 | **已实现 · 真计数** | `entry.viewCount`，打开日记即 +1 |
| 筛选 | **已实现 · 且已持久化** | 实现侧 `_diaryFilterSheet`；#27 进 `SettingsRepository` |
| 列表 / INS 双布局 | **已实现 · 布局选择已持久化** | `journalIns` 进 Settings 四处同步 |
| 日记搜索 | **缺 · 已登记未修** | 顶栏搜索钮只搜笔记（查漏补缺评估件 §三 UX 段） |

### 核心结论：点亮／收藏是「死胡同」

落库链路是完整的，问题在下游——**全仓只有 `ins_card.dart` 读这两个字段**
（`lib/features/journal/presentation/` 内零其他命中）。由此三条断口：

1. **切回列表布局，收藏态完全不可见、也不可操作**（列表篇卡不读 `starred`/`liked`）；
2. **筛选面板没有它们**——选项＝`['全部', '☐ 待办', ...tags]`（实现侧 `_diaryFilterSheet` 现读），
   原型侧同为 `['全部','☐ 待办','#加班','#复盘']`，两端口径一致地都没有「收藏／点亮」；
3. **无收藏夹视图、无「我的回望」入口**。

⇒ 产品判断成立：**点了有回执、有落库，但没有任何地方能再把它们取出来用**。
这是「半成品态」——比没做更差，因为用户会以为自己收藏成功了。

### 评论与分享：明确在需求门外

查漏补缺评估件文末已定性：「后续仅剩需求门外的 V1.x 规划项（INS 分享／评论等占位）」。
即两者**不在现行需求内**，不是「欠修」而是「未立项」——要做得先走需求门。

## 二、竞品借鉴（三张截图归纳）

> 对象＝一款日记 App。三图＝**同一批数据的三种视图**，顶部一键切换。

### 视图一 · 时间流（左栏日期轨道）

- **左栏日期四档分层**：日号（15）＞ 月份（3月）＞ 星期（星期日）＞ 时刻（16:07）；
- **右栏**＝该条正文与图片，条目下带**地点行**（上海市 崇明区 东平国家森林公园）；
- 顶部＝菜单／标题／标签／搜索；**下一条日期顺次下移**（14 3月 星期六 17:11）；
- 机制＝整列随滚动上移，新日期从下方把旧日期顶出。

### 视图二 · 瀑布流（双列图卡）

- 两列不等高图片卡，卡下只标日期（2024/06/06 · 2023/02/16…）；顶部「随机」＋视图切换钮。
- 适合**图片密度高**的库：日期退为脚注，主角是图。

### 视图三 · 月历图墙

- **月历每格＝当天内容缩略图**（有无内容一眼可见）；顶部「今日／分享月历」；
- 下方「自定义日历图」＋选中日详情（1 二月 星期三 00:01 ＋大图＋分类标签）。

### 可移植性判断（对照 lifeHarness 日记现状）

| 借鉴点 | 与现状的关系 | 判断 |
|---|---|---|
| 左栏日期轨道 | 现 INS 卡头是**一整行小字**（昵称·日期·星期·天气·心情） | **可改** · 日记一天可多篇 ⇒ 右栏有实内容 |
| 日期四档分层字号 | 现无 | **可改** · 零数据成本 |
| 月历图墙 | 首页已有「心情月历卡 ＋ 30 色条 · 点色条看当天」 | **可升级** · 同一骨架；但日记以文字为主，须先定义「没图的格子」怎么画 |
| 地点行 | 日记已有城市／天气字段（`sheetCityPick`／`sheetWeatherPick`） | **可展示** · 数据现成 |
| 瀑布流 | 现无；INS 卡片流＝单列大卡 | **不建议照搬** · 会放大「没图的日子」，与文字型日记的内容形态不符 |
| 视图切换 | 已有 列表 ⇄ INS 两档 | 可扩为三档，但**每增一档都是实现面**（不是免费） |

## 三、结论

- **可做且贴题**：日期轨道（时间流）＋ 月历图墙升级——两者同一思路（日期即主角），且所需数据全部现成。
- **不建议**：瀑布流（内容形态不匹配，会惩罚无图日记）。
- **互动出口二选一**：点亮／收藏要么**补出口**（筛选项 ＋ 收藏视图 ＋ 列表态可见），要么**明确下线**；
  维持现状是最差解。
- **三处前置**：① 需求门（评论／分享属新增需求）；② 原型门（版式先改原型）；
  ③ 左栏竖向吸顶需自定义 Sliver——**全仓零 `SliverPersistentHeader`／`StickyHeader` 使用**，属新版式件。
- **玻璃质感提醒**：实现侧 `BackdropFilter` 已被真机反馈否决并全摘（阅读器顶／底栏、影音游计时页三处注释点名，
  2026-09-28），重启须先过原型门 ＋ 真机复验；且日记页为纯色底，玻璃需先有「可透的背景」才成立。
