## 1 · 为什么要做（病根诊断 · 实测读数）

现行文档瘦身规则**只卡"字节/行数上限"，不卡"该沉什么"**。后果是每轮收尾照抄读数、闸红了就再放宽上限，永远回不到默认面。2026-10-16 实测三件病状：

| 件 | 实测 | 上限/黄线 | 病灶（行数闸看不见的部分） |
|---|---|---|---|
| `docs/STATUS.md` | **13,931 字节 / 17 行** | 14,336 / 黄线 12,902 | **已越黄线**。单行滚存：下一站 1,192 字符、复测包 1,013、未推 755、基线各行 400~700。全靠"追加式"堆读数 |
| `docs/INDEX.md` | **84,698 字节 / 118 非空行** | 行数预算 130（**已超**·存量） | **69%（30,799 字符）挂在 43 条已归档件的行尾流水上**，其中一行 **11,930 字符**；活件仅 18 条。**无字节闸** |
| `docs/排期池.md` | **13,784 字节 / 65 非空行** | 20 KiB / 120 行 | 速览表 11 行 + 详情段 10~13 占 19 行，**详情与速览重复登记同一读数** |

**共性病灶＝"已完成的叙事钉在现行件里"**。三件都越界或贴界，但每件超的都是"历史"，不是"现状"。

## 2 · 规则优化方案（三条，按可执行度排序）

### 规则一 · 内容型闸取代单纯的量型闸（核心）

对三件各加一道**内容型判红**——不看总字节，看**该沉的内容是否还在现行件里**：

- **守护二十「INDEX 归档件行瘦身」**：`docs/INDEX.md` 里每条 `| docs/archive/… |` 行正文 ≤ **220 字符**（现状中位数远超）。归档件只需"在哪、能查"，不需要"做了什么"。超限 → 红并打印实际长度。
- **守护二十一「STATUS 单行滚存上限」**：任一字段行 ≤ **700 字符**（比现行 1,200 严一档，专治下一站/复测包这类超长行）。同时对全文设**黄线 11,000 字节**（比现行 12,902 严）。
- **守护二十二「排期池速览-详情不重复」**：速览表行正文 ≤ **160 字符**，细节只许落在详情段；同一编号在速览与详情两处的**实测读数**不得重复出现第二遍。

### 规则二 · 棘轮改成"默认面 + 收窄"，不再单向放宽

现行 `status_set.py` 的 `MAX_FILE_BYTES` 是**唯一常量且只被 --set 撞红时改**。优化为：
- 常量下调到实测瘦身后的 ×1.10（留 10% 余量，不留 50%），并在注释里写明**下调须同批完成瘦身**；
- 任何放宽必须写 `--ratchet-note` 理由进 STATUS（**人工审**，不能静默改常量）。

### 规则三 · 沉档有唯一去处（避免"删了找不回"）

三件瘦身出的历史读数**不许就地删**，统一去处：
- STATUS 的历史读数 → `docs/交接文档.md` 文末变更日志（已在守护十二滚动窗口内）；
- INDEX 的归档件流水 → 该件自身的归档正文已在 `docs/archive/`，**INDEX 行压到"路径＋一句话能查"即可**；
- 排期池的详情 → 保持详情段（**速览只留一行结论＋指针**，不删信息）。

## 4 · 门禁（机械可验）

1. `python tools/doclint.py` → **零死链 + 守护全绿（含新增二十/二十一/二十二）**。
2. `python tools/status_set.py --check` → 体量三检绿。
3. **变异双刀**（每道新闸各一）：守护二十 → 把某归档件行灌到 300 字符，红其位、复原；守护二十一 → 把某 STATUS 字段行灌到 800 字符，红其位、复原；守护二十二 → 在速览表行里灌重复读数，红其位、复原。
4. **行数闸不动**：INDEX 行数预算维持 130（存量 118 行在瘦身后自然回落，**不借机改预算**＝棘轮纪律）。
