## 2. 子批 A 规格与落地（已完成）

### I02 列表搜索 · I04 排序与状态/金额筛选（纯函数层）

新增 `lib/features/items/domain/items_filter.dart`：

- **关键词**（I02）：`normalizeItemKeyword`（trim＋小写）＋ `itemHaystack`（名称／分类／状态三处拼串）。**I03 加列后只改 `itemHaystack` 一处**，搜索框与判定不必各改一遍。
- **状态筛选**：四档（使用中／闲置／已回收／已报废），判据 `status.startsWith(档)`——「已回收」自动覆盖「已回收(抵扣留用)」与「已回收(转出)」两子态，与 hero 计数同口径。
- **金额段**：按**成本池**（`poolOf`＝购入价＋二次付费−回收）分四档，左开右闭：不限／≤1000／(1000,5000]／>5000。不按购入价——模块的核心指标是池，用价分档会把二次付费算丢。
- **排序五档**：日均↓（默认，＝列表原有顺序，切过去不跳变）／成本池↓／购入价↓／购入时间↓／名称 A→Z。日均可能为 null（冻结条目），**null 一律沉底**，否则「没算出来的」会浮到榜首被当成最贵。
- **稳定排序**：Dart `List.sort` 不稳定，同值项会乱序跳动；用原索引做第二关键字，保证同值恒按原顺序。
- 分类 seg 仍在 `itemsByCat`（既有口径不动），本层负责它之后的三道闸＋排序；`filterItems` 返回新列表，不改入参。

### I01 照片落地·地基部分

`lib/core/media/media_usage_scanner.dart` 的 `_refColumns` 追加 `('item_profiles', 'photo')`。

**为什么必须先做**：照片落 `note_images/` 后，清理扫描按「引用列里出现过该 basename」判在档；漏登记这一列，用户拍的照片会被当孤儿**静默删掉**（health 批3.5 与影音游批6 都踩过，注释原话「存了就等于没存」）。配常驻用例 `test/media_usage_scanner_test.dart`「物品照片列也算引用」。

## 4. 验收判据

1. 关键词命中名称／分类／状态，大小写不敏感，空词＝不限。
2. 状态多选取并集；「已回收」覆盖两子态。
3. 价位按成本池分档，边界 1000／5000 归属不重不漏；池≠价时分对档。
4. 五档排序顺序正确；日均 null 沉底；同值保持原序；不改入参。
5. 物品照片在档不被孤儿扫描误删（常驻用例）。
6. `flutter analyze` 零新增 error；批内一文件一波；doclint 零红。
