## 前置 A · 适用范围与需求冲突裁决（开工前必读）

### A.0 适用范围澄清（防止代码模型自造）

本模块＝**系统桌面入口与寻址**（快捷方式／小组件／URL Scheme）＋ **App 内配套的设置二级页**。以下内容**不属于本模块**，代码模型**一律不得实现**：

| 疑似需求 | 归属 | 处置 |
|---|---|---|
| 通知渠道/时段/免打扰改造 | 提醒通知模块（既有） | **不适用**；批 4 只在既有 `reminders`/`daily` 渠道上**加动作按钮** |
| 超级岛（HyperOS 3 Super Island） | — | **明确不做**（须小米评审白名单＋图片 HTTPS 外链，与「零网络·纯本地」红线冲突） |
| 负一屏接入 | — | **明确不做**（须小米平台审核；产品令「不走官方审核」） |
| 小组件内嵌键盘/滚轮输入 | — | **明确不做**（RemoteViews 禁文字输入、禁滑动，硬边界） |
| iOS／平板／桌面端小组件 | — | **不适用**（本期只做 Android 手机） |
| AI 智能归类、图标角标、锁屏快捷 | AI 增强／未立项 | **不适用**；不在本档范围 |

> **红线**：代码模型若在本模块实现「超级岛／负一屏／小组件内输入／iOS 侧／静态 shortcuts.xml」，视为需求越界，判不合格。

| C11 | 快捷方式/小组件图标 | 项目禁 emoji | 一律**线性 SVG 转 PNG**（stroke 1.8 同族），禁 emoji、禁彩块 |

| C13 | 深链开关是否重开 | R3-1 已关 embedding 深链 | **保持关闭**；`lh://` 走 MainActivity 自解析，**与 embedding 深链无关**（防 `content://` 灌进 go_router） |
| C14 | 设置页归属分组 | 考察件「与数据与同步/提醒通知/AI 增强同级」 | **归「外观与交互」组**（与「外观」「底部导航栏自定义」同组——皆是入口/交互配置），原型 `p-profile` 第 03 组 |
| **C15**<br>（V3·C37） | 四路入口 Intent 形态是否统一 | 快捷方式/铺桌面/小组件 PendingIntent 各写各的 | **四路（长按菜单／铺桌面／小组件点击／外部 `lh://`）一律 `Intent(ACTION_VIEW, Uri.parse(lh://<ns>/<key>))` ＋ `setClass(this, MainActivity)` ＋ `FLAG_ACTIVITY_NEW_TASK\|FLAG_ACTIVITY_SINGLE_TOP`**。理由：Manifest 既有 5 组 `content/file` 打开方式 intent-filter，**只 setAction 不 setData 会误匹配**（C13 深链已关，正是靠 data 精确匹配才不被抢走）。**禁**只 `setAction(ACTION_VIEW)` 不 `setData`；**禁**新造自定义 action 承载功能型动作（悬浮窗既有 `ACTION_PILL_*` 除外·C17 豁免②） |
| **C16**<br>（V3·C38） | 「URL Scheme 为核心」的准确表述 | 「所有入口都走 `lh://`」 | **精确到层**：`lh://` 寻址契约（L1）是**唯一真源**，**分发（L2）各随平台**（C17）。本模块是 **L1 的实现方**（URI 形态＋ns 常量表＋白名单解析＋`takeLaunchRoute` 投递），**不承担**统一各路 Intent 的职责——那是误解 |
| **C17**<br>（V3·C39） | 要不要给所有分发路定「统一 action」KPI | 想统一架构 | **不设**。L2 各自选 action，**明确豁免三类**：① **NFC**（平台派发 `ACTION_NDEF_DISCOVERED`，**App 不可选**，其模块 C39 判越界条文即「把 NFC 改成 `ACTION_VIEW`」）；② 不开 App 的后台动作（service／自定义 action，含既有 `ACTION_PILL_END/NOTE`，**一字不改**）；③ 既有 `content`/`file` 打开方式（属 EPUB/MD 通路，**禁并入 `lh` 命名空间**）。**验收反向条文**：代码模型若把上述任一路强行改造成统一 `ACTION_VIEW` ⇒ 判越界 |
| **C18**<br>（V3·C40） | `lh://` 带参动作的等级 | `lh://ledger/add?amount=38.5` 免确认直接记账 | **三级分级**：**导航类**（`nav.*`）可带参直接执行；**写入类**（记账／打卡／计时起停）**只预填、提交须 App 内确认**；**删除类一律不进 URL**。⚠ 本档批 1 白名单七个动作中 `quick.ledger` 属写入类 ⇒ 带 `amount` 落地后**必须停在预填态**，不得自动提交（现 F1-1 原文只说「预填」，此处补死） |
| **C19**<br>（V3·C38 派生） | 新增功能往哪加 | 每来一个新入口就手写一段解析分支 | **新功能一律「加 ns」**，ns 取自**一张常量表**（与动作表同源生成，**禁散落字面量**）；**禁**在既有 ns 下塞新语义。`nfc` ns 由 NFC 模块引入（`lh://nfc/<cardId>`），本模块只提供解析与投递通道 |

### A.2 缺失边界补齐表（原文未定义，本档冻结）

| # | 边界场景 | **冻结行为** |
|---|---|---|
| B1 | 动态快捷方式为空（App 从未被打开） | 首启进入主页时以**默认 4 枚**初始化；菜单空态不做专门 UI |
| B2 | `requestPinShortcut` 不支持（部分启动器） | `isRequestPinShortcutSupported` 失败 → 该行按钮禁用＋一行提示「当前桌面不支持自动添加，请长按图标手动拖出」 |
| B3 | 系统桌面无法被原型表达 | 桌面侧（快捷菜单/小组件外观）以**本档 §4/§5 规格＋样张**为准，不进 HTML 原型；**App 内设置页必须进原型** |
| B4 | `lh://` 未知/非法路由 | 复用现成 `unknownRouteFallback`（toast「页面不存在，已回到首页」＋回 `/`） |
| B5 | scheme 参数非法（金额/日期非数） | **忽略该参数**、仍落地目标屏（不做 tryParse 兜底、不弹错） |
| B6 | 小组件首次添加时无快照 | widget 显示占位（`--`）＋一行「打开应用后自动同步」 |
| B7 | 隐藏金额开关切换 | 通知 widget 重绘并切换金额位文案（`••••` ↔ 数值） |
| B8 | 可交互 widget 后台唤醒（无 UI） | 后台 isolate **只跑入库＋回写快照**，不初始化 UI 依赖；失败静默（保留上次快照） |
| B9 | 系统深浅色切换 | widget 重绘对应色档（见 C6）；与 7 主题无关 |
| B10 | 卸载重装 | 固定快捷方式随卸载消失（系统行为），文档声明不补偿 |
| B11 | `lh://` 被他 App 抢注 | 不探测；按 Android 标准多候选 chooser；本 App 仍是候选之一 |
| B12 | 目标模块未开放/已下架 | 动作表**只列已开放模块**；下架模块从编译期常量表摘除 |
| B13 | 小组件刷新失败 | 保留上次成功快照，不显示错误 |
| B14 | 通知权限未授予（批4 动作按钮） | 降级为普通通知（无按钮）＋设置页一行引导 |
| **B15**<br>（V3·B37） | 冷启动时 `takeLaunchRoute` 尚未就绪 | 冷启动意图**先入队**，`app.dart` 组合根**首帧完成后**才消费并 `go(目标路由)`；**单次消费**（读后清空，防重放）。⚠ **禁丢弃**：意图若在首帧前被读掉即永久丢失＝用户点了图标没反应。已就绪的热启动（singleTop）路径**一字不改** |
| **B16**<br>（V3·C36 派生） | 同一目标被多路同时送达（如贴卡紧接桌面点击） | 由 L3 单一消费端负责收口：解析/校验/去抖/回执**只有一份实现**（各路不得各自去重）。本模块 `takeLaunchRoute` 只保证「一次意图→一次路由」，**跨路去重不在此判**（NFC 侧 3 秒窗口是其自身边界） |
| **B17**<br>（V3·C19 派生） | `lh://` 的 ns 未登记在常量表 | **只放行常量表内的 ns**；未登记 ns 一律按未知 path 走 `unknownRouteFallback`（B4）。**禁**在解析代码里 `when` 到未登记 ns（新增 ns 走 C19 流程） |

### A.3 `lh://` 寻址契约（L1 唯一真源 · V3 新增 · C16/C17/C18）

> **来源**：产品 2026-10-15 提议「以 URL Scheme 为核心，NFC／快捷方式等皆为其外围功能」（见 NFC 冻结档 §前置 A.3）。
> **本档口径**：**本模块＝L1 寻址层的实现方**，不是「所有分发路的统一者」。URI 形态、ns 常量表、白名单解析、`takeLaunchRoute` 投递由本档负责；各路用什么 Intent 派发**各随平台语义**（C17）。
> **一句话判据**：**凡「进 App 的路」由平台决定 ⇒ 不可统一；凡「进 App 之后做什么」由本项目决定 ⇒ 必须统一。**

```
L0  动作表（desktop_actions.dart）        ← 唯一真源：动作 id ⇄ 名称 ⇄ 路由 ⇄ lh:// path
     │  全模块复用，禁各写一份
     └─→ L1 寻址契约：lh://<ns>/<key>[/<arg>…]   ★ 本模块实现这一层
            ns = inbox|todo|journal|ledger|items|habit|today|nfc|…（取自一张常量表·C19）
     │
L2  分发（各路自选，允许不同 action）            ← 不强求统一（C17）
     长按菜单／铺桌面／小组件 → ACTION_VIEW + lh://（本模块自建，C15）
     URL Scheme             → ACTION_VIEW + lh://（系统派发，本模块只解析）
     NFC 贴卡               → ACTION_NDEF_DISCOVERED（data 仍是 lh:// URI）  ← 平台定死，豁免①
     悬浮窗按钮             → 自定义 action + extra（既有 ACTION_PILL_*，不动）← 豁免②
     既有 content/file 打开  → 各自 filter（属 EPUB/MD 通路）                  ← 豁免③
     App 内 FAB             → 直接调 Dart 函数（零序列化）
     全部汇聚 ↓
L3  Dart 消费：takeLaunchRoute 单次消费 → 同一份解析／校验／去抖／回执实现
```

- **收益**：L1 单一真源（行为不分叉）＋ L3 单一消费（校验／去抖／回执只有一份）＋ L2 各按平台语义自由（不跟平台打架）。
- **C18 带参三级分级**（本档只落地「写入类只预填」这一条，其余见 NFC 档）。
- **引用关系**：本节与 `docs/handoff/NFC卡片模块-冻结版开发方案-20261015.md` §前置 A.3 **同源同口径**；改一处必须同步另一处（doclint 守护）。

## 1. 模块目标

**一句话核心目标**：在**系统桌面**为 lifeHarness 建立「**一步直达**」的高频入口层——用户不打开 App、不翻主页，即可从图标长按、桌面小部件、或外部链接（二维码/NFC/自动化工具）**直接落到一次真实记录动作**。

**业务价值**：
1. **降低记录摩擦**：把「速记/待办/记一笔/打卡」从「开 App→找模块→点新增」压到「桌面点一次」，直击个人工具类 App 最高频的使用断点。
2. **补上被竞品忽略的系统层**：多数本地记录 App 只做应用内；桌面入口是**留存与习惯养成的杠杆**。
3. **首次建立统一寻址底座（`lh://`）**：一次投入，供给快捷方式/小组件/外部自动化三端复用，后续新增模块零成本接入。
4. **零云依赖、零新增网络面**：全部本地，契合项目隐私红线。

### 2.0 动作表（唯一来源，全模块复用）

| 动作 id | 名称 | 落地 | 对应路由 | Scheme（白名单内） | 带参等级（C18） |
|---|---|---|---|---|---|

| `quick.todo` | 记待办 | `/todo` ＋ `QuickAddEvent('todo')` | 既有 | `lh://todo/new` | 写入类·只预填 |
| `quick.journal` | 写日记 | `/journal/edit` | 既有 | `lh://journal/edit` | 写入类·只预填 |
| `quick.ledger` | 记一笔 | `/ledger/add` | 既有 | `lh://ledger/add` | 写入类·只预填 |
| `quick.items` | 记物品 | `/items` ＋ `QuickAddEvent('items')` | 既有 | `lh://items/new` | 写入类·只预填 |
| `quick.habit` | 今日打卡 | `/habits` | 既有 | `lh://habit/check` | 写入类·只预填 |
| `nav.today` | 回今天页 | `/` | 既有 | `lh://today` | 导航类·可直接 |

**默认 4 枚**＝`quick.inbox` / `quick.todo` / `quick.ledger` / `quick.habit`。
**实现红线**：动作表＝**唯一入口定义**，快捷方式/小组件/URL 三端**都只能引用它**，禁止各写一份跳转逻辑（防行为分叉）。

**URI 构造规则（V3·C15/C16）**：本表 Scheme 列是**字符串拼接的唯一来源**；构造 `lh://` URI 时一律取该列原值，**禁**在别处手写字面量。
**Intent 构造规则（V3·C15）**：凡本模块**自己**派发的入口（`setDynamicShortcuts` 的 `Intent`／`requestPinShortcut` 的 `Intent`／小组件 `PendingIntent`）一律：

```
Intent(Intent.ACTION_VIEW, Uri.parse(<Scheme 列原值>))
    .setClass(this, MainActivity::class.java)
    .addFlags(FLAG_ACTIVITY_NEW_TASK or FLAG_ACTIVITY_SINGLE_TOP)
```

- ⚠ **禁只 `setAction` 不 `setData`**：Manifest 既有 5 组 `content/file` 打开方式 intent-filter，只带 action 的 Intent 会**误匹配**到它们。
- ⚠ **禁**新造自定义 action 承载功能型动作（C17 豁免②仅保留既有 `ACTION_PILL_END/NOTE`）。
- **验收**：四路（长按菜单／铺桌面／小组件点击／外部链接）产生的导航栈**逐字一致**——同一动作从哪进都得到同一条栈。

### 3.2 跳转关系

```
「我的」p-profile
  └─[点击行]→ /settings/desktop（p-sub-desktop）
```

- 设置页为**全屏栈页**（同 `p-sub-notify`/`p-sub-appearance`），顶部自带返回，**不占底栏**。

### 3.3 返回与状态保持

| 场景 | 行为 |
|---|---|
| 设置页返回 | `pop` 回「我的」；**改动已即时落库**，返回不丢 |
| 从 `lh://` 冷启动 | 组合根 `go(动作路由)`；目标页**无返回栈**（回 `/`），与「打开方式」文件入队语义一致 |
| 从 `lh://` 热启动（singleTop） | 复用现有实例，`go(动作路由)` 替换栈顶；不堆栈 |
| 后台被 widget 唤醒后回到前台 | 保持被唤醒前的导航状态（widget 动作是独立入库，不改导航） |

## 4. 交互规范

### 4.1 长按图标菜单（4 枚）

- **8 行**：桌面侧菜单结构（图标＋短标签），标签≤6 字（速记/待办/记一笔/打卡）。
- **选中**：点击任一 → 走动作表对应路由；**冷启动直达、无中间页**。Intent 形态按 §2.0 Intent 构造规则（V3·C15）。
- **上限**：系统硬限 4；设置页勾选超过 4 项时，第 5 项 checkbox **置灰不可点**＋一行提示「长按菜单最多 4 个，更多入口请『铺到桌面』」。
- **更新时机**：设置页每次改动 → 立即 `setDynamicShortcuts`；无需重启。
- **V3 补（C15）**：重建时每枚 `Intent` 必须带 `setData(lh://…)`；**禁**只设 action/extras——否则会落到既有 `content/file` 打开方式 filter 上。

### 4.2 设置页「桌面与快捷方式」交互

| 区块 | 交互 |
|---|---|
| **① 长按菜单** | 7 个动作行（checkbox）；已选 N/4 计数；点行切换选中；上限拦截见 4.1 |
| **② 铺到桌面** | 每个动作一行，右侧按钮「铺到桌面」；已铺→「已铺」（不再可点）；不支持→禁用＋提示（B2）；一次允许铺多枚（不限量）。⚠ `requestPinShortcut` 的 `Intent` 同样按 §2.0 构造规则（C15） |
| **③ 小组件** | 「添加到桌面」按钮 → 调起系统小部件中心本应用页；下方两个开关：`今日概览读数`、`快捷记录入口`；再下方一行 `隐藏金额联动`（默认开，灰字说明） |
| 行卡样式 | 与「底部导航栏自定义」「外观」**同款行卡**（`card`＋`set-ic`），**禁新造控件** |

### 4.3 URL Scheme 解析链路（`lh://`）

1. **Manifest**：`MainActivity` 增 `intent-filter`（`VIEW`＋`DEFAULT`＋`BROWSABLE`，`data scheme="lh"`）。
2. **原生解析**（`handle(intent)` 新增分支）：按 **URI 分解口径**取**归一化寻址段** —— `lh://<ns>/<key>` 中 **`ns` 落在 authority(host)**、只有 `key` 落在 path，故 **段＝`uri.host + uri.path`**（如 `ledger` ＋ `/add`）；再带 `uri.queryParameters` → 先校验 **ns 在常量表内**（B17）→ 查**白名单表**（段 → 动作 id）→ 合成 `Map<String,String>{action, args...}` 入队（与既有 `lh/intents` 同风格）。
   > **⚠ 2026-10-15 热修（本档原文有误，已改）**：原文写「取 `uri.path`（如 `ledger/add`）」——**这是错的**：`Uri.parse('lh://ledger/add').path` 求值为 **`/add`**，ns 整段被丢掉，ns 校验必失败、意图被静默丢弃，真机表现为**长按菜单／铺桌面／小组件／外部 `lh://` 四路点击全部落回首页**。Dart 侧口径真源＝`desktop_actions.launchSegOf`（依 RFC 3986，`lh://` 后首段即 authority），原生按同口径拼 `host + path`；两侧由 `desktop_intent_shape_test` 各钉一头（Dart 钉口径、原生钉实现）。
3. **投递 Dart**：新方法频道 `lh/launch`，方法 `takeLaunchRoute`，**单次消费**（读后清空，防重放）。
4. **组合根消费**（`app.dart`）：**首帧完成后**才 `takeLaunchRoute` → 命中动作 id → **按目标路由类型选导航语义**：**壳内路由**（注册在 `<模块>ShellRoutes()`，等价点底栏 tab）用 `go(路由)`；**全屏栈路由**（注册在 `<模块>PageRoutes()`，如 `/journal/edit`、`/ledger/add`）用 `push(路由)`。带参动作按 §2.0 注入（如 `quick.ledger` 带 `amount/cat` 时预填，**且必须停在预填态、提交须 App 内确认**·C18）。
   > **⚠ 2026-10-15 热修（本档原文只写 `go`，不完整）**：全屏栈路由若也走 `go`，会连栈底那条壳页一起换掉 ⇒ 页内 `Navigator.pop()`（如日记编辑页 `PopScope(canPop:false)` 保存后强退）**无处可去** ⇒ 真机表现为**返回黑屏且退不出去**。故动作表新增 `fullScreen` 列（取值**不得手写猜**，由 `desktop_actions_test` 与真实路由表 `*ShellRoutes()`/`*PageRoutes()` 交叉核对），消费端据此分派。守卫＝`test/desktop_launch_app_test.dart`（钉「壳页仍在栈底」＋「返回落回今天页」）。
5. **兜底**：未知 `path` / 非法参数 → 忽略该参数或落 `unknownRouteFallback`（B4/B5）。

**白名单（批 1 冻结全集，一字不多）**：`inbox/new`、`todo/new`、`journal/edit`、`ledger/add`、`items/new`、`habit/check`、`today`。
**白名单扩容（V3·C19）**：新功能**只允许「加 ns」**，由所属模块在本表外**追加一条并回写本档**；ns 与 path 均取自常量表，**禁散落字面量**。
- 已由 NFC 模块引入的形态：**`nfc/<cardId>`**（如 `lh://nfc/aB3xY9zQ1m2K`）。本模块只负责**解析出 cardId 并原样投给 Dart**，**不解释其业务含义**（含义归 NFC 模块）；`cardId` 格式校验由投递方做（B35·NFC 档），本模块**只判 ns 合法**。
- 已由小组件模块引入的**系统寻址段**（2026-10-18·`kSystemLaunchPaths`）：**`settings/desktop`**（→ 设置 › 桌面与快捷方式）。只给 **App 自己的界面部件**指路（打卡枚失效三态的「点此设置」），**不是用户动作**、**不进动作表**——动作表喂三张用户可勾选清单（设置页勾选／长按菜单／小组件目标），塞进去会各多一项既不能勾也不能铺的怪条目。**段即 id**（含斜杠，天然不与动作 id 撞车），消费端 `LaunchRoute` 查 `kSystemLaunchPaths` 得路由、按全屏栈 `push`。

**⚠ 四路 Intent 形态统一（V3·C37／本档 C15）**
长按菜单（`setDynamicShortcuts`）／铺桌面（`requestPinShortcut`）／小组件（`PendingIntent`）三路**自建 Intent** 一律：

```
Intent(Intent.ACTION_VIEW, Uri.parse(lh://<ns>/<key>))
    .setClass(this, MainActivity::class.java)
    .addFlags(FLAG_ACTIVITY_NEW_TASK or FLAG_ACTIVITY_SINGLE_TOP)
```

- **禁只 `setAction` 不 `setData`**：Manifest 既有 5 组 `content/file` 打开方式 filter，只带 action 的 Intent 会误匹配到它们（这正是 C13 关闭 embedding 深链的原因）。
- **禁**新造自定义 action 承载功能型动作；既有 `ACTION_PILL_END/NOTE`（悬浮窗，6133/6135 热修链路）**一字不改**（C17 豁免②）。
- **本模块不承担统一 NFC 分发**：`ACTION_NDEF_DISCOVERED` 由 Android 派发，**App 不可选**（C17 豁免①）；把 NFC 强行改成 `ACTION_VIEW` 判越界。

**⚠ 冷启动不丢弃（V3·B37／本档 B15）**
- 冷启动：意图**先入队**（原生侧持有），`app.dart` 组合根**首帧完成后**才消费 → `go(目标路由)`。
- **验收**：杀掉进程 → 点桌面图标 → 直达目标屏；连点两次也不重放（单次消费）。**首帧前把队列读空＝永久丢失，判不合格。**
- 取法先例：根 `NavigatorState.context` / `navigatorKey.currentContext`，**首帧后**取（既有先例 `lib/shared/linkage/sys_pill_sync.dart:102`「走根 Navigator」）。
- 热启动（singleTop）路径**一字不改**。

**安全**：不反射任意路径；`amount` 非数即忽略；金额等敏感参数**不写日志**；`MainActivity` 已 `launchMode=singleTop`。

### 4.4 小组件交互

- **点击区**：整个 widget 为单一点击区 → 跳对应屏（`PendingIntent` 走 `lh://`，统一寻址；Intent 形态按 §4.3 四路统一条文·C15）。
- **可交互 widget（批 3）**：读数区内的「勾/加」小按钮＝独立 `PendingIntent` → 后台 isolate 执行 → 回写快照 → 重绘；**无二次确认**（打卡可撤销在 App 内）。⚠ 后台 isolate 不经 `lh://` 派发（不开 App 路径·C17 豁免②）。
- **刷新**：App 存活时主动刷新；系统侧调频导致的延迟**不视为缺陷**（C4）。
- **空数据**：占位 `--` ＋「打开应用后自动同步」（B6）。

### 4.5 动画

- 设置页勾选：checkbox 200ms ease-out；行按下 `active:scale-[.98]`。
- 计数变化（N/4）：数字淡入切换，无位移动画。
- 「已铺」态：按钮文字淡切，无弹跳。
- **widget 侧无动画**（RemoteViews 限制）。

### 4.6 加载与反馈

| 场景 | 反馈 |
|---|---|
| 勾选/开关变更 | 即时生效，无 loading（本地写） |
| 铺到桌面 | 系统弹窗自解释；成功/失败由系统反馈，应用侧不重复 toast |
| 调起小部件中心 | 系统 UI；失败（无桌面）→ `AppToast`「当前桌面不支持」 |
| `lh://` 冷启动 | 直达目标屏；无中转 loading |
| 未知链接 | `AppToast`「页面不存在，已回到首页」＋回 `/` |

### 4.7 异常/边界场景

严格按 §前置 A.2（B1~B14）执行；开发期新增场景须回本档冻结，**不得自行发挥**。

### 4.8 无障碍（a11y）

- 设置页所有交互控件加 `Semantics(button:true,label:"…")`，label 含**动作名＋当前态**（如「速记，已选」）。
- 触点 ≥44dp；字体放大不截断（行高自适应）。
- widget 提供 `contentDescription`（2×2 概览＝「今日待办 N 项，习惯 M 项已完成」）。
- 对比度：正文/背景 ≥4.5:1（widget 深色色档同样满足）。

## 6. 开发约束

### 6.1 Flutter 实现限制（架构红线）

- **目录**：设置页＝`lib/features/settings/presentation/desktop_settings_page.dart`（新）；偏好键＝`lib/core/settings/settings_repository.dart`（**仅加 `desktop.*` 键，不改既有键**）；动作表＝`lib/core/platform/desktop_actions.dart`（新，编译期常量表）。
- **路由**：`lib/features/settings/presentation/settings_routes.dart` **仅加一行** `/settings/desktop`；**不动**其他路由。
- **禁止 feature 直连**：设置页与各模块**互不直连 import**，跳转只用**动作表**里的 `path` 字符串＋既有事件总线（守 R1）。
- **禁新造弹层容器/确认框**（复用 §5.5）。
- **零新增网络面**：不得引入任何联网能力的插件。
- **`lh://` 解析只在原生**：Dart 侧**只消费已解析的动作 id**，不接触原始 URI（防未知路由炸 `GoException`，与 R3-1 一致）。

### 6.2 原生（`android/**`）实现限制

- **Manifest 改动面**（唯一）：`MainActivity` 加 `scheme=lh` 的 intent-filter；批 2 加 `AppWidgetProvider` 的 `receiver`；**不动**既有 `content/file/SEND` 三个 intent-filter（EPUB 通路一字不改）；**不重开** `flutter_deeplinking_enabled`。
- **`MainActivity.kt` 改动面**：`handle()` **仅加 `lh://` 分支**＋新频道 `lh/launch`；既有 `lh/intents` 一字不改；**`ACTION_PILL_END/NOTE` 一字不改**（C17 豁免②，6133/6135 热修链路）。
  - ⚠ **V3 追加（C15）**：三路自建 Intent（`setDynamicShortcuts`／`requestPinShortcut`／widget `PendingIntent`）必须 `setData(Uri.parse(lh://…))`；**只 setAction 不 setData 会误匹配既有 content/file filter**。
  - ⚠ **V3 追加（B15）**：`lh://nfc/*` 与 `ACTION_VIEW` **共用同一解析分支**（C36·NFC 档）；冷启动意图**入队不丢弃**，首帧后单次消费。
  - **L1 出口唯一**：本模块是 `lh://` 解析的唯一实现方；其他模块（当前＝NFC）**禁**各自再写一套 URI 解析（守 R1：feature 互不直连，跨模块唯一出口）。
- **Kotlin 收口**：动 `android/**` 的批必须跑 `tools/kotlin_check.sh`（`flutter analyze` 盖不住 Kotlin）。
- **widget**：`AppWidgetProvider` ＋ `RemoteViews` 布局 XML（`res/layout/`），色档走 `values/`＋`values-night/`；**读数只读 SharedPreferences**（C5）。
- **`home_widget`**：桥＝`saveWidgetData`/`updateWidget`/`registerInteractivityCallback`（批 3）；插件版本以 `pubspec.yaml` 实装为准，**不引第二套 widget 桥**。
- **图标**：线性 SVG → PNG 落 `res/drawable-*/`；**禁 emoji、禁彩块**。

### 6.3 性能要求（秒开 / 缓存 / 功耗）

| 项 | 规格 |
|---|---|
| 冷启动 | 全项目口径 ≤2s；`lh://` 直达不额外加时（解析在原生、一跳到 Dart） |
| 设置页 | 秒开；偏好读取走内存控制器，**不阻塞首帧** |
| widget 刷新 | App 存活时**按需刷新**（动作完成后触发），**不轮询、不定时器常驻** |
| widget 读数 | 只读 SharedPreferences 快照（O(1)），**无 DB 查询** |
| 功耗 | 无常驻定时器；后台 isolate（批3）**执行完即退**；无动画空转 |
| 包体 | 新增原生布局/图标/`home_widget` 增量小（估 <300KB）；**不动 DB** |
