## 一、三条桌面通道的能力边界（先划清能做什么、不能做什么）

三件事彼此不是替代关系，是「同一批入口能力」的三层载体：**URL Scheme 是底座（寻址），快捷方式与小组件是它的两个消费端**。

| 通道 | 平台机制 | 能做 | 硬边界 / 不能做 | 门槛 |
|---|---|---|---|---|
| **A. 桌面快捷方式** | 静态 `res/xml/shortcuts.xml`（打包即存在）＋ 动态 `ShortcutManager`（运行时可改）＋ 固定快捷方式 `requestPinShortcut`（加桌面·用户授权） | 长按图标出快捷菜单（直达某屏/带参数）；固定快捷方式可铺多枚、不限数量 | **长按菜单只显示 4 枚**（静态＋动态合计）；固定快捷方式应用**不可删、只能禁用**；带参数能力靠 intent data | 低（纯 `android/**`，零新依赖） |
| **B. 桌面小组件 (AppWidget)** | `AppWidgetProvider` ＋ `RemoteViews`（Android 原生）／`home_widget`（Flutter 桥） | 桌面/负一屏常驻读数卡；点击跳应用内指定页；**可做成可交互**（点一下打卡/记一笔，后台 isolate 跑 Dart） | RemoteViews 只支持有限控件：**禁止滑动、禁止文字输入**（⇒「就地内嵌键盘/滚轮」在本项目铁律下**落不了地**，记账评估件已判死）；布局须用原生 XML 写，不能直接用 Flutter 渲染（可 `renderFlutterWidget` 出静态图） | 中（新 `android/**` 组件＋清单 receivers＋数据桥） |
| **C. URL Scheme / Deep Link** | 自定义 scheme intent-filter ＋ `MainActivity` 拦截解析 | 统一寻址：外部 App 跳转、二维码/NFC/浏览器链接、以及 A/B 两条通道内部一律走它 | 项目**当前已显式关闭** Flutter embedding 深链（`flutter_deeplinking_enabled=false`，R3-1，为防 open-with 的 `content://` 被当初始路由灌进 go_router）；自定义 scheme 须**另写白名单解析**，不能复用 embedding 那条 | 低-中（清单 1 个 intent-filter＋MainActivity 解析＋Dart 侧路由白名单） |

**关键判断**：三件事合起来才成立——只做快捷方式则小组件无寻址、只做小组件则无法被外部触发、只做 Scheme 则用户看不到入口。**底座是 Scheme，入口是快捷方式/小组件**。

## 三、小米（HyperOS/MIUI）专属事实——「适配」的核心

### 3.1 小部件

- **归类**：标准第三方 AppWidget 在小米桌面归入**「安卓小部件」**分类（桌面双指捏合 → 小部件 → 搜索 → 安卓小部件）。想进**「米家原生」**那一列（如 Spotify 那样）**不是自助的**——社区实证＝由小米服务端 allowlist 决定，须走官方合作/审核（发邮件 `miui-widget@xiaomi.com`，官方称 10 个工作日内联系）。
- **官方设计规范（须逐条遵守，否则审核不过）**：名称格式「应用名·小部件名」、2~10 汉字；介绍 ≤22 中文字符；尺寸手机端 **2×2 / 4×2 / 4×4**（平板另加 4×2）；**必须支持深色模式**、**必须支持无障碍（TalkBack／大字体不截断）**、跟随系统多语言；预览图直角、系统裁 55px 圆角、内容留 ≥42px 安全区；日期时间用原生 `AnalogClock`。
- **官方开放的能力（正好服务于「手动设置」）**：① 支持应用**主动查询用户是否已添加某小部件**；② 支持应用**调起小部件中心本应用详情页**，一键引导用户添加；③ 支持**长按小部件 →「编辑小部件」跳转到开发者指定页**；④ 支持给不同状态设优先级。
- **禁止**：小部件内上下/左右滑动、文字输入。
- **刷新**：系统在小部件展现时调进程刷新，App 存活时也可主动刷新；系统会按类别/状态智能调频。

### 3.2 超级岛（HyperOS 3 Super Island）

- 机制：`Notification` 的 extras 塞 `miui.focus.param`（JSON）＋ `miui.focus.actions` 自定义按钮，走「岛通知」。
- **门槛高**：须注册小米开发者、创建并上架 App、提交**「上岛场景预审」**、配指纹证书、白名单联调、正式审核通过后灰度放量（上线后 7~15 天到 100%）；**仅 OS3 支持**（OS2 只有焦点通知）。
- **判定**：对本项目（个人工具类、无上架运营计划）**性价比极低，不列入首批**；仅登记为「若将来做计时/行程类实时状态可回头评估」。注意：本项目「零网络 / 纯本地」与超级岛的图片须 HTTPS 外链要求天然冲突。

### 3.3 负一屏

- 基于小部件，可**自主接入**（开发小部件→小米小部件平台上传审核→用户自行添加）或走非标合作。定位＝「信息获取 / 一键直达」。
- 判定：与 3.1 同一套 widget 组件，**做了小部件即顺带可上负一屏**（多一道上传审核），不额外增加开发量。

### 3.4 快捷方式

- **上限：长按菜单只显示 4 枚**（静态＋动态合计；多数启动器如此）。⇒ 菜单里的 4 枚必须精选（建议＝速记/待办/记一笔/打卡这类最高频的）。
- **固定快捷方式（铺桌面）不受此限**：这正是「让用户手动挑」的官方出路——4 枚菜单做默认，其余交给用户在设置页自选并 `requestPinShortcut` 铺到桌面。

## 四、「手动设置」怎么做（三档，均可行，从轻到重）

项目已有两组同族先例（底部导航可配置 `NavModule` 开关上限 5、首页卡片可编排 `homeCardOrder`），**这三档就是同一份用户偏好的三种出口**：

- **档 A · 应用内设置页（推荐首选）**：新增「我的 › 桌面与快捷方式」二级页（与「数据与同步/提醒通知/AI 增强」同级）。用户勾选：① 哪 4 个动作进长按菜单（动态快捷方式按用户选择 push）；② 「把 X 铺到桌面」（逐条 `requestPinShortcut`，含 `isRequestPinShortcutSupported` 探测降级）；③ 小组件读数口径开关。零原生 UI，全在 Flutter 侧，复用现有设置页形态与持久化。
- **档 B · 小组件自带配置 Activity（`android:configure`）**：用户把小组件拖到桌面时弹出配置页，选「这块显示什么」（如 2×2 显示今日待办还是本月支出）。**与档 A 用同一份偏好**，避免两套设置。
- **档 C · 长按「编辑小部件」跳指定页**：小米官方能力，长按桌面小部件 →「编辑」→ 打开应用内档 A/D 的配置页。**是 MIUI 上体验最顺的入口**，但依赖 3.1 的官方能力（标准 AppWidget 亦可通过 `android:configure` 达到近似效果）。

**判定**：档 A 必做且最轻；档 B 建议随首批小部件一起做；档 C 是 A 的原生入口化，做 A 后成本很低。

## 五、URL Scheme 方案（把三条通道串起来）

- **命名建议**：`lh://`（短、好敲、与既有 `lh/intents`、`lh/saf` 通道前缀同族）。
- **架构（务必不碰 embedding 深链）**：
  1. 清单给 `MainActivity` 加一个自定 scheme 的 `intent-filter`（VIEW + DEFAULT + BROWSABLE，`scheme=lh`）；
  2. `MainActivity.handle(intent)` 里**新增分支**解析 `lh://`，把 `path + query` 过**白名单表**映射成一条内部路由 id（**不把原始 data 交给 go_router**，正是 R3-1 掐掉那条以免未知路由炸 GoException）；
  3. 经一个新方法频道（沿用 `lh/intents` 风格，如 `takeLaunchRoute`）投给 Dart，`app.dart` 组合根消费 → `context.go/push(白名单路由)`；非法/未知 → 复用现成 `unknownRouteFallback`（回首页 + 一行提示）。
- **语法示例（白名单内）**：

  | 链接 | 落地 |
  |---|---|
  | `lh://inbox/new` | 收集箱并聚焦输入 |
  | `lh://todo/new?title=` | 待办新建横幅 |
  | `lh://ledger/add?amount=12&cat=food` | 记一笔预填 |
  | `lh://habit/check?id=` | 习惯打卡 |
  | `lh://journal/edit` | 写日记 |
  | `lh://today` | 回今天页（小组件点击默认落地） |

- **用途**：① 快捷方式/小组件的 `PendingIntent` **统一走它**（一处寻址，两端复用）；② 外部自动化——Tasker / MacroDroid / 小米快捷指令类工具、浏览器链接、二维码、NFC 标签；③ 应用间「分享文本 → 收集箱」。
- **安全口径**：白名单映射（不反射任意路径）＋参数校验（金额/日期非法即忽略，不走 `tryParse` 兜底）＋不入日志的敏感参数（金额可脱敏）；`MainActivity` 已是 `launchMode=singleTop`（复用现实例，不会堆栈爆炸）。

## 六、还可以拓展的功能（超出四问的加分项）

1. **通知栏操作按钮**（已有通知基建 `reminders`/`daily` 渠道）：提醒通知直接带「记一笔 / 打卡 / 延后 10 分钟」动作，点通知不打开 App 就完成——**与小组件同源，成本最低**。
2. **动态快捷方式按「最近使用」生成**：菜单 4 枚里留 1 枚给「最近记的账分类/最近打卡的习惯」，随用随变。
3. **桌面图标角标**：MIUI 支持数字角标，复用现成 `navBadgeCount`（待办逾期数）——零新算法。
4. **锁屏快捷方式**：静态快捷方式带 `categories`，Android 7.1+ 可在锁屏放两枚（小米支持度需真机验）。
5. **应用内一键引导添加**：设置页「把小组件加到桌面」按钮 → 调起小米小部件中心本应用详情页（官方能力，见 3.1）。
6. **负一屏**：做了 widget 顺带可上（多一道审核）。
7. **分享菜单扩展**：现只收 epub/md（`lh/intents`）；可加「任意文本 SEND → 收集箱」，补上「别处复制一段话丢进 lifeHarness」。
8. **常驻计时通知**：计时器场景（时间/影音游）加前台常驻通知，顺带为将来「若上架则接超级岛」留位。

## 七、技术落地要点（Flutter 侧）

- **桥**：引入 `home_widget`（pub 上 0.9.x，活跃维护）＝`saveWidgetData`（写 SharedPreferences，widget 侧读）＋`updateWidget`（触发重绘）＋`registerInteractivityCallback`（`@pragma('vm:entry-point')` 后台回调）。**仍需原生写 RemoteViews 布局**，插件只解决「数据进出」。
- **widget 读数从哪来（关键决策）**：**推荐**＝App 存活时把「要展示的成品字符串/数字」写进 SharedPreferences，widget 只读这份快照（**避开 widget 进程直读 sqlite 与 sqflite 的并发锁风险**，也与本项目「测试禁真磁盘」的既有约束同族）。**不推荐首批**＝Kotlin 直读 sqlite。
- **可交互 widget**（点一下打卡）＝`HomeWidgetBackgroundIntent` + 新 Receiver，后台 isolate 跑 Dart；须在应用入口注册插件回调，并处理「无 UI 从后台被唤醒」的初始化裁剪（记账评估件已提示「内嵌键盘不可行，维持点进全屏」）。
- **构建/门禁**：动 `android/**` 的批收口链须跑 `tools/kotlin_check.sh`（`flutter analyze` 盖不住 Kotlin）；出包前跑 `tools/prebuild_check.js`；真机门必含「添加/点击/读数刷新」三条。UI 侧沿用禁 emoji、无教学文案、线性图标规范。
- **隐私**：widget 数据全本地、零网络，符合项目隐私红线（除用户自配同步/天气/豆瓣外零请求）。

## 八、风险与坑

- **MIUI/HyperOS 后台与自启限制**：widget 刷新可能被系统调频延迟（官方称「智能调频」），**读数「不够实时」是特性不是 bug**，真机门要按此判。
- **深色模式**：小米规范强制，本项目的 7 主题＋深色三档体系须映射到 widget 配色（RemoteViews 不能吃 Flutter 令牌，须另出原生色档）。
- **4 枚菜单上限**：直接决定「哪些动作露脸」，与档 A「手动设置」强绑定。
- **`requestPinShortcut` 支持度**：部分启动器不支持，须探测降级（提示手动长按拖出）。
- **超级岛/负一屏非自助**：需审核与合作，不能当交付承诺。
- **两套行为分叉风险**：桌面入口与 App 内入口若各写逻辑，行为会漂——必须共用第二节的统一动作 id。
- **隐藏金额等隐私开关**须联动 widget 读数（记账评估件已提醒）。
- **包体**：新增原生 widget 布局＋图标增量小、不动 DB，风险低。
