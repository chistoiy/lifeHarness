### U2（已拍板 2026-10-05 产品）宫格进模块的返回语义
- **拍板口径**：未编排进底栏五模块的功能（记账/物品/日子/目标/习惯/呵护/阅读/收集箱等）→ 宫格进入后**一次返回＝回「今天」页**；已编排进底栏五 tab 的（待办/时间/记录）→ **二次返回退出**（第一次回今天）。合并成一条规范＝**「今天」是唯一根出口，任何非今天页按返回都不许直接退出 app**。
- 现状（探针 7/7 实测）：宫格磁贴 `context.go(NavModule.*)`＋单 ShellRoute → 无历史 → 一次返回直接退出，与拍板不符，需整改。
- 实现候选（批主择一，均须真机判据）：① 壳层根 `PopScope` 拦截——location≠'/' 时返回改走 `go('/')`，改动最小、不碰各模块路由；② 宫格磁贴 go→push＋tab 历史——有 R14-5 push 壳 tab 白屏前科，必须真机验底栏不双叠不白屏。widget 测不复现壳路由缺陷，**判定在真机门**。
- 验收判据＝`tools/uxwalk/back_probe.sh` 用例表：宫格 7 条由 EXIT-APP 翻绿为「回今天」；tab 切换链路二次返回退出。
- 回灌项：该语义写进 `docs/UI组件规范.md` 壳层节＋需求清单口径（随批走）。

### U4（High）阅读热力图整片灰
- **代码层预筛（2026-10-06 本会话，不等真机就能排掉的两项）**：① 取数链 `read_repo_stat.dayLogYear` 与书架汇总 `shelf_query.sessionAggByBook` **同一条过滤**（`endedAt == null` 的在跑会话都不入账）且都按 `startedAt` 归日、键归一到零点，所以「热力图有数／书架没数」这种键错位**不存在**；② 色阶 `_heatCard` 的 `mx` 用 `max(1, 全 365 天最大 `_val`)` 且 `lvl = v==0?0:...`，指标默认 `'min'` 取 `dayMinutes`——**若 `dayMinutes` 全零，mx 恒为 1、整片 lvl0＝灰**，与现象一致。⇒ 判据落在**数据侧**：热力图唯一数据源是 `book_sessions`（书架计时），而今天页那张「本周时间分布」读的是**日程计时**（时间模块的分类「阅读」）。用户若习惯用日程计时记阅读，`book_sessions` 就是空的——那不是渲染坏了，是**两套计时口径不互通**。
- **产品口径（2026-10-06 问询定）＝先真机定数据，再选修法；本轮不写代码。** 判据一条（真机插上即跑，6073 arm64 腿）：进「记录 → 阅读段 → 统计」读热力卡右侧汇总两数（`合计 N 分 · M 天`，同源 `dayMinutes`），再回今天页读「本周时间分布 · 合计 …」。**两边不一致（一边 0、一边有值）＝坐实两套计时口径不互通**，届时在下列四条里选：
  - **A 并源**：热力图与阅读统计的日账同时吃日程计时的「阅读」分类，与今天页同口径。不须原型门。代价＝先定同一天两边都记了怎么算（相加／取大／按书归并），改动跨 read+calendar 两域，要带聚合回归用例。
  - **B 不并源，只补空态与指引**：数据链不动，汇总为 0 时热力卡不再装作有数据，给人话一句＋去处（开书架计时／跳时间账本）。代价＝属 UI 变更，**先改原型经逐屏确认**才动实现；两个计时入口仍并存。
  - **C 不修，登记为既定口径**：书架计时＝这本书读了多久，日程计时＝这段时间归到哪个分类，热力图只按前者画，灰是正常。代价＝「我明明读了却全灰」的体验问题挂着。
  - **读数若「两边都有值且相等」＝上面两条代码层预筛漏了东西**，回到渲染分支（`_heat[lvl]` 色值与 `inM` 透明度、`_month` 过滤态）重判，不许直接套 A/B/C。
- 顺带一条防误读：`read_stat_page` 热力格的 `Tooltip('$m 分钟…')` 与点格 toast「摘录约 Y 条」在没数据时同样读得出「0 分钟」，**不能拿它们当数据侧证据**，只认汇总两数。
- 雷电复现不了：那台机的数据条件凑不出「有 5 天会话」的形态，硬造属假现场，不做。
- 现象：2026 有 2h18m/5 天数据，365 格无一着色（x-dark 轮同屏复现于浅色）。
- 排查序＝先数据后渲染：① SQL 核对 5 天计时是否进热力聚合窗口；② 色阶函数 min>0 判定与档位映射；③ 若均正常则查格子着色分支。定性随证据走（回填断 or 色阶失效），修复带常驻用例（读真实聚合 fixture，禁写死日期）。
