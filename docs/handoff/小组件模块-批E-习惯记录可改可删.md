# 小组件模块 · 批E 习惯打卡「记录可改可删」（打卡时间 ＋ 数值）

> 2026-10-18 产品真机回执原话（在批D 装机验过三格步进之后）：
> 「最小减到零，点击后显示为已打卡·xx ok 的，**但是需要修改下习惯打卡模块的逻辑，
> 缺少修改打卡记，删除或修改（打卡时间，数值这一类的）**」。
> 本件＝该诉求的开批规格＋实施记录。代码落点跨 Dart（App 内）与 Kotlin（桌面一枚按钮）。

## §1 真因：不是「少一个按钮」，是三处入口全是死区

产品说的「缺少修改」不是指功能没写，而是**每一条能想到的入口点下去都没有出口**：

| 入口 | 批D 交付态 | 病 |
|---|---|---|
| 桌面打卡枚（已打卡） | 按钮置灰、`setOnClickPendingIntent(id, null)` 撤意图 | **点了完全没反应**（批D §6-2 照原型「撤销/改数回 App 内」写的，但 App 内当时没有这个能力） |
| 详情页「打卡流水 · 近 14 天」 | 每行是纯 `Row`，无手势 | **只读**——看到哪天错了也点不进去 |
| 详情页「打卡日历」今日格 | `habitToast('今天请在卡片上打卡或记量')` | **死提示**（说的那件事 App 里也做不到） |
| 记量弹层 `showHabitLogSheet` | 只能编辑**今天**（`dayKey(now)` 写死） | 历史日无入口；`checkAt` 用「沿用旧值/取此刻」二选一，**没有编辑控件** |

即：批D 那句「撤销/改数回 App 内」当时是**空头支票**。本批把票兑上。

## §2 口径

1. **一处表单，按日参数化**：`showHabitLogSheet(context, ref, h, {String? day})`。
   `day == null` ⇒ 今天（原有行为不变）；传了 ⇒ 编辑**那一天**。
   **禁另写第二套「历史记录编辑页」**——同一份表单换目标日，加/减档、组习惯达成规则、
   备注、冻结标记全部自动继承。
2. **打卡时间可改**：新增 `ValueKey('hlog-at')` 可点行 → `showTimePicker`，
   `alwaysUse24HourFormat: true`（与流水列 `HH:MM` 同格式）。默认值＝原记录 `checkAt`，
   没有则取此刻。
3. **改值必须保留原来源**：`origin: e?.origin ?? HabitEntry.oManual`。
   旧实现一律写 `oManual` ⇒ 改一次历史补记，来源就被洗成手动（统计与审计口径会漂）。
   `backfilled` 同理保留，历史日**首次**建记录按补记算（`e?.backfilled ?? !isToday`）。
4. **删除走仓库唯一出口**：`repo.deleteEntry(h.id, k)`。
   桌面/App/后台三入口的写实现已经收敛（`habitValueWrite` / `upsertEntry`），
   删除同理——禁在弹层里直接 `db.delete`。
5. **桌面已打卡态从「死区」改成「导航」**：按钮保留置灰观感，但挂
   `clickIntent(SEG_HABIT_CHECK, REQ_BTN)` 把用户送进 App。**是导航意图，不写库**
   （C5 禁的是第二套业务写实现，不是禁跳转）。
6. **布尔型不出数值区**：`if (h.hasVal)` 才渲染量块——布尔习惯的记录编辑只有
   「打卡时间／备注／删除」。

## §3 落法切片

- **S1 弹层参数化**：`_HabitLogSheet` 增 `final String? day`；`k => widget.day ?? todayK`、
  `isToday => k == todayK`；`initState` / `_checked` / `_save` / `_undo` 全部改用 `k`。
- **S2 打卡时间行**：`late String _at`（原记录优先）＋ `_pickAt()`（`showTimePicker`）＋
  弹层顶部可点行；保存时 `checkAt: _at`。
- **S3 文案与按钮分档**：标题 `isToday ? '打卡记量' : '记录'`；按钮 `isToday ? '撤销' : '删除'`；
  toast 历史日带日期（`已删除 M月d日 的记录`）。
- **S4 详情页两处入口**：日历今日格 → `showHabitLogSheet(..., day: k)`（删掉旧死提示）；
  流水每行包 `GestureDetector(key: ValueKey('hd-rec-<dayKey>'), behavior: opaque)` → 同日弹层。
- **S5 桌面按钮**：`HabitCheckWidget` 布尔型 `row.done` 分支与数值型「已提交态」分支，
  按钮意图从撤除改成 `REQ_BTN` 导航（与 root 同段不同码，互不覆写）。
- **S6 守护**：新增 `test/habit_record_edit_test.dart` 六例＝三条行为（流水行改+删、今天格、
  布尔无值块）＋三条源码守护（`day` 参数化与 `showTimePicker`／改值保留来源／详情页两处入口）。

## §4 实施记录（2026-10-18 · 6187 已装机）

### §4-1 为什么不做「历史记录专用页」

历史日与今天的差别只有三件：目标日、补记标记、按钮文案。另起一页要复制组习惯的
达成规则校验（`_met` / `_ruleOk`）、子项分档、备注、冻结——复制一次就是一次分叉源。
故走**参数化**：一份表单，`k` 一改全变。

### §4-2 `_at` 用 `late` 字段而不是 `initState` 里赋值

`_at` 的初值依赖 `widget.ref.read(habitDataProvider)`，而 `initState` 里 provider
可能还没首次求值完（`valueOrNull` 为空）——`late` 字段在**首次读取**时求值，
拿到的是真正要用的那份数据；同时它只求值一次，用户改过之后再重建不会被打回原值。

### §4-3 打卡时间只改「时刻」，不改「日期」

日期由 `k` 决定（流水行点的是哪天就写哪天）。允许在「那天的记录」里把时刻改到任意分钟，
但不允许把它搬到另一天——搬日期是「删除 + 补记」两件事，混在一个控件里会造出
「补记标记与日期不符」的脏数据。

### §4-4 桌面这枚按钮仍是「导航」，不是「就地编辑」

原生的 ± 只动显示态草稿（批D §6-1），改记录要动业务库＋要时间选择器，
两者都不能在 RemoteViews 里做（无输入控件、无对话框）。所以桌面只负责**把人送到门口**：
`lh://habit/check` → `/habits` → 点卡片进详情 → 流水行 → 那天的记录。
**已知余量**：没有直达「该习惯该日」的深链（快照里只有习惯名、没有 id；
新增 id 字段要动快照编码与两侧守护）。若产品要求「桌面点一下就落到编辑」，
需单开一条带参系统寻址段（`habit/record?name=` → 解析成 id → `push('/habit/<id>')`）。

## §5 坑

- **别在弹层里写 `dayKey(DateTime.now())`**：那是本次改造要消灭的硬编码。
  一律走 `k`，`_save`/`_undo`/`_checked`/`_v` 四处都要改，漏一处就会出现
  「界面显示的是历史日、写进去的是今天」。
- **改值不能顺手「修」来源**：`oBackfill` 被洗成 `oManual` 会让补记统计失真；
  同理 `frozen`（冻结）必须原样透传，否则改一条冻结记录会把它解冻。
- **`find.text('07:15')` 会撞两次**：详情页流水行本身也写着这个时刻。
  断言时刻一律 `find.descendant(of: byKey('hlog-at'), ...)`。
- **测试视口 800×600**：流水行常落在视口外，`tap` 前必须 `ensureVisible`，
  否则报的是「找不到某段文案」而非「点不到」。
- **桌面按钮两码一目标**：`REQ_ROOT`（整枚）与 `REQ_BTN`（按钮）指向同一段，
  `PendingIntent` 相等性不比 extras，**码必须不同**，否则互相覆写。

## §6 验收（真机·6187）

1. 详情页「打卡流水」任一行点开 ⇒ 标题是「记录 · 名 · M月d日（补记）」，
   数值是那天的量、时刻是那天的时刻（不是此刻）。
2. 改数值 + 改打卡时间 → 保存 → 流水行当场变；库里 `origin` 仍是原来源。
3. 点「删除」⇒ 那天记录消失（今日则回到「未打卡」）。
4. 日历点今天 ⇒ 直接开「打卡记量 · 名」，**不再弹「今天请在卡片上打卡或记量」**。
5. 桌面数值型已打卡枚点按钮 ⇒ 进 App 习惯页（不再毫无反应）；布尔型同理。
6. 布尔型习惯的编辑弹层**没有**数值区（只有时刻／备注／删除）。
