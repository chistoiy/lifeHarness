## 1 · 背景与已修/未修边界

- **已修（提交 `eb7c4c1`，6061 真机已验）**：`lhbak` 不在 file_picker 的 Android MIME 表 → `FileType.custom` 直抛 `PlatformException` 且 UI 无 catch＝点「选择 .lhbak 文件」从未弹起过。现 custom 被拒降级 `FileType.any`（降级留痕日志）＋UI 可见失败条。雷电 6061 实测：选择器正常弹起。

### 14B · 真机反馈三条（产品 2026-10-06 口述）

- **①「我的」页 WebDAV 状态永远显示未配置**＝根因是 `settings_page.dart` 那行 `trailing: '● 未配置'` **写死的常量**，从没读过配置（真机 6077 截图已确认）。修法＝新 `activeSyncServiceProvider`（激活服务，未配置给 null 且**绝不抛错**）＋行内 `ref.watch`。**措辞取「已配置」不取「已连接」**：本机只知道自己存了端点，连通性是同步页「测试连接」的口径，主页不许冒充（原型 `p-profile` 那行的「● 已连接」属过度承诺，待产品点头后回改原型）。
- **②差异对比「重新扫描」无反应、退出重进才刷新**＝根因＝`SyncOrchestrator.compare()` 调 `list()` **不带 force**，而 store 实例被 `_stores.putIfAbsent` 长期持有、内建 **60s 清单缓存**（原注释自认「60s 缓存在 store 内建」）→ 第二次点拿到同一份旧清单，看起来就是没反应；TTL 过了再进才换新。对照件＝`CloudCleanService.cloudOrphans` 早就 `force: true` 并注明「清理决策必须看最新云端」。修法＝`compare({bool force = false})` 透传，差异半屏进屏与重扫一律 `force: true`（自动同步/调度侧继续吃缓存，不多打 PROPFIND）。
- **③清理云端不能全选＋彻底删除无进度并「堵塞」页面**＝根因＝这屏**从来没做全选入口**（差异半屏有 `全选上传/下载` chip，S7 漏做），且批量执行只把 `_busy` 置真（全控件禁用）**没有任何进度与取消出口**，几十条期间像卡死。修法＝屏头加「未引用 N 个 · X MB」＋`cc-all` 全选/取消全选；执行期换成进度行（`归档中 3 / 12`＋`LinearProgressIndicator`＋`cc-cancel`），`CloudCleanService.archive/purge` 加 `onProgress(done,total)` 与 `cancelRequested`（**当前条落定后**才停手，不硬切请求；失败条也推进度）；半屏被关＝用户收手（`dispose` 置取消）。
- **④顺手抓出（真机走查带出）**＝「我的」页记录管理入口副注仍写「版本恢复 · 快照 · **回收站清理**」，而该档位 F5-3 已挪进回收站屏——原型从未有此文案＝**实现侧漂移**（与 U11 同类，不过门），改「版本恢复 · 快照 · 文件夹」。
