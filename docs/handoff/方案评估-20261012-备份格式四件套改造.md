# 备份/导出体系改造评估：格式（四件套）＋ 范围（自由导出）

> 评估件（非施工工单）·只读产出，未动代码与原型。
> 基线＝当前 `.lhbak` 实现（`lib/core/backup/lh_bak.dart`、`backup_service.dart`）
> ＋既有笔记导出能力（`lib/features/journal/presentation/note_export.dart`）
> ＋上一批只读审计（`docs/handoff/审计记录-20261012-备份与还原查漏补缺.md`）。

## 〇 一句话结论

**四件套的「内容骨架」可行，但「md 当恢复源」这条不可行。**
推荐做法＝**权威库（数据库快照）+ 可读投影（md/图片/配置）双层**，两层同源派生，
装进同一个**能被任何解压工具打开**的包 —— 我们把这条叫「**可读的包**」。
无论最终选哪个方向，上一批审计的三条 P0（附件不落盘 / 退版包漂移 / 包内套包）
都必须一并修掉，**不能用「换方案」绕过**。

## 一 现方案基线（实测口径）

| 维度 | 现状 |
| --- | --- |
| 容器 | `.lhbak` = ZIP（`ZipFileEncoder`，archive ^3.6.1） |
| 成员 | `manifest.json` + `db.sqlite`（`VACUUM INTO` 一致性快照，不拷活文件）+ `attachments/<目录名>/<相对路径>` + `logs/<文件名>` |
| manifest | dbVersion / appVersion / createdAt / 逐表行数+校验和 / members / encrypted / kdf / skippedLarge |
| 加密 | 可选口令档：`db.sqlite.enc`、`attachments/**.enc` 逐成员 AES-GCM（PBKDF2-HMAC-SHA256，100k 轮，算法白名单 + 轮数封顶）；manifest 与 logs 恒明文 |
| 恢复链 | verify → 恢复前自动备份（`auto_before_restore_*`，只落应用导出目录、永不进同步目录）→ close → unpack（整库替换，ATTACH 快照重建）→ reopen → 报告 |
| 附件落盘 | **无**（`lh_bak.dart` 自注「附件/日志落盘属 T10，此处只恢复 DB」） |
| 配置 | **不入包**（prefs 逐字段读写，`SettingsRepository` 无整包序列化） |
| md | **不入包**（但 `note_export.dart` 已能「无损」导出 `<标题>.md` + 同级 `_assets/`） |

**四件套对号**：数据库 ✅（已有）／图片 ✅（包里有，恢复不落盘）／md ❌（有能力未接）／配置 ❌（不入包）。

## 二 逐项可行性

| 件 | 现状 | 可行性 | 关键约束 |
| --- | --- | --- | --- |
| 数据库文件 | `db.sqlite` 快照 | ✅ 直接保留 | **必须继续当恢复权威** |
| 图片文件 | `attachments/` 已收 | ⚠️ 收得到、恢复不落盘 | 修 P0；`note_images` 是 SHA256 内容寻址命名，md 引用靠相对路径 |
| md 文件 | 有导出能力、未接入备份 | ⚠️ 可做，**不能当恢复源** | `rich` 的 Quill Delta→md 有损；DB 有 md 装不下的元信息 |
| 配置文件 | prefs 逐字段 | ⚠️ 要分两类 | 口径设置可入包；**凭据（云 token/密码）绝不入包** |

## 三 为什么 md 不能当恢复源（最关键的一条）

1. **有损**。`_deltaToMd` 只覆盖 heading / list（有序·无序·勾选）/ blockquote / code-block / inline（bold·italic·strike·code·link）/ image。**表格、嵌套列表层级、自定义 attr、视频等嵌入物（退化成 `▪`）都会丢**。DB 是唯一无损源。
2. **不完整**。一条 note 在库里还有 `folder`、排序、`deleted_at`（软删）、`kind`、双链、创建/修改时间等；单文件 md 装不下，硬塞要自造 front-matter，等于发明第二套格式。
3. **不适用**。日记、健康、影音游、X-Ray 词库、记账、思维导图……这些模块的数据**本来就不是「笔记」**，md 化既无意义也无法无损。
4. **权威歧义**。md 与 DB 冲突听谁的？一旦定义「DB 权威」，md 就**只能是投影**，不能反哺恢复。

> 结论：**md ＝ 可读投影 / 迁移出口；数据库 ＝ 恢复事实源。两者角色不能互换。**

## 四 三个候选方案对比

### 方案 A（推荐）：可读的包 —— `.lhbak` 内部就是这四件

```
lifeharness_20261012_143000.lhbak   ← 仍是 zip；改名 .zip 即可用任何工具解压查看
├── manifest.json      版本 / 逐表校验和 / 逐文件 sha256 / structVersion（结构版本）
├── db.sqlite          恢复权威（VACUUM INTO 快照）
├── notes/             md 投影：笔记/日记各一 .md（front-matter 存元信息，复用 note_export 口径）
│   └── _assets/       该条引用的图片（相对路径，内容寻址名）
├── attachments/       note_images / book_covers 原图
├── config/
│   └── settings.json  口径设置（去凭据）
└── logs/
```

- **优点**：满足「可读」诉求（任何解压工具都能看/能核对）；保住一致性快照与逐表校验锚点；改动集中在 manifest ＋ 打包成员 ＋ 恢复落盘规则；口令加密能力保留（逐成员 `.enc`，可读性＝持有口令后可见）。
- **缺点**：md 是新增产物，导出耗时与体积略增（文本量小，可接受）。
- **兼容**：manifest 加 `structVersion`（旧包=1，新包=2），解侧按版本分支 —— 旧 `.lhbak` 照常可恢复。
- **一句话**：把「可读」做进包内结构，`db.sqlite` 当权威、`notes/` 等当投影，**一个包同时满足「能恢复」和「能看懂」**。

### 方案 B：无包目录树（用户原方案的字面形态）

- 形态：备份 = 一个文件夹（db + notes/ + attachments/ + config/），云同步时再压 zip 上传。
- **优点**：最可读、可增量、可人工修。
- **缺点**：**多文件无法原子快照**（备份进行中正在编辑 → DB 与 md/图片撕裂）；散文件易丢、云盘易「部分同步」；路径/权限耦合；恢复要重造目录语义；加密只能逐文件（可读性优点反而被抵消）。
- **判定**：**不推荐**，风险 > 收益。

### 方案 C（最小改动）：单包不动 ＋ 旁挂「可读导出目录」

- 形态：`.lhbak` 完全不动，导出时**额外**产出一棵可读导出目录（复用 `note_export`）。
- **优点**：零风险，不碰恢复链路。
- **缺点**：两份产物用户得自己管；「可读」与「可恢复」割裂，不是一个东西。

**选型建议**：优先 **A**（一个包两用）；若产品要极致稳、先落地再演进，先做 **C** 铺路、下一批升 **A**；**B 不建议**。

## 五 无论选哪个，都必须一并解决

1. **附件落盘恢复（P0）**：现恢复只还原 DB，换机后 `note_images/` 全空、正文图片悬空。方案 A/C 都要补「unpack 后按 `attachments/` 落盘 + 清理旧目录」。
2. **退版包 schema 漂移（P0）**：`verify` 只拒「包 dbVersion > 当前」；旧包放行，`unpack` 按旧 DDL 重建且**不写 `PRAGMA user_version`** ⇒ 迁移永不触发、`no such column` 永不自愈。改法＝要么拒收旧包，要么恢复后按当前版本**显式跑迁移**。
3. **`exports/` 套包（P0）**：`attachDirs` 含 `<docs>/exports`（云同步 `.lhbak` 落点），打包递归收全部文件 ⇒ 每导一次套一层。改法＝按扩展名排除 `.lhbak`。
4. **配置分「口径 / 凭据」**：口径设置（主题、同步份数、健康随备份开关、导航收起态…）入包；**凭据（云 token/密码）绝不入包**。需给 `SettingsRepository` 加「全量导出/导入」能力 —— 注意硬约定：**加设置项必四处同步**，新增「整包序列化」是同一处集中改造。
5. **md 有损兜底口径**：文档与 UI 明示「md 为只读投影，恢复一律以数据库为准」，避免用户误以为 md 就是全部。

## 八 追评：按范围的「自由导出」（选择性导出）

> 追问场景：「我只导出阅读数据」这种。

### 8.1 这是与四件套正交的第二根轴

| 轴 | 问题 | 现状 |
| --- | --- | --- |
| 轴一 · 存成什么 | 格式 / 可读性 / 加密 | 已有 `.lhbak`（§一~§七讨论的就是它） |
| 轴二 · 导出什么 | 范围 / 子集 | **只有「全部」**；`excludeTables` 是反向排除，不是正向选择 |

「只导出阅读数据」＝ 让轴二从「恒等于全部」变成「可选」。两轴可自由组合（格式 × 范围）。

### 8.2 抓手是现成的：schema 已按模块分文件

`lib/core/database/schema/` 下每个模块一个文件，表名以 `const String tXxx` 常量导出，
`schema.dart` 把它们逐个拼进 `createStatements`。**模块 → 表清单的映射天然存在**：

- 阅读 `read.dart`：`books` / `book_sessions` / `book_quotes` / `book_toc_nodes` / `book_dict` / `book_reviews` / `book_lists` / `book_list_items` / `douban_meta`（9 表）
- 其余：`health` / `media` / `ledger` / `care` / `habit` / `days` / `goals` / `items` / `ai` / `mindmap` / `xray` / `core`

而且**已有「模块内范围导出」先例**：记账 `/export`（范围四 chip × CSV/JSON、流式落盘）、健康导出 CSV/JSON。
把这两个抽象成通用件，就是本方案的地基。

### 8.3 决定性岔路：导出后要不要「装回去」

- **纯出口**（分享 / 迁移 / 给第三方工具读）→ 不需要合并恢复，风险低。
- **部分恢复回库** → `unpack` 现在是**整库替换**（先把所有表 `DROP` 再按包重建）。
  **拿一个只含阅读数据的子集包走 `unpack`，会把健康/记账/日记全部清空**。
  要支持部分恢复，必须另写**合并恢复**（按主键 upsert、去重、外键顺序），复杂度与风险都高一档。

> 结论：**把「导出」和「部分恢复」拆成两件事**。首批只做「数据出口」，部分恢复单独立项。

### 8.4 三档形态

| 档 | 形态 | 用途 | 碰恢复 | 建议 |
| --- | --- | --- | --- | --- |
| ① 模块数据出口 | 目录：md/csv/json + 附件 | 分享、迁移、第三方读 | 否 | **首批** |
| ② 子集可恢复包 | `.lhbak` + `manifest.scope` | 跨机迁移单模块 | 需合并恢复 | 后置/单独立项 |
| ③ 单条记录分享 | 一条书摘 / 一个书单 | 摘录分享 | 否 | 随 ① 顺带 |

### 8.5 范围的自由度（可组合的过滤器）

- **按模块**：单选 / 多选（阅读、健康、记账、日记…）
- **按时间**：全部 / 近 1 年 / 自定义区间（吃 `created_at` / `date` 列）
- **按记录子集**：某本书、某个账本、某个标签
- **是否含附件**：图片是体积大头（`book_covers/` 等），给开关

### 8.6 必须一并解决的坑

1. **合并 ≠ 替换**（见 8.3）：子集恢复必须另辟路径，**绝不能复用 `unpack`**。
2. **表闭包**：模块内表要整组导出，`books` 不带 `book_quotes` 会残缺 —— 导出单元定义要含闭包。
3. **跨模块悬挂引用**：note 可挂 book、mindmap 可挂 note、书摘可挂书 —— 只导一侧会让另一侧出现「指向不存在记录」的引用。三选一：保留空引用 / 带最小上下文 / 导出时拒绝并提示。
4. **附件一致性**：只导阅读是否带 `book_covers/`？书封会不会被别处引用（如书单）—— 按引用图决定。
5. **包要自描述**：manifest 增 `scope`（模块 / 表清单 / 时间 / 是否含附件），恢复侧据此分流（全量替换 vs 合并 vs 只读挂载）。
6. **可再生表**：X-Ray 解析产物照旧排除（`kRegenerableExcluded`），子集导出同理。
7. **隐私提示**：按模块导出更易「单独泄露」某类数据（健康/记账），UI 要给敏感模块提示。
8. **版本口径**：子集包同样要处理 §五·2 的退版包漂移问题。

### 8.7 落地建议

1. **先改原型**（流程铁律 7）：导出入口从「一枚导出钮」升级为「范围选择面板」（模块 chips × 时间 × 格式 × 含附件），先过产品门。
2. **抽象通用件**：把记账 `/export`、健康导出收编为统一 `ExportSheet` ＋「导出单元注册表」（模块 id → 表清单 → 附件目录 → 投影器）。
3. **首批只做「数据出口」，不碰恢复链**；子集「合并恢复」单独立项评估（主键 / 外键 / 去重策略）。

## 九 原型改动单（待过门）：导出范围选择面板

> 供产品过门用；通过后按铁律 7 落原型 → 过门 → 升需求版本 → 进实现。

### 9.1 挂屏决策：家 = 「数据与同步」屏

- 现导出入口＝该屏「本地备份」卡里的两枚按钮（**导出一键备份** / **从文件恢复**），点按直出，无范围可选。该屏归属＝`prototype/index.html`（壳与跨模块，屏 id `p-sub-data`）。
- 「备份文件」屏（`p-sub-backup`）是**列表与删除管理**，不是「发起导出」，不宜再塞入口（审计已提入口语义重叠）。
- **结论**：新增一枚**页内弹层 `sheetExport`，家在本屏** —— 与既有 `sheetSyncDiff` / `sheetBkDel` 同模式（弹层家在本屏）；不新开整屏，因为导出是一次动作，整屏过重。

### 9.2 面板结构（自上而下）

| 区 | 内容 | 说明 |
| --- | --- | --- |
| 标题 | 「导出数据」＋ 关闭 | grabber |
| ① 范围 | 模块 chips 多选：**全部数据** / 阅读 / 日记 / 健康 / 记账 / 呵护 / 习惯 / 目标 / 物品 / 影音游 / X-Ray / 思维导图 / AI 记录 | 首项「全部数据」＝单选快捷；其余可多选；右下角显「已选 N 个模块」 |
| ② 时间 | 全部 / 近一年 / 自定义区间 | 自定义用现有日期选择件（就地内嵌） |
| ③ 内容 | 含图片附件（开关，显预估体积） / 附可读 Markdown（开关） | 图片是体积大头，给开关 |
| ④ 格式 | `.lhbak`（可恢复） / 可读目录（md+csv+json） | 默认 `.lhbak`；非全量范围选 `.lhbak` 时出提示行（见 9.3·2） |
| ⑤ 底栏 | 「N 模块 · 约 X MB」＋ 渐变主钮「导出」 | 主钮文案随范围变（全量＝「导出备份」） |

### 9.3 交互与边界

1. **默认态 ＝ 全部数据 ＋ 全部时间 ＋ 含附件 ＋ `.lhbak`** ＝ 现「一键备份」的等价物（旧路径不丢）。
2. **非全量 ＋ `.lhbak`** ⇒ 提示行：「子集包暂不能直接恢复，仅作数据出口」（对应 §8.3）。
3. **「附可读 Markdown」** 仅当被选模块含笔记类数据（日记 / 阅读书摘 / 思维导图）时才可用，否则置灰。
4. **空态**：所选范围无数据 ⇒ 主钮禁用 ＋ 文案「所选范围暂无数据」。
5. **体积预估**：进入弹层即算（附件占比），避免导完才发现几百 MB。
6. **权限 / 失败**：沿用「点了必须有看得见的变化」——导出中给进度、失败出声（对齐备份批口径）。

### 9.4 状态存法

- 面板开关是**瞬时 UI 状态**，不持久化；结构照记账导出 `exp={scope,fmt,month,acct,cat}` 的通用版：
  `exp = { modules: [], time: 'all', custom: null, assets: true, md: false, fmt: 'lhbak' }`。
- 可选（非必需）：把「上次导出范围」记进 prefs（照 `backup_last_save_hint` 模式，仅展示记忆、不做授权），下次进面板回填。

### 9.5 涉及改动与登记

- `prototype/index.html`：`p-sub-data`「本地备份」卡按钮改为开弹层；新增 `sheetExport` DOM ＋ `renderExportSheet()` / `exp` 状态 ＋ 预估与导出动作占位。
- 注册表：`sheetExport` 入册（`proto_registry.js --write --add-missing`，`_modules.json` 对齐；CRLF 归一口径见 MEMORY）。

| 「本地备份」卡两枚按钮 | 「导出」改开本面板；「从文件恢复」不动 |
| 记账 `p-export` 整屏（`index-ledger.html`，有账户/分类维度） | 保留为「模块内深度导出」；通用面板的记账项可深链过去 |
| 健康导出 CSV/JSON | 收编为通用件的一个「投影器」，或深链 |
| 笔记「导出为本地目录」 | 同上（可读投影器） |
| 同步弹层 `s-backup`（`index-sync.html`） | 云同步侧；若含重复导出入口，改深链本面板或删重（审计已提重叠） |

### 9.7 过门检查清单

1. 面板挂屏是否认同（数据与同步屏的页内弹层）；
2. 模块粒度：是否等于宫格模块清单；
3. 是否同意「非全量 `.lhbak` 暂不可恢复」的提示口径；
4. 格式两档（可恢复 vs 可读目录）是否够用；
5. 时间维度是否首批就要，还是先只做模块维度。
