## 一、审计总评

16 屏 + 19 弹层与 V1.33~V1.40 九轮修订的全部交互点**基本全量落地**（多账本 bk、双维排行钻取、消费洞察四规则、hero 草稿-保存制、who/标签/商家半屏、四则键盘先乘除后加减、退款互链、预算结转、金额隐藏开关等逐项核实通过）。正面确认：滚轮 `didUpdateWidget` 守卫齐全、键盘同步求值无丢键、双账本隔离逐查无漏 bk、记一笔 `_saving` 防重入已有。**但有四个高危缺陷 + 一条断链联动**。

## 三、中危/低危清单（按面分档）

**流畅度**：`acctById/catById` 是 getter 每帧重建全 Map（`ledger_providers.dart:85-105`，`LTxRow` 每行调用）→ 构造期预计算；主页 `_TxList` 非 `ListView.builder` 全量构建（`ledger_page.dart:817-861`）；搜索每键 setState 全量过滤+排序无防抖（`ledger_search_page.dart:170,230`）；报表趋势 O(桶×N)（`ledger_report_page.dart:157,320-357`）；净资产走势 O(6·A·N)（`ledger_repository.dart:374-399`）；`ledger_ring.dart:76` 与两处曲线 `shouldRepaint` 恒真、无 RepaintBoundary；`commitImport` 逐行查 hash 最坏 O(N²)（`ledger_repository.dart:1300-1306`）；导入解析串行 await 查重无 loading（`ledger_import_page.dart:126-137`）。

**跟手/手势**：日期滚轮年份硬编码 `_years=[2024..2028]`、越界静默跳 2024（`ledger_date_sheet.dart:39,68`）——**2029 年起必炸**；管理态小钮触达 24-28px（`ledger_pick_sheets.dart:454-488`、`ledger_cats_page.dart:605-637`）；金额滚轮确定钮裸 GestureDetector 偏小（`ledger_date_sheet.dart:273-289`）；`showDialog` await 后 dispose 竞态隐患（`ledger_sheets.dart:118-145`、`ledger_pick_sheets.dart:19-51`，cats 页 `_PromptDialog` 已是正解模式，收敛即可）。

**UX**：搜索框承诺「备注/商户名」但 `ledgerSearch` 不匹配 `merchant`（`ledger_search_page.dart:164` vs `domain/ledger_search.dart:52-55`）——搜商户恒空；同日合计列表/日历口径不一（adjust 一计一不计，`ledger_page.dart:865-872` vs `ledger_calc.dart:160-176`）；错误态仅 L1 有重试（`LoadErrorBanner`）其余页裸文字；「搜索分类（模拟）」「添加图片附件（模拟）」占位 toast 暴露；CSV 导出不含 merchant/who；结清后「记还款」钮未禁（`ledger_repository.dart:1192-1207`）；无障碍金额无 Semantics。

**测试缺口**：高危 1/2/3 与滚轮年份越界均无回归用例，修复批须补。

## 五、新面评估① 微信/支付宝付款自动记账

**口径澄清**：Android 无官方 API 读微信/支付宝界面数据，可行通道按侵入度三档：

| 通道 | 可行性 | 判定 |
|---|---|---|
| **A. 通知监听**（`NotificationListenerService`，解析微信「服务通知」/支付宝「支付助手」支付成功通知） | 纯本地免 root、通道稳定、隐私风险低；钱迹等成熟记账同款主通道 | **推荐** |
| B. 无障碍读屏（读支付结果页字段） | 能拿全字段但改版即断、隐私敏感、厂商封杀——本仓 HyperOS a11y 保活有实锤坑（服务看似绑定却 cgroup 冻结零事件） | 不推荐 |
| C. 小票截图 OCR | 需求清单 V2 注册表已灰置 | 维持 V2，不重评 |

**实现要点**（若拍板走 A）：Kotlin `NotificationListenerService`（`android/**`）＋「通知使用权」引导页；解析规则按包名分表；解析成功→落**待确认流水**（建议 `source='notify'`＋待确认标记或独立 pending 半屏），复用 `bill_hash` 去重、可并入 V1.56 整批撤销链；通知里点「记一笔」预填速记表单兜底。

**拍板项（开工前必问产品）**：① 静默入账 vs 待确认（建议**待确认**，通知解析易误记）；② 微信通知缺商户字段的兜底（进备注还是拦待补）；③ 双通道重复（App 通知＋短信）去重口径；④ 隐私与引导文案（须说明金额仅本地解析）。

**风险**：厂商杀后台/自启限制（小米 HyperOS 需手动放行，真机门必验）；支付通知文案随版本改版需热修；release 包无 a11y 组件是既有实测口径，通知监听组件同样须真机验证。

**流程门**：新能力先落需求清单（需求门）→ 通知卡/待确认流水 UI 原型先行 → 实现批改 `android/**` 须 `tools/kotlin_check.sh`＋出包真机验证。

## 六、新面评估② 手机桌面小组件快捷记账

**可行**（Android AppWidget + RemoteViews），形态分三档：

| 档 | 形态 | 判定 |
|---|---|---|
| 1 | **入口 widget**：2×2/4×1 图块，点击直达 `/ledger/add`，可带「本月支出」读数 | **推荐首批**，成本最低零输入风险 |
| 2 | **模板一键记**：widget 上 3~4 个预设模板钮（如「早餐 12 元」），PendingIntent 无 UI 记账（复用 `addTxn`＋默认账户；须防连点重复） | 二期可与 1 组合 |
| 3 | widget 内嵌金额键盘 | **不可行**：RemoteViews 不支持复杂输入；「就地内嵌滚轮」铁律在 widget 场景落不了地，维持点进全屏记一笔 |

**实现要点**：`android/**` 新 `AppWidgetProvider`＋Flutter 侧 `home_widget` 或纯 Kotlin；读数刷新以「记账后 App 主动 update」为主（widget 进程无 Flutter engine，直读 sqlite 须注意与 sqflite 并发读）；隐藏金额开关建议联动 widget 读数。

**拍板项**：① 形态档位（建议 1＋2）；② 读数刷新时机；③ 隐藏金额是否联动；④ 尺寸组合（建议 4×1＋2×2 各一）。

**流程门**：原型门可降为一张桌面示意图确认（SPA 原型表达不了系统桌面），样张确认后进实现；改 `android/**` 同样走 kotlin_check＋真机门（添加/点击/读数三条）。
