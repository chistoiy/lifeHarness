## §1 一句话目标

每个功能模块做一枚 **1×1 静态瓦片**，桌面上看起来就是一个 App 图标；点它**直接落到该模块首页**（不是先开首页再找）。**零数据、零刷新、零绑定、零配置。**

## §2 与既有四枚 widget 的分界（别照抄）

| | 读数型（概览 2×2／快捷 4×1／待办／记账／打卡） | 导航型（本批 1×1 瓦片） |
|---|---|---|
| 数据来源 | Dart 推快照 → `home_widget` → 原生解码（`LhWidgetSupport`） | **无**，布局写死 |
| 刷新 | `pushWidget*Snapshot` 按需刷新／后台 isolate | **永不刷新**（`updatePeriodMillis=0`） |
| 绑定 | `widget_bind.<id>` 三键＋交接位＋TTL | **无绑定**，一枚就是一个模块 |
| 配置页 | 打卡枚写 `android:configure` | **禁写**（见 §4.1） |
| 点击 | 部分带状态回写（乐观回显／待办勾圈） | **纯导航**，只发一条 `lh://` 深链 |
| 功耗 | 需考虑唤醒与推送 | **零**（静态图，无 receiver 常驻） |

⇒ 本批**不要**接 `pushWidgetHabitSnapshot` 那类链路，也不要碰 `widget_binding_store`。唯一复用是**深链通道**（§4.2）。

## §4 技术方案（A 案 · 推荐）

### 4.1 为什么必须「一模块一个 provider」

- 系统小部件选择器里**每一项 = 一条 `<receiver>` + 一份 `appwidget-provider` XML**；同一个 Kotlin class 写两条 `<receiver>` 会被 manifest **合并成一条**（组件名相同）。
- 所以：一个 `ModuleTileProvider` 基类 ＋ 17 个 3 行子类（`class TileTodo : ModuleTileProvider()`），17 份 `res/xml/lh_tile_<id>_info.xml`（尺寸全同，只 `description` 不同）。
- **禁 `android:configure`**：本仓 6176 轮已实证 **MIUI 桌面不跑 `android:configure`**；而「一枚瓦片＋配置页选模块」正好依赖它 ⇒ 在目标机型上必然坏。本批瓦片无参数、无需配置，天然规避——这是选 A 案而非 B 案的决定性理由。

### 4.2 深链表扩展（Dart / Kotlin 两处必须同步）

- **Dart** `lib/core/platform/desktop_actions.dart`：
  - `kDesktopNamespaces` 加 `'modules'`；
  - `kSystemLaunchPaths` 加 17 条 `'modules/<id>' → <路由>`（**段即 id**，与 `settings/desktop` 同族）；
  - 新增 `const Set<String> kShellLaunchSegs`（§3 里语义＝`go` 的那 12 条段），并让 `LaunchRoute.fullScreen` 变成三级判定：
    ```dart
    bool get fullScreen {
      final a = desktopActionOf(action);
      if (a != null) return a.fullScreen;
      if (kShellLaunchSegs.contains(action)) return false; // 模块瓦片·壳内 tab → go
      return isSystemLaunchPath(action);
    }
    ```
    （现状是「系统寻址段一律 push」，直接用会把底栏页 push 成栈顶 ⇒ 底栏消失。**这一行不改就是本批最大坑**。）
- **Kotlin** `MainActivity`：`LH_NS` 加 `"modules"`；`LH_WHITELIST` 加同样 17 条。原生**不需要**知道 go/push（那是 Dart 的导航语义），保持「只解析、不解释」。
- 既有守护 `desktop_ns_registry_test` / `desktop_intent_shape_test` 会钉两表逐条一致——不同步必红。

### 4.3 点击实现

```kotlin
val pi = PendingIntent.getActivity(
  context, requestCode,
  Intent(Intent.ACTION_VIEW, Uri.parse(MainActivity.lhScheme("modules/todo")))
    .setPackage(context.packageName),
  PendingIntent.FLAG_IMMUTABLE or PendingIntent.FLAG_UPDATE_CURRENT
)
rv.setOnClickPendingIntent(R.id.lh_tile_root, pi)
```

- 目标**全写进 URI**，**不要**往 extras 里塞模块名——`PendingIntent` 相等性不比 extras，同码＋`FLAG_UPDATE_CURRENT` 会互相覆写（6180 轮实锤）。
- 走 `ACTION_VIEW` 即复用既有 `enqueueLaunch`：冷启走 `onCreate`、热启走 `onNewIntent`，两条都已覆盖。
- **禁**为瓦片另起引擎/Activity（6181 轮崩溃就是「多一个引擎入口」带出来的）。

### 4.4 布局与视觉

- `res/layout/lh_tile.xml`：`LinearLayout(vertical, gravity=center)` ＋ `ImageView`(28dp) ＋ `TextView`(10sp·单行·`ellipsize=end`)。**禁裸 `<View>`**（RemoteViews 白名单）。
- 尺寸：`minWidth/minHeight=40dp`、`targetCellWidth/Height=1`、`resizeMode="none"`、`updatePeriodMillis="0"`、`widgetCategory="home_screen"`。
- 预览：`previewLayout`（A12+）＋ `previewImage`（**MIUI 只认图**，缺了 17 枚会长得一模一样）；沿用 `tools/gen_widget_previews.py`，浅/深两档。
- 图标：**vector drawable**（禁多密度 PNG，17×5 套会把 APK 吹起来）。来源＝Material Symbols 官方 SVG 逐个取 `<path>`，与底栏同形；一份 path 用 `android:tint` 走主题。
- 颜色：RemoteViews **不解析主题属性**（`?attr/…` 无效）⇒ 底色/文字色各出 `values/` 与 `values-night/` 两份 `<color>`。

## §6 验收清单（真机逐条）

1. 桌面长按 → 小部件 → 出现 17 枚「模块 · X」，**预览图各不相同**（不能全是应用图标）
2. 拖一枚到桌面 → 立刻显示图标＋标签，**全程不弹任何配置页**
3. **冷启**：划掉 App → 点瓦片 → App 打开并**直接停在该模块页**；返回行为正确（壳内模块退到底栏首页；全屏页返回上一级）
4. **热启**：App 停在别的模块 → 点另一枚瓦片 → **直接切过去**（不是回首页）
5. 同一模块加两枚瓦片 → 两枚都能点
6. 深色模式下底色与文字正确
7. 功耗：`dumpsys alarm` 无新增周期唤醒（`updatePeriodMillis=0`）
8. 卸载重装后旧瓦片显示系统占位而非崩溃

> 3、4 两条不过，其余都白搭——这两条正是「相当于桌面装了 App」的全部价值。

## §8 已知坑（本仓实证 · 别再踩）

1. **同一 class 两条 `<receiver>` 会被 manifest 合并** ⇒ 一模块一子类，不能偷懒。
2. **RemoteViews 白名单**：禁裸 `<View>`；状态点用 `ImageView`＋`setInt("setBackgroundResource")`；撑开器用空 `LinearLayout`。
3. **PendingIntent 相等性不比 extras** ⇒ 目标只写 URI，不写 extras。
4. **MIUI 不跑 `android:configure`** ⇒ 本批零 configure。
5. **`previewImage` 缺失 ⇒ MIUI 里所有瓦片长一样**（实测过五枚同款灾难）。
6. **深链两表必须同步**（Dart `kSystemLaunchPaths` ↔ Kotlin `LH_WHITELIST`），否则既有守护红。
7. **`go` vs `push`**：壳内模块用 `go`（底栏高亮/栈顶唯一），全屏页用 `push`（`go` 会换掉栈底壳页 ⇒ 返回黑屏退不出去·V1.67 真机伤）。
8. 新目录/新增行要上 `test/feature_size_budget_test.dart` 登记（本仓只许减，确属增长先写理由）。
9. `flutter test` 前先 `rm -f build/native_assets/windows/sqlite3.dll`（残留会崩 `PathExistsException`）。
10. **别在 python subprocess 里起 flutter**（会解析到 WSL 存根，输出 UTF-16 横幅、测试根本没跑）；跑测试用 Bash 直调。

## §9 明确不做

- 不做「一枚瓦片＋配置页选模块」（MIUI 不跑 configure）。
- 不做数据／角标／红点（那是读数型 widget 的活，会引入推送与功耗）。
- 不做动态图标（Launcher 不支持）。
- 不替换、不隐藏 App 图标。

### 11.2 三处与规格原文的偏差（都为了不踩已知坑）

1. **只给 `previewImage`，不给 `previewLayout`**（规格 §4.4 要求两个都给）：`previewLayout` 渲染的是
   `lh_tile.xml` 原样——图标槽为空、只剩一个标签，Android 12+ 桌面上比应用图标更难看；而 MIUI 只认

2. **`kShellLaunchSegs` 落在 `module_tiles.dart` 且由 shell 位派生**（规格写「在 desktop_actions 加 const Set」）：
   手写 const 集合＝第二份 shell 口径，加模块必漂移。现由目录派生，守护测试钉「集合 ≡ shell 位为真的段集」。
