# 拍板记录 · 2026-10-18 记一笔弹窗记账（走 A 路）与桌面零输入口径改判

> **产品拍板（2026-10-18）**：① 4×1「记一笔」点击改为**对话框弹窗记账、不开全屏 App**（调研 A 路）；② 存量跨线红（`NfcRelayActivity` 空 taskAffinity 撞桌面批3 守卫）归口本会话，已修。
> **上游**：`docs/handoff/评估结论-20261017-小组件Glance裁定与内容对齐NFC分类评估.md` §三 Q3④（原判·本件改判）＋产品两轮追问。

## 一、调研结论（为什么只有 A 路可行）

- **widget 自身弹不出任何弹窗**：RemoteViews 只是布局描述，无 popup/dialog API，也无可输入控件（Android 12 起只补勾选/单选/开关的**渲染**）；Glance 建在 RemoteViews 之上，天花板相同。「点小组件直接弹窗」＝点小组件拉起一个**对话框主题的 Activity**——业界标准做法。
- **本仓已有两块现成先例**（不是从零起）：`WidgetConfigActivity`＝`Theme.DeviceDefault.Dialog`＋带包名前缀的独立 affinity＋`excludeFromRecents`；`NfcRelayActivity`＝透明主题＋空 affinity＋`noHistory`（trampoline）。写入通道亦有先例：待办勾圈＝原生单列写＋失败入 `pending_toggles` 队列、App 启动排空；NFC＝引擎活着走 MethodChannel、不在走 relay。
- **三路径**：A 原生对话框 Activity（紧凑表单＋交 Dart 写库）＝**推荐**；B Flutter 对话框 Activity（视觉好但小窗＋IME＋文本缩放实测风险高、要为小窗重做紧凑 UI）；C SYSTEM_ALERT_WINDOW 输入型悬浮窗（焦点/IME/返回/MIUI 后台限制，**不推荐**）。
- **2026-10-18 追加（产品令·见 §五）**：弹窗版式须**复用记账页那套**（四类型 tab＋分类行＋子类 chips＋键盘栅格）。这条把 B 路原来的短板反过来了——「为小窗重做紧凑 UI」不再需要（同一份表单进对话框即可），**B 路升级为首选**，A 路降为「要重画一套、两套 UI 会漂」的备选。

## 二、口径改判（关键·先于实现）

2026-10-17 评估件 §三 Q3④ 原判：「近似桌面弹小窗打字的唯一路径是对话框主题输入 Activity，**本质仍是 App 内页面，与零输入口径冲突，不采用**」。

**本件起改判为采用**：「桌面零输入」重新释义＝**widget 自身（RemoteViews）不放输入控件**不变；**记账录入允许对话框形态的轻量 Activity**。依据：产品令「不要打开 app」的用户感知＝不起全屏、不进最近任务——由 `excludeFromRecents`＋`noHistory`＋独立 affinity 达成（对话框浮在桌面上，任务栈里不留痕）。**本条未改前，实现批不开工。**

## 三、实施口径（实现批·原型过门后动）

- **Activity 范式**：照 `WidgetConfigActivity`（Dialog 主题＋独立前缀 affinity＋`excludeFromRecents`）＋ `noHistory`（随手 dismiss）。
- **表单**：**版式＝复刻记账页「记一笔」**（四类型 tab 支出/收入/转账/借贷＋分类行「图标块·大类·子类」＋子类 chips 轨＋四则键盘「保存跨两行·再记/算同列」），弹窗只换**容器**与**高度**，不另造样式（详见 §五）；**原生只收集，写完交 Dart 写库**（引擎活着走 MethodChannel／不在走 pending 队列、App 启动排空）。**禁原生复刻记账规则**（分类解析/流水规则/导入哈希·R1 行为分叉红线）。
- **C15**：4×1 点击意图仍走 `LhWidget` 唯一出口，新增目标段，禁第二套构造。
- **隐私**：隐藏金额开关不影响弹窗（弹窗是录入入口，非读数位）。
- **深色**：弹窗跟随系统深浅（与 widget C6 口径一致，不吃 App 四主题）。
- **真机门四项**：软键盘不遮挡／返回即消／深色跟随／横竖屏。
- **同批合并**：4×1 三区原生实现（`52d79315` 原型已过）与本弹窗同一实现批（都动 `lh_widget_quick` 布局与点击意图），收口跑 `kotlin_check`，复测包攒批。

## 四、存量红裁定（同日·产品令「归属本会话」）

`test/desktop_widget_test.dart` 守卫「activity 标签禁空 taskAffinity」（2026-10-15 桌面批3 立，防 8147「最近任务两张卡」）撞 `NfcRelayActivity`（2026-10-17 NFC 批3c·贴卡透明中转，**有意**空 affinity：不归并主任务＝贴卡不闪现 App）。

**裁定＝守卫改「有条件豁免」而非放行**：空 affinity 必须**同时**带 `excludeFromRecents="true"`＋`noHistory="true"`（不出现在 recents 的中转界面与「面向桌面的入口」不同类；缺一照红）。变异实证：抠掉 `noHistory` → 守卫红；复原 md5 全等。**纪律**： invariants（组合不变式）比属性清单更重要——防将来照抄空 affinity 却丢了两个保命属性。

## 五、版式同源（2026-10-18 产品追加·推翻「紧凑表单」设想）

**产品原话**：「记一笔的弹层不对，应该是复用当前记账页面的那种四种类型，然后还有各个子类的样式」。

**读法**：弹窗不是「另一套简版表单」，而是**记账页「记一笔」的同一套版式换个容器**——四类型 tab（支出/收入/转账/借贷）＋分类行（图标块·大类·子类）＋子类 chips 轨（当前大类 chip＋其子类，无子类回落常用/收藏）＋四则键盘（保存跨两行·再记/算同列）。弹窗与整页的差异只允许有两处：**容器**（对话框 vs 页面）与**高度**（按内容收）。

**两条实现路（都可做·代价不同）**：

| | ① 原生按版式复刻 | ② 对话框 Activity 内嵌 Flutter 渲染同一份表单 |
|---|---|---|
| 视觉一致性 | 靠手工对齐（字体/图标/圆角/暗色逐个搬），改一处要改两处 → **会漂** | **零差异**（同一棵 widget 树，天然一致） |
| 图标 | 需把 Material Icons 字体塞进 android assets，按 codepoint 渲染 | 无需处理（Flutter 自带） |
| 分类数据 | Dart 下发快照 JSON（原生不读 sqlite·C5 同口径） | 直接走 Dart 仓库，天然合法 |
| 启动速度 | **快**（纯原生 <100ms） | 冷启需拉引擎（~300–600ms；用 `FlutterEngineGroup` 预热可压到 ~150ms） |
| 小窗/IME | 需自己处理软键盘遮挡与滚动 | 需实测小窗高度＋`adjustResize`（B 路原有风险） |
| 维护成本 | 两套 UI（记账页＋弹窗）长期双改 | 一套 UI，弹窗只是复用 |

**结论（本件定调）**：产品要「复用记账页版式」⇒ **②为首选**，①降为「②在真机上引擎冷启/小窗实测不过关」时的备选。两路都**不动** §三 的三条硬口径：原生/弹窗只收集、Dart 写库、禁复刻记账规则。

**原型样张（已交付·`widget_acheck` 38/38）**：`prototype/index-desktop.html` 的 `#qpDlg` 真弹窗按此版式重做（四 tab 可切、支出/收入＝分类行＋子类 chips、转账＝转出/转入两张账户卡、借贷＝借出/借入两段＋对方输入、键盘 15 键保存跨两行），`#dt-widget` 规格卡两档预览由**同一个生成函数**出图（防样张与真弹窗两套样式）。闸内新增：四 tab／分类行／子类 chips 单选中／键盘 15 键／转账借贷表单切换／弹窗不溢出屏幕框／内容无横向溢出／两档预览同源。
