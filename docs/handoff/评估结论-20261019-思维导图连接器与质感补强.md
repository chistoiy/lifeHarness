## §2 问题总评

你点的两条是**同一根因的两个病象**：本模块的树关系**只有 `parent_id` 一个入口**——新建根必然游离、md 平铺必然孤立，而「把 B 挂到 A 下」这个动作在画布上**根本不存在**（长按菜单七项、工具条三枚，实证无任何挂接项）。
所以修法不是给「加根」打补丁，而是补齐**挂接/摘除**这一对基础动作 ＋ 给 md 解析一个**结论先行**的分组口径。

其余面：批 1~5 功能骨架扎实（数据/渲染/性能规格/四连接点/五批导出），漏的是**「编辑效率链路」与「层级视觉」**——速录要反复开弹层、编辑一下编辑器就关、多根画出来分不清主次、节点长短不一导致连线忽长忽短。质感问题集中在**节点/连线的层级与焦点**，不在配色。

## §3 连接器（本批核心 · 三条，口径已定）

### 3.1 P1 节点挂接／摘除（根治「根连不上去」）

| 项 | 规格 |
|---|---|
| 服务端（数据） | 复用 `parent_id` ＋ `sort`（无新列；连接＝改 `parent_id`，摘除＝置 `null` 回根） |
| 入口 A（连） | 长按菜单新增**「连接到…」**：激活后画布进入**连接态**（顶部一条提示条 ＋ 全部可选目标节点描边闪烁），点目标节点＝挂到它下面；点空白/返回＝退出 |
| 入口 B（合并根） | 选中 A 后点 B：「B 挂到 A 下」；选中的是根时另给**「并入…」**（A 整枝成为 B 的子级） |
| 摘除 | 菜单**「断开→移到根层级」**（仅非根节点出现）；「断开」不删节点、不丢挂载引用 |
| 边线手势 | 拖节点右缘连接点（小圆点）到目标节点松手＝同 A（更高效，原型必做；实现侧可后置） |
| 红口径（禁） | 不可挂到**自己或自己的后代**下（成环）——连接态下这类节点**置灰不可点**，从根上杜绝，不给事后报错 |
| 折叠目标 | 目标节点处于折叠态时，连接后**自动展开**并滚到落位（否则「连了什么也看不见」） |
| 撤销 | 一次挂接＝命令栈一步，`label`＝「连接到 X」／「断开到根层级」 |
| 多根结果 | 挂接后该枝不再是根 ⇒ 单根遍历自然收成一条主干（配合 L1 视觉，多根孤岛问题当场消解） |

### 3.2 P2 md 解析分组（根治「全 H1 全是孤岛」）

现行 `parseMdOutline` 按「首枚标题相对归零」，拿到 10 个 `#` 就返回 **10 个 root**（实证 `md_parse.dart`）。**判定与处置**：

| 情形 | 现行 | 本批口径 |
|---|---|---|
| 有 ≥2 个层级（H1 下挂 H2…） | 一棵树 ＋ 若干同层根 | 不变，正常成图 |
| **全文仅一层标题（多为全 H1）且 >1 枚** | N 个孤立根 | **自动建中心主题**（图名／笔记标题）作为唯一根，其余全部并入其下；预览顶部一行「已按单层标题并入中心主题（N 项）」 |
| 预览层 | 只显示「共 N 个节点」 | 加一档**「结构」**选择：`并入中心主题`（默认）／`保留为多根`（用户本意就是并列清单时不强并） |
| 零层级（空行通道） | 平铺根 | 同上并入中心主题 |

落地位置：解析层只负责「判定并置位」（`singleLevel` 标记 ＋ 建议中心主题标题），**建图侧执行**（`mindmap_list_page` 的 md 起点分支），确保导出/HTML 一条通道同口径。

### 3.3 P3 树内导航（连接之后必然要的配套）

选中节点时菜单补两枚：**「收起整棵树」**（除焦点枝外全部折叠，配合 L3 聚焦——大图（含 md 导出的几十上百节点）一屏看清主干）／**「展开全部」**。二者不入命令栈（纯视图态，与默认布局同口径）。

## §4 层级与焦点质感（UIUX · 建议一并做进本批）

| # | 现状（实证） | 改造 |
|---|---|---|
| L1 | 全节点同色同重 ；根与叶只有缩进差别 | **按层分级**：根＝主色描边＋9% 淡底＋加粗；一级＝常规；二三级起描边降一档透明度。线与节点同族色（根级线用 `--mm-branch`） |
| L2 | 节点盒宽随文字长短，连线一长一短 | **同级节点最小列宽对齐**（横向树列宽已这样；纵向树补「同深度最宽值」下限，上限 300 不动） |
| L3 | 层缩进仅 24dp、节点宽封顶 280 ⇒ 深子节点的 `x` 会越过浅层兄弟的右缘，**连线钻进节点盒子底下**（实证：9 字标题盒 ≈164＋24×4 ⇒ **第 5 层起**必然发生，md 导出的深大纲首当其冲） | 连线在节点下层（现状）＋**被连线穿过的节点盒补不透明底色**；同批把根级线加粗提亮，视觉上分清「主干」与「细枝」 |
| L4 | 选中＝外扩描边，观感偏「加粗」 | 选中改**描边＋外发光 3px 淡环**（原型已有此形），取消时无跳变 |
| L5 | 画布无焦点概念 | **聚焦态**：选中一节点时，非同枝节点降到 40% 不透明度（松手/点空白恢复），大图立刻读得出「我在哪一枝」 |

## §5 功能与 UX 断链（按代价排序 · 前四条建议进本批）

1. **选中按钮条压在系统手势条上（UX 硬伤·实证）**：工具条给 `SafeArea` 加了 `bottom:false`，49dp 高贴到屏幕最底，Android 手势导航下三条键正对手势热区。修＝恢复安全区内边距并对齐原型 `bottom:82` 的抬升量。**零成本，优先修**。
2. **无同级速录**（脑图最高频动作）：加完一个子节点必须重新长按父节点。改＝「添加同级」后可连续回车继续、保留选中；回车=确认，**不关弹层**。
3. **编辑弹层无提交快捷**：标题/备注/标签输入框无 `onSubmitted`，改一下标题要伸拇指点保存。改＝回车即存（备注允许多行回车）。
4. **剪贴板域件已写好但无入口（实证）**：`mindmap_clipboard.dart` ＋ `MmClipboard`（含跨图、含子级）齐备、命令栈用例已覆盖，但画布**没有任何复制/剪切/粘贴入口**（长按菜单 7 项、工具条 3 枚）。补三枚即兑现 F4-2。
5. 兄弟重排缺失：`sort` 列与 `MmCommands.editNode` 都在，但没有上移/下移/拖拽换序。脑图调顺序是常事，补「上移/下移」两枚最省。
6. 长按菜单已 7 项（P1 后 8~9 项）：原型节点菜单是**定点浮层**（`openNodeMenuAt`），实现侧是底部弹层——**浮层贴节点更贴近手指、也不挡画布**，建议照原型改；项数多了可在浮层里分两段。
7. 工具条三枚全在底部（远离手指、挡内容）：建议「选中主操作（加子节点）」移到**贴节点的小气泡**，底部只留高频两项。
8. 搜索入口不齐：原型列表态顶栏有「搜索挂载节点」，实现侧列表页没有（全局搜索里能搜到，但本模块无入口）。
9. 连接点③ 反向缺件（实证）：`inbox_page.dart` 只有四向 ＋ `✕`，**没有第五向「转导图」**（需求模块 18 明确要双向）。属跨线，建议单开小批。
10. 「粘贴为子节点」的落位口径：粘贴到**当前选中节点**是反直觉的（复制 A、选 B、粘贴 ⇒ A 成了 B 的子节点）。建议改「粘贴为同级」默认，菜单里保留「粘贴为子节点」。

## §6 明确不建议做

**自由关系连线（节点 ↔ 节点任意箭头）**：与「一图多根＋树」的数据模型正交，要新增边表与增删同步；且竞品里使用率最低。P1 挂接/摘除解决的是**真需求**（把孤立的根连起来），自由连线解决的是**画法自由度**，不是一回事——除非以后要画流程图类内容。

**其它不建议**：强制转屏编辑（C13 已裁）、.xmind 导入（冻结口径只出不进）、多图缩略网格（需求明确不纳入首批）。

## §19 批P6 画布手势补强（2026-10-21 · 落到 Flutter）

### 19.1 为什么是这四件

§5 十条全部闭环后，产品点名「画布手势补强」。四条都不是新功能，是**手感债**：

1. **滚轮 / 触控板缩放**：桌面、投屏、平板外接键鼠场景里滚轮**完全没反应**（画布只认触摸）。
2. **按钮缩放的锚点错了**：两个缩放钮只改 `_scale`、不动 `_pan`，观感是
   「从画布左上角往外撑」——连点几次，刚盯的那一枝就漂出屏外。原型 `mmZoomBy`
   一直是「以画布中心为锚」，实现侧漏了。
3. **双击空白＝回全图**：大图缩到 25% 时一片糊，回全局只有摸右下那枚 fit 钮一条路；
   但 25% 档恰恰是小钮最难点的状态。
4. **缩得很小时节点点不中**：节点行高 40dp，25% 档只剩 10dp，远低于 44dp 触线下限。

### 19.2 落地清单

- **域层新增两个单位**（`mindmap_viewport.dart`，纯函数零 Flutter 依赖）：
  `mmMinScale/mmMaxScale`（25%~400% 只有一份口径）＋ `zoomAround(scale, pan,
  nextScale, anchor)`——**先钳后算**，顶到上下限时不会用未钳值算出假偏移。
  三处缩放入口（按钮 / 滚轮 / 捏合）全部走它，只有锚点不同。
- **新 part `mindmap_canvas_gestures.dart`**：`_zoomAt/_zoomCenter`、`_onPointerSignal`
  （`Listener.onPointerSignal` 收 `PointerScrollEvent`，折算 `exp(-dy/300)`：
  鼠标一格≈1.4 倍、触控板一格≈1.1 倍，且上滚/下滚互为倒数）、
  `hitNodeWithMinTouch`（最小可点面 44dp，重叠时取**中心最近**的那枚）。
- **双击空白＝fit**：接在 `_handleTap` 的空白分支上，判据＝「先前无选中 ＋ 位移 <32dp
  ＋ 间隔 <350ms」。第一击照旧只取消选中（未选中时那一下本就是空操作），
  所以双击不会白丢一次。
- **捏合也改走 `zoomAround`**：顺手把 `_pinchStartMid` 这个只在旧算式里用的字段删了。

### 19.3 一处**试了又回退**的改动（记下来免得后人再走一遍）

原计划还有第五件：**系统字号变大时盒宽跟着变**。做法是量宽键里加
`MediaQuery.textScalerOf(context)`、并在 `didChangeDependencies` 里检测字号变化重排。

**实测不成立**：`mmNodeMeasure` 压根不接 `textScaler`（`TextPainter` 未传），
画布文字走的是**样式弹层的 sm/md/lg 档**（12/13.5/16），不是系统档。
改量宽键不改变任何盒宽，`didChangeDependencies` 里那段是死代码。**整组已回退**，
原位留一条注释说明「系统档不进画布排版，无障碍走样式字号档」。
顺带把那条用例改成真正有意义的 `mmNodeMeasure` 三档单调递增（纯函数层）。

### 19.5 本轮新坑（测试侧，下一批复用）

1. **泵页面读「语义块尺寸」量不出字号差异**：`rectOf` 拿的是语义层 `SizedBox`，
   按节点盒走；测试字体替身又按固定字宽排版 ⇒ sm/lg 差不到 1dp。要让字号生效得在
   **量宽那一层**（`mmNodeMeasure`）断，不是在 widget 层断。
2. **测试里 `MediaQuery` 不设 `textScaler` 时，字体替身不加载字宽**（量出来恒 14px/字）。
   任何"盒宽随字号变"的断言在这种环境下都是恒等式。修法＝`pumpMap` 里统一钉
   `textScaler: TextScaler.noScaling`（显式钉比"不设"可读）。
3. **`tester.tap` 连点两次不算双击**：两次之间必须 pump 一帧，否则都落在同一帧的
   计时器上——能过，但不是真路径。
4. **`PointerScrollEvent` 在 `sendEventToBinding` 里可能按 `HitTestResult` 重定位**：
   hit test 被前面的 widget 吃掉时，事件位置会变成那个 widget 的左上角。
   所以「锚点没跑」的断言要么钉画布中心、要么完全用**比例关系**（左沿到锚点距离
   ÷缩放比 不变量），不要拿绝对坐标。
