# LifeHarness 开发计划书

> 依据：《需求清单 V1.3（冻结版）》｜原型：`prototype/index.html`
> 本计划书定义技术选型、架构、里程碑与排期。需求变更须同步更新本文件。

## 一、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Flutter 3.x（Dart） | 跨端、单代码库、预留 iOS |
| 状态管理 | Riverpod | 编译安全、可测试、依赖注入清晰 |
| 本地数据库 | Isar（首选）/ sqflite（备选） | 高性能 NoSQL、支持复杂查询与全文检索；若生态受限降级 sqflite |
| 图表 | fl_chart | 纯 Dart、PI/柱/线/热力覆盖需求 |
| 本地键值 | shared_preferences | 设置项 |
| 文件/附件 | path_provider、image_picker、file_picker | 图片压缩、导入导出选文件 |
| 通知 | flutter_local_notifications + timezone | 日程/任务/简报/复盘提醒、免打扰 |
| WebDAV | 自建基于 `http` 的轻量客户端（PROPFIND/GET/PUT） | 坚果云应用密码直连，避免重依赖 |
| 加密 | cryptography（AES-GCM 备份口令加密） | 同步/备份可选加密 |
| 农历 | lunar 或自建转换工具 | 重要日子农历需求 |
| Markdown | flutter_markdown | 笔记渲染/预览 |
| 小工具插件运行时 | webview_flutter + 本地 HTML/JS 工具包规范（plugin.json） | Dart 无法安全动态编译，WebView 沙箱方案可同时支撑「本地目录热加载」与「GitHub 链接下载安装」两种拓展（需求 V1.7） |
| AI 接入 | 无 SDK，Dio 直连 OpenAI 兼容 Chat Completions + flutter_secure_storage 存 Key | 一套协议适配 DeepSeek/Kimi/通义/智谱/OpenAI/Ollama；Key 系统级加密、不随备份/同步导出（需求 V1.8） |
| 公式渲染 | flutter_math_fork（KaTeX 语法） | 笔记 LaTeX 行内/块级公式实时渲染（需求 V1.9） |
| 账单导入 | csv 包 + 自研支付宝/微信表头解析器 + archive（zip 解压） | 两平台导出为 zip 加密 CSV，固定行数元信息前缀，规则解析可离线完成（需求 V1.9） |
| 插件平台（大模块插件化） | 声明式 UI Schema + QuickJS/WebView 双模式沙箱 + SQLite 隔离表空间 plugin_* + GitHub Release index.json/minisign/SHA-256/bsdiff 增量与回滚 | Flutter 不可动态分发 Dart；宿主能力 API + 插件薄层；需求 V1.15 六场景规范；试点：物品/影音游，V1.x 后段 GA |

> 建库策略：V0.1 即定义 待办/日程/日记/笔记 四核心表 **并预留** 健康/财务/物品 表结构与迁移骨架，避免后期数据迁移。

## 二、架构设计

采用分层 + 特性模块化（feature-first）：

```
lib/
├── core/            # 通用能力
│   ├── database/    # Isar 初始化、schema、DAO 基类
│   ├── theme/       # 主题、深色模式、字号
│   ├── router/      # 路由（go_router）
│   ├── notifications/ # 提醒调度
│   ├── sync/        # WebDAV 客户端、备份/恢复、加密
│   └── utils/       # 日期/农历/文件大小/哈希去重
├── features/        # 各业务模块，内部 model/data/domain/presentation
│   ├── dashboard/   # 模块6 仪表盘（首页）
│   ├── todo/        # 模块2 待办+四象限
│   ├── calendar/    # 模块1 日程+时间块
│   ├── journal/     # 模块3 日记+笔记
│   ├── reading/     # 模块4 阅读笔记+导入向导
│   ├── inbox/       # 模块5 收集箱
│   ├── finance/     # 模块8 记账
│   ├── items/       # 模块9 物品价值
│   ├── days/        # 模块11 重要日子
│   ├── health/      # 模块12 健康
│   └── settings/    # 通用/同步/外观/关于
├── shared/          # 跨模块联动服务（L1~L14 编排）
│   └── linkage/     # 例：SummaryService, CrossRefService
└── app.dart / main.dart
```

- **联动实现**：模块间不直接互相 import UI，通过 `shared/linkage` 中的服务 + 事件总线（Riverpod Stream/事件）解耦，保证可测试与低耦合。
- **数据流**：Repository 模式，UI ← Riverpod Provider ← Repository ← DAO/DB。

## 三、UI 与设计系统

- 以 `prototype/index.html` 为视觉与交互基准：主色 `#6366f1`（brand）→ 紫→粉渐变 `grad`；圆角 20px 卡片；深色完整适配（`.dark`）；底部 5 导航 + 悬浮球快速记录。
- 组件映射：原型中的 card / chip / seg-pill / toggle / sheet(底部弹层) / toast 在 Flutter 中封装为 `AppCard / FilterChip / SegPill / AppSwitch / AppSheet / AppToast`。

## 四、里程碑与排期（V1.16 重排 —— 基于全面评估的单人工时修正）

> 重排原因（评估发现 R-1）：原 V1.0 堆了约 12 个功能簇，单人 6 周容量超载约 40%；且插件平台要求宿主能力 API 在 V0.1 即预埋。现拆为 M0→M4 五段，总量约 29 周；每里程碑含交付物/验收/预案。估算为人工周，CC 协同可压缩处另行标注（通常 20–35%）。

### M0 · V0.1 骨架（3 周）
- 交付：工程初始化、**7 主题设计令牌体系（JSON 驱动，与原型 themes/ 同构）**、路由、DB schema（4 核心表+预留表+`plugin_*`命名规范）、**宿主能力 API 基线 v0（模块注册表/挂载点协议/事件总线接口，需求 V1.15 预埋）**、底部导航可配置、待办基础、日/周+格子日程（含**进行中事项两态流与悬浮计时条基础设施**）、纯文本日记、收集箱。
- 验收：对应需求清单第九章 AC（待办/日程/日历交互三行）；重启不丢数据；离线全链路。
- 预案：Isar 受阻 → 48h 内切 sqflite（Repository 已隔离）。

### M1 · V0.5 记录与写作（6 周，原 4 周上调）
- 交付：富文本/图片日记 + **INS 卡片流双模式（同源存储）**、心情/标签、四象限核心、纯写作笔记编辑器完整体（四模式/快捷栏/实时渲染/**flutter_math_fork 公式**/版本快照）、阅读计时+三方式进度+目录（手动/导入 3 格式，AI 补全留接口）、**习惯打卡完整实现（正/负向双模式+周月统计；自 V1.x 提前，与日程计时同源）**、本地通知框架（精确闹钟/通知权限降级链，见需求 8.4）。
- 验收：日记/笔记 MD/阅读计时/习惯四行 AC；14 项语法自测集入 CI。
- 预案：分屏大文档卡顿 → 渲染节流 + 段落级 diff 刷新；兼容底线 2000 字 <32ms/帧。

### M2 · V1.0 数据底座（8 周，原 V1.0 拆分之一）
- 交付：WebDAV 同步（断点续传/冲突双留/口令加密/历史回滚/限流退避）、本地备份 .lhbak、**数据导出（JSON/CSV/MD+附件，V1.16 补遗）**、今日仪表盘+自由编排、四象限智能规则、基础记账 + **支付宝/微信账单导入（含整批撤销）**、物品价值 v1（直线法+三态生命周期）、AI 基础设施（secure storage Key/验证工具/能力矩阵/**token 用量熔断与月度预算上限，评估补遗 R-5**）、全局搜索、重要日子+农历、睡眠/喝水、迁移自检与水位线时钟防护（需求 8.1/8.2）。
- 验收：同步断点续杀测试、300 条账单样本识别 ≥98%、AI 关机时 0 网络请求（抓包）。
- 预案：同步子系统超期 → 先交本地备份/导出（不阻塞主流程），同步降级为 beta 渠道。

### M3 · V1.1 内容与智能（6 周，原 V1.0 拆分之二）
- 交付：阅读导入全套（微信读书/Kindle/Notion/豆瓣书单·片单，三级去重）、**影音游基础版（与阅读同构代码复用）**、母婴完整（周期/排卵预测回测、八类记录、WHO 曲线、疫苗计划）、收集箱 AI 分流+日记反思+周报点评+目录 AI 补全（首批 AI 增强点，逐项灰度开关）、豆瓣式健康趋势入周报、L2/L4/L8/L12~L16 联动收尾。
- 验收：母婴/豆瓣清单/插件前同步类 AC；AI 每项能力带发送内容预览与确认。
- 预案：豆瓣解析不稳 → 解析器独立数据包化（为 M4 插件化预验证格式兼容策略）。

### M4 · V1.x-advanced（6–8 周，可切分销项）

## 五、开发规范

- Dart lint（`flutter_lints`）+ 命名规范；每 feature 独立可编译。
- Git：`main` 保护，`feat/xxx`、`fix/xxx` 分支；提交遵循 Conventional Commits（`feat:`/`fix:`/`docs:`/`refactor:`/`chore:`）。
- 版本号语义化 `V主.次.修`，每次发版打 tag。
- 每个联动（L#）与导入解析器需附单元测试。
- 隐私红线：V1 除 WebDAV 外无任何网络请求；密码/应用密钥不落日志。

## 六、风险与应对

| 风险 | 应对 |
|---|---|
| 微信读书导出格式多变，解析易失败 | 解析器按模板版本适配 + 字段映射预览 + 失败容错入库为普通笔记；导入向导可手动纠正 |
| WebDAV 多设备冲突 | V1 保守：逐条人工选择，不静默合并；保留历史快照可回滚 |
| Isar 在部分平台维护风险 | Repository 层隔离，保留 sqflite 备选实现切换 |
| 模块多导致范围蔓延 | 严格按里程碑冻结；新想法进《需求清单》待排期，不入当前版本 |
| 农历/时区计算错误 | 采用成熟库 + 边界用例测试（需求 8.1 日期规范） |
| Android 12+ 通知/精确闹钟受限（评估新发 R-2） | 降级链：近似闹钟→应用内角标；首次启动引导页集中申请权限；各提醒类 AC 含降级路径验收 |
| 插件 UI Schema 表达力不足（评估新发 R-4） | 双模设计可降级 WebView 全页；两试点均不达标则收回内置，插件平台保留小工具/解析器/主题三层，沉没成本约 4 周可控 |
| AI token 成本失控（评估新发 R-5） | 每能力独立开关 + 月度 token 预算上限 + 超限自动熔断只读；调用面板展示用量 |

### 7.1 模块预发布流程（2026-09-19 起强制执行，用户制定）

**每完成一个大模块功能**（待办/日程/日记/收集箱/同步等粒度；小修复与保真补丁不算），
在推送 GitHub 分支后，**必须同时创建一个 GitHub 预发布（prerelease）**：

1. **构建 APK**：从已提交的模块 HEAD 重新构建，保证发布物与提交一致。
   本机需先移除 `FLUTTER_STORAGE_BASE_URL`（tuna 镜像 download.flutter.io 路径 404，见《交接文档》TODO-4）：
   `powershell -Command "Remove-Item Env:FLUTTER_STORAGE_BASE_URL; flutter build apk --debug"`
2. **命名**：tag `v0.1.0-m0.<模块名>`（如 `v0.1.0-m0.calendar`）；APK 副本重命名为
   `lifeharness-<模块>-debug.apk` 上传（仓库 `.gitignore` 已排除 `*.apk`，副本传完即删）。
3. **创建 release**（含功能描述 + APK 附件）：
   `gh release create <tag> <apk> --prerelease --title "M0 预发布 · <模块>（业务编号）" --notes-file ...`
   notes 固定结构：①本版本内容（对齐原型的保真点清单 + 提交号）②已具备能力 ③已知占位项（后续里程碑）④安装要求（Android 8.0+/minSdk 26/纯本地无账号）。
4. **验证**：release 页面 APK 资产可见、tag 指向模块提交；随后删除本地 APK 副本。

首个示例：`v0.1.0-m0.calendar`（日程模块，2026-09-19）。
