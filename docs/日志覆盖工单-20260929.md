## 二、为什么这三块 core 优先于 11 个 feature

1. **core/database**：schema 迁移与数据修复是跨设备排查的唯一线索，目前炸机只留全局兜底的一行异常，
   没有版本号与影响行数——V1.4x 多次「升级后数据不对」类反馈都缺这条。
2. **core/backup**：`.lhbak` 导出/导入/口令校验失败现在完全静默，用户侧表现为「备份没生效」。
3. **core/notifications**：通知排程降级链（精确闹钟→普通→被系统杀）按设计要可查，目前无从取证。

feature 侧多为「表单写库 + 列表渲染」，异常基本会被全局捕获；补日志的价值在**业务上下文**
（哪个实体、哪次操作），按模块随批补即可，不必专项突击。

## 四、是否加架构守护（待拍板）

候选规则：`features/*/data/**` 与 `core/**` 内的 `catch (` 块中必须出现 `AppLog.` 调用，
否则 `architecture_test.dart` 判红（R9）。

- 优点：空档不会再长回来。
- 代价：现网 catch 数量大（含大量有意吞掉的清理型 catch），首跑会一片红，
  需要「白名单 + 逐批收敛」，本身会产生一次大 diff，与「纯移动」纪律冲突。
- **建议**：先按 L1~L5 铺完再上守护；过渡期用软约束＝本单 + §2.3 + PR 自查项
  「新增 catch 是否记了日志」。等你点头我再进 `architecture_test`。

   - **已上线（2026-09-29 · L1~L5 收口后）**：`test/catch_log_guard_test.dart`。判定面四条——①块内 `AppLog.add/addKey/addStack/reportError`；②`rethrow`/`throw` 上交（全局兜底已统一记）；③同前行或上一行有 `catch-ok: 理由` 注释（`//` 与 `/* */` 都认）；④`core/logging/**` 基建豁免（记自己会递归）。其余＝静默吞噬，必须进 baseline 登记（登记值＝该文件当时违规数），**只许减不许增**，清零请删项。覆盖面含**不带 catch 的 `on X { … }` 回落**（这类最容易静默）；`extension X on Y {` / `mixin M on Y {` 靠「`on` 必须紧跟 `}`」排除——首版没这条时把 4 个 extension 误判成了异常块，登记面虚增到 142 处，正对照样本把它照了出来。上线实测存量 **108 处 / 51 文件**（read 42·kits 5 属并行会话写区，由各自留痕批次消项）；`CATCH_GUARD_DUMP=1 flutter test test/catch_log_guard_test.dart` 可重生成登记面；「扫描面骤减即红」+ 合成样本正对照两条防守护空转。
3. **L2~L5 按序排后**，每批独立走三门禁（analyze 基线 / 模块 mini 池 / 全量 run_gate），维持「只加日志零行为改动」纪律。
   - **L2 已交付（2026-09-29）**：纪律守住——`catch (_)` 改 `catch (e)` 只为把异常写进日志文本，控制流一字未动；新增日志一律走 `AppLog`，未开第二条通道。
   - **L3 已交付（2026-09-29 续批）**：同纪律。三域里 calendar/todo 原本**零 catch**（异常直接抛给 Riverpod 吞成 `AsyncError`，UI 侧 `valueOrNull ?? 默认值` 表现为「空列表/角标 0」），所以新增点分两类：失败路径一律 `catch (e)` 记完 `rethrow`（控制流未动），成功路径只补 key 汇总行。**自证口径再补一条**：Provider 体内的失败日志必须按文案去重——失败态每次 rebuild 都会重跑 provider，不去重会刷屏；FakeAsync 下 `AppLog` 的 300ms 节流 Timer 要显式推进才到期，故 settle 之后补一次 `helpers.dart` 新增的 `drainLogTimer(tester)`（`time_v152_test`／`g1_back_probe_test`／`dashboard_days_items_test` 三处，顺带暴露这三处都没 override 待办仓储、读取其实一直失败并被当成空列表）。
   - **L4 已交付（2026-09-29 续批）**：同纪律（`catch (_)` 只为写日志改 `catch (err)`，控制流一字未动；两处表达式体方法改 async 块仅为落日志，返回值不变）。**新增一条硬约定**：仓库层落 key 行以后，模块内**每个** widget 用例末尾都要 `await drainLogTimer(tester)`——本批用 `tools/l4_test_drains.js` 一次性补齐 17 个文件 99 处（脚本按「同层 `});` 回溯同层 `testWidgets(`」定位，注意 `group` 收尾同为 `  });`，缩进不同层不可混判）。`tearDown(AppLog.reset)` 这条路**试过不成立**：定时器不变式在包级 tearDown 之前校验。
   - **L5 已交付（2026-09-29 续批）**：同纪律。两条新自证口径进 §四/§五：① **随读触发的汇总行必须按变化去重**（`syncDerived` 每次 `loadAll` 都跑，不去重＝打开一次刷一行）；② **纯表达式体方法（`=> db.transaction(...)`）要落日志必须改块体**，且日志放事务提交之后才不虚报——本批 `bumpKr`/`addItem`/`addExtraPay` 三处即此形（内容一字未动）。
   - **工装两条（写死在 `tools/run_gate.sh` 注释里）**：① `sqlite3.dll` 拷贝冲突（errno 183）会让 `flutter test` 启动即崩、表现为成片「找不到 dll」，**只在 gate-err.log 出现 PathExistsException 时**摘除该产物再重跑；② 反过来，**预防性地删这个 dll 会制造假红**——最早并发起来的若干测试文件会在重拷贝完成前解析 `sqlite3_initialize`（errno 126），本批实测埋了 8 个假红后才改回。
4. 交付门新增一条自证：**来源归类必须核对**——异步回调（如 sqflite `onCreate/onUpgrade`）的调用帧里没有业务帧，`_deriveSrc` 会落到「系统」，需要时显式带 `src`。
