## 一 · 同表混放软删（回收站）与「源码级谓词守护」

**元信息**

| 项 | 值 |
|---|---|
| 域 | mobile（任何关系型库 + 单表软删场景，与 Flutter 无强绑定） |
| 问题 | 表里既有在册行又有回收站行，漏一处 `WHERE` 就是「删掉的数据还在计数/还在提醒」 |
| 方案核心 | 统一 DAO 出口 + 一条**扫源码**的守护测试（不依赖运行时数据） |
| 成本 | DAO 五件套约 40 行 + 守护测试约 90 行 · 零运行时开销 |
| 本项目出处 | `lib/features/todo/**`、`lib/core/database/schema*.dart`、`test/todo_trash_guard_test.dart`（提交 `a110e9d`） |

**一句话定义**：给软删列（`deleted_at INTEGER`·NULL=在册）配一个「扫 `lib/**` 源码找裸表名」的守护测试，让「漏加谓词」在编译前就红灯，而不是等用户发现幽灵数据。

**编号规则**

- **S1 迁移只加列不动数据**：`ALTER TABLE t ADD COLUMN deleted_at INTEGER`；用例必须断言「迁移后既有行 `deleted_at` 恒为 NULL」——默认值写成 0 会让全部旧行被当成已删除。
- **S2 谓词只有一个出口**：在册读取（`list`/`count*`）一律在 DAO 内加 `deleted_at IS NULL`；垃圾箱读取用反谓词 `IS NOT NULL`；业务层禁止裸 SQL 点名表。
- **S3 恢复＝同一条目**：`restore` 只把 `deleted_at` 置回 NULL，绝不新建行（否则历史 id/关联/排序全断）。
- **S4 硬删通道保留且分离**：`remove/purge` 走真 `DELETE`，与软删入口在 UI 上分处两级（行内钮 vs 确认弹层）。
- **S5 到期清理在冷启动跑**：`purgeExpired(keepDays)`·`keepDays<=0` 直接返回 0（「不清理」档），并落一条 key 级日志（删除 N 条 · 保留期）。
- **S6 守护测试三段式**：① 白名单外裸表名必须含谓词；② **白名单失效自检**（登记的文件不再点表名就报红，防守护空转）；③ DAO 内部自检（`list()` 体内确有 `deleted_at IS NULL`、五件套方法齐全）。

**实现骨架**

```dart
// DAO：在册 / 垃圾箱 / 软删 / 恢复 / 彻底删 / 到期清
Future<List<T>> list() => db.query(table, where: 'deleted_at IS NULL', orderBy: '…');
Future<List<T>> trashed() => db.query(table, where: 'deleted_at IS NOT NULL', orderBy: 'deleted_at DESC');
Future<void> softRemove(int id) => db.update(table, {'deleted_at': now, 'updated_at': now}, where: 'id = ?', whereArgs: [id]);
Future<void> restore(int id) => db.update(table, {'deleted_at': null, 'updated_at': now}, where: 'id = ?', whereArgs: [id]);
Future<int> purge(List<int> ids) => db.delete(table, where: 'id IN (${List.filled(ids.length, "?").join(",")})', whereArgs: ids);
Future<int> purgeExpired(int keepDays) => keepDays <= 0 ? Future.value(0)
    : db.delete(table, where: 'deleted_at IS NOT NULL AND deleted_at < ?', whereArgs: [cutoff]);
```

**验收清单**

- [ ] 迁移用例：v(n-1) 结构 + 旧行 → 跑迁移 → 断言行数/列值不变、`deleted_at` 为 NULL。
- [ ] 联动断言（照抄原型校验脚本那条）：软删后「清单/看板/今日数字/逾期计数」四处同时减一，且表里行仍在。
- [ ] 恢复用例：断言 `id` 不变、象限/截止等原列不变、垃圾箱清空。
- [ ] `purgeExpired` 三条：超期删 / 界内不删 / `keepDays=0` 一条不删；边界带 1 分钟余量（内部再取一次 `now`，卡整日数会因毫秒推进翻面）。
- [ ] 守护测试自证：临时造一个裸查询文件 → 红 → 删除 → 绿；临时把白名单改成不存在的路径 → 报失效。
- [ ] 期限档位「选后即时回显 + 真落盘 + 冷重载读回」三条都在（只改 Provider 态＝重启回默认，属假承诺）。

**已知坑**

| 坑 | 根因 | 处置 |
|---|---|---|
| 守护正则漏匹配 | 项目里表名既写 `DbSchema.tTodos` 也写 `$tTodos`/`'todos'` | 模式并集：`tTodos|'todos'|"todos"`；上线前先跑一遍确认命中数>0 |
| 守护假绿 | 白名单里的文件改名/删表名后不再命中，条目变死配置 | 加「白名单失效自检」（本项目 S6②） |
| 注释被算成违规 | DDL/说明注释里出现表名 | 扫描跳过 `//`、`///`、`*` 开头行 |
| 边界用例随机红 | `purgeExpired` 内部第二次取 `now`，与用例种子差几毫秒 | 断言带 1 分钟余量，别卡 `keepDays` 整点 |
| 排序/统计被回收站污染 | `MAX(sort_order)`、聚合 SQL 忘了谓词 | 全表聚合函数也要过一遍谓词审计（本项目 goals KR 即此类） |
| 「不清理」档被写死成默认 | UI 文案与档位来源不同步 | 期限文案做 getter（`trashKeepTxt`），入口行/屏头/toast 三处同源读它 |

## 二 · 长图分享公共通道（RepaintBoundary → PNG → 真实路径回执）

**元信息**

| 项 | 值 |
|---|---|
| 域 | mobile · Flutter |
| 问题 | 各页各自实现「分享」，多数停在 `toast('已保存（模拟）')`；真落盘时出图宽度/文件名/键盘遮挡各处不一 |
| 方案核心 | 一个 `captureShareCard()` + 一个 `ShareCardModel/View` + 一个底部弹层，六站点共用 |
| 成本 | 单文件约 300 行 + 用例 6 条 |
| 本项目出处 | `lib/shared/widgets/share_card.dart`（提交 `ff57199`） |

**一句话定义**：把「要分享的卡片」包进 `RepaintBoundary`，按目标宽度反算 `pixelRatio` 出 1080 宽 PNG，落应用文档目录 `share/<净化名>.png`，提示条**回显真实路径**。

**编号规则**

- **C1 出图宽度反算**：`pixelRatio = 1080 / boundary.paintBounds.width`，而不是写死 3；设计宽（本项目 640）1:1 布局，预览用横向滚动而不是缩放。
- **C2 边界链上禁止祖先变换**：`FittedBox/Transform/ScaleTransition` 会让栅格化按变换后的尺寸算，实测出图 1364 宽（非 1080）。用例直接断言 PNG 宽度。
- **C3 文件名净化**：剥 `\/:*?"<>|` 并 trim，防路径穿越与 Windows 非法名。
- **C4 回执只说真话**：成功=`已保存：<绝对路径>`；失败=写日志 + 「生成失败 · 详见日志」，禁止「已保存到相册」这类没做过的事。
- **C5 文字版并列提供**：同一 model 生成 `〔段名〕…` 纯文本，复制与存图两条出口同源。
- **C6 弹层内反馈**：模态层里挂页面级 SnackBar 看不见——先 `pop` 再 `messenger.showSnackBar`，或在弹层内做状态行。

**实现骨架**

```dart
Future<String?> captureShareCard(GlobalKey boundary, {required String name, String? src}) async {
  final ro = boundary.currentContext?.findRenderObject() as RenderRepaintBoundary?;
  if (ro == null) return null;
  try {
    final img = await ro.toImage(pixelRatio: 1080 / ro.paintBounds.width);
    final bytes = (await img.toByteData(format: ImageByteFormat.png))!.buffer.asUint8List();
    final f = File('${docsDir}/share/${sanitizeShareName(name)}.png');
    await f.parent.create(recursive: true);
    await f.writeAsBytes(bytes);
    return f.path;
  } catch (e) {
    AppLog.warn('分享长图生成失败：$e'); // catch 必带交代（守护测试）
    return null;
  }
}
```

**验收清单**

- [ ] 出图后读文件头断言宽度 == 1080（不是「存在且非空」）。
- [ ] 断言提示条文本**含真实路径**，且全仓源码扫描无「（模拟）/已保存到相册」字样残留。
- [ ] 落盘是真实异步 I/O：只在 `tester.runAsync` 里点按钮，配合 `pump(30ms)` + `Future.delayed(30ms)` 交错（FakeAsync 下栅格回调永不返回）。
- [ ] 轮询到 `lengthSync() > 1000` 而不是 `existsSync()`（存在但 0 字节的中间态会假过）。
- [ ] 隐私开关同口径：金额/敏感字段遮蔽状态要传进 model（`amtText(hide:)`），不能分享卡里又露出来。

**已知坑**

| 坑 | 根因 | 处置 |
|---|---|---|
| 出图 1364 宽 | 祖先链有 `FittedBox` 缩放 | 卡片 1:1 布局 + 预览横向滚动；断言宽度 |
| 测试 `file exists == false` | tap 链在 FakeAsync 下停摆，栅格回调排在真实事件循环 | 整个 tap+轮询放 `runAsync`，交错 pump |
| 存在但空文件 | `writeAsBytes` 中间态 | 轮询到字节数达标 |
| 覆盖 `flutter/platform` 整通道 mock 判成功 | Title/SystemSound 消息也走该通道 → `FormatException` | 别 mock 整通道，改断言 UI 结果 |
| 弹层里 toast 看不见 | 模态层压在页面 SnackBar 之上 | 先关弹层再 `messenger.showSnackBar` |

**复用清单**：任何 Flutter/原生 Android 应用内「生成分享图/报表图落盘」场景。与 `engineering/module-prerelease-delivery-sop` 无交集；与「提示条只说真话」这条行为规范同源（假承诺文案一律摘除）。
