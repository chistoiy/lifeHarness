### 批3 过程留档（可复用判据）

- **自写编码器要用两个独立解码器交叉取证**：`dart:ui` 只回答「能不能解」，Pillow/libjpeg 才回答「解出什么像素」。本轮三处口径全靠外部解码器抓出：① 正交归一 DCT 的 `a(0)=1/√8`（写成 `1/√2` 时 DC 放大 4 倍，纯色亮度 200 被还原成 0）；② DC 频次必须按**差分链**统计且与编码遍逐条对应——Cb 与 Cr 各有一条 prev，合用一条会让 Cr 的差值口径变成「相对上一块 Cb」；③ 规范码跳档是 `cur = cur << Δlen`，写成 `(cur+1) << Δ` 只有出现长度跳档的表才出错，于是「纯色图绿、彩色图丢色」，最容易误判成算法不行。
- **现场生成 Huffman 表必须留空洞**：码表完备（Kraft=1）时规范码最后一个必为全 1，而 JPEG 禁止分配全 1 码字；判据是算 Kraft 和，等于 1 就把最长类里最后一个符号加长一级。两符号表与跳档表是两类踩点。
- **一片 FAIL 先自证工装**：本轮为定位丢色写了临时解码探针（段结构 + 熵码流逐 MCU 解），先确认探针能解官方样例再信它的结论；探针落 `%TEMP%`，用完即删，不进仓库。
- **屏侧读数只引真实字节**：WebP 没有纯 Dart 编码器，就显式给「待接入系统原生通道」并仍按 JPEG 真压、文件名照实 `.jpg`——比按原型的 `.webp` 假标注诚实。凡是界面出现的 KB/百分比/字符数，都必须能追溯到一次真实编码的返回值。
- **红线与写区冲突时优先补通道而非绕红线**：批3e 需要真实发请求，但 R7 禁 features 直取 `aiServiceProvider`。处置=新增 `core/ai/ai_verify_channel.dart`（不碰任何既有 core 文件，也不与并行会话争写区），函数形状与 `aiRunWithReview` 同构；屏侧经静态缝调用，测试注入假结果，零网络。
- **带周期 Timer 的全屏舞台：先暂停再 `settle5`**：`pumpAndSettle` 等的是「没有帧被排」，16ms 定时器永远在排帧 → 直接超时。滚动位移用 `tester.getTopLeft(bodyKey).dy` 断言；横向（`RotatedBox`）会把位移映射到 x，所以位移用例先切竖向再量。
- **共享小文件一次成型 + 立即局部提交**：`kit_tools_kit.dart`/`kit_tool_page.dart` 是各批都要改的窄门，本轮做法=一个文件一轮写完，写完 `git add` 与 `git commit -- <路径>` 同一调用内完成，避免并行会话的暂存区状态被卷走。

### 批2 过程留档（可复用判据）

- **公有字段当 key 用要写 `ValueKey<String>(name!)`**：`ValueKey(keyName)`（keyName 为 `String?` 字段）得到的是 `ValueKey<String?>`，与测试里的 `find.byKey(const ValueKey('x'))` **不同型不等值**，表现为「widget 明明在树里、finder 却说找到 0 个」。局部变量能被流分析提升所以不踩，字段不能——本批 18 例里三处红全是它。
- **转盘/旋转类动画别把绝对角度写进 `AnimationController.value`**：controller 的 `upperBound` 默认 1，越界赋值让 `pumpAndSettle` 永不收敛（表现为 `pumpAndSettle timed out`，而不是断言失败）。正解：controller 只在 0~1 跑归一进度，角度用 `_from + (_to-_from)*value` 在监听里算，收尾把 `_from` 收到 `_to` 再复位 controller。
- **图片/解码类工具屏留两个静态缝**：`KitPick.imagePicker`（取路径）与 `KitPick.decoder`（路径→RGBA），widget 测试注入固定小图即可覆盖「点图取样→加入取色盘」全链路，零真异步 I/O；原生字节读不到时退化为按像素画网格（`_PixelGrid`），测试与生产共用同一命中公式。
- **色彩链保持浮点、只在展示层取整**：原型的 `cmpShow` 把浮点 HSL 直接喂 `hsl2r`，若在中间步骤 round，`S+4` 之类的相对量会漂移 1 档；断言因此用 `closeTo(…, 1)` 而不是逐色相等。

### 反馈轮4 过程留档（可复用判据）

- **主工作区被并行会话改到编译不过时，门禁要在 HEAD worktree 里跑**：本轮 `lib/features/care|ledger` 有他人在途半成品（`ledger_notify.dart` 未落定、`care_remind_page.dart` 引了还不存在的方法），主树里任何整包 widget 测试都会以「loading … Compilation failed」红掉，看起来像本批引入的回归。做法：`git worktree add ../lifeHarness-kits4 HEAD` → 只覆盖本批文件（含删除）→ 在那儿跑 284 例。注意 `git status --porcelain -- test` 会把别人的新用例一起列出来，覆盖时按 `kit_*` 前缀收窄，别把外会话文件带进隔离区。
- **一次性自动收起定时器会让用例中段行为不可复现**：提词舞台进入 1.8s 后收起控制条是一次性 `Timer`。若用例在 1.8s 内去点底部控件，`IgnorePointer` 会让点击落到舞台上，表现为「点了没反应」而不是报错。定式：先 `pump(>窗口)` 让一次性定时器落地，再断言「点按唤回」，此后状态只跟随点按。
- **转屏可在 widget 测试里取证，但参数是枚举全名**：`setMockMethodCallHandler(SystemChannels.platform, …)` 抓 `SystemChrome.setPreferredOrientations`，收到的 args 是 `['DeviceOrientation.landscapeLeft']`，不是 `DeviceOrientation.landscapeLeft.name`；断言写 `.name` 会假红。
- **摘一件内置工具是四处联动**：登记表 `kKitTools` + 分类枚举 `KitCat` + `kitToolBody()` 插槽 + 用例里的样本键（首页卡数、分类 chip key、收藏弹层、隐藏列表、统计分布）。老数据不删：`kit_usage` 里的 `ping`/`speed` 足迹靠 `kitToolOf` 返回 null 走兜底（`kitCountByCat` 归入演示、工具屏外壳显示「工具未登记」），这条要有用例兜着。
- **原型 HTML 是 CRLF**：脚本改它时多行锚点必须先 `\r\n → \n` 再打锚、写回时还原，否则「命中 0 次」会被误读成锚点写错。（本轮 `rs-land` / 提词器整段替换都走这条。）
- **kits 用例不许钉死全局 DB 版本号**：`kit_schema_test` 原来写 `expect(DbSchema.version, 28)`，并行会话一升到 v29 就把 kits 门禁撞成假红。改为 `greaterThanOrEqualTo(28)`（只守「kit 四表自 v28 起建」这条真实约束），版本等值由 `database_schema_test` 自己守。

### 批0/批1 过程留档（可复用判据）

- **两档提速里的「批内增量」不等于跳过测试**：批0 的 40 例、批1a 的 9 例都是先写实现再补断言，但每条断言都锚在 `ValueKey` 上（`kit-hero-slot-*` / `kit-cfg-*` / `kit-set-*` / `kit-fav-*` / `kit-recent-*`），后续批次改版式不会连带改测试语义。
- **两段式破坏性按钮必须持 `Timer` 并在 `dispose` 取消**：`Future.delayed` 的 4 秒武装态回退定时器会让 widget 测试收尾报「A Timer is still pending」（本轮第一次红就是这个）。
- **`dart format` 只对新文件用**：对 `lib/core/settings/*.dart` 这类共享热点整文件格式化，一次制造 223 行噪音 diff；处置=回退文件、用命中数断言脚本在 HEAD 基线重放编辑，再逐处核对 `git diff --numstat` 只增不改。
- **并发跑测试会崩在 `native_assets/sqlite3.dll` 硬链**（Flutter tool `PathExistsException` errno 183），且两会话同工作区时别人的中间态会让本会话编译失败：`tools/ftest.sh` 负责退避重试，遇到非本会话文件的语法错直接复跑。
