# X-Ray 词条质量治理计划（V1.54.1 · 2026-10-02 立项）

> 定案口径（2026-10-01~02 产品负责人逐条拍板，本文为唯一执行依据）：
> ① **人名合集（名人表）不做**——1MB 体积不合算，不进任何批次；
> ② 精度提升走「**用户养数据**」路线：阅读期间选中的实体可加入/屏蔽，词库全量可管理（增删改查）；
> ③ 导出分两部分：**预置词库（公共基准标识）＋用户养起来的数据**；
> ④ X-Ray 中可选**是否启用**用户养起来的数据；
> ⑤ 选区工具条 X-Ray 必须直达该实体（已修，见批1）；
> ⑥ 解析实体可走 **AI API 精化**，但**每请求体量必须可控**（免费 API 上下文小，一次传不下）。
> 承接：`docs/真机逐屏验收清单-20261001-xray实现批.md` §9-4（词条质量：人类简史榜首多为通用词、人名仅 15~30 枚、机构 2 枚）。

## 0. 背景与根因（证据）

真机两书走查暴露的「数据不好看」三层根因：

| 根因 | 证据 | 后果 |
|---|---|---|
| 词表资产是**预研探针级** | `assets/xray/dicts/`：常用词表 **99 词**（小说味，非虚构不适用）、地名表 **110 条**、全库 <10KB（`xray_lexicon.dart:12` 自注「GT 挂在这批词上」＝为阿加莎小说定制） | 通用词无防线 |
| 术语通道无「通用高频词」先验 | `xray_engine.dart:364-407`：过滤链只有虚词(240)→常用词(99)→PMI（**仅查 ≥3 字**）；计分 `√n×idf`（`:484`）放大高频通用词 | 「几乎/概念/造成」霸榜 |
| 人名通道靠对话动词+姓氏边界两正则 | `xray_engine.dart:205-208`；预研「已知名人集」锚定未移植（通道1d 退化为称谓路由 `:421-447`） | 非虚构书人名召回低 |

## 2. 批1 · 选区直达修复（已交付 `c0166a9`）

用户真机口径「选中实体点工具条 X-Ray，还得手动再查一次」。F6 链路（`xrSelToLearn`）其实早已实现，哑火是两个缺陷叠加：

1. `_xrSelLookup` 只传词条名，面板按 `e.name == focus` **全等匹配**——选中文本与词条名不一致（模糊命中）必落空；
2. 接力一次性标志在**面板首帧**消耗，而 `xraySnapProvider` 异步加载，首帧快照为空 → 匹配打在空列表且**永不重试**。

修法：新增 `readerXrFocusIdProvider`，迷你卡传词条行 id、面板按 id 定位；词降级为回退（全等→互含，与 `dao.searchEntities` 命中判同式）；接力拆两半——加词弹层照旧首帧消费，直达详情等快照 `hasValue/hasError` 再消费。
测试：`test/xray_sel_relay_test.dart` 5 例（闸门快照竞态回归/id 失效回退/互含回退/加词接力不回归/全落空不炸）；回归 xray_panel 37 例 + reader_select + reader_ui/xray_backup 15 例全绿。

## 3. 批0（可选）· 通用高频词表

top 5000~8000 通用高频词（开源词频数据，约 100~150KB 资产）进常用词表过滤层，`looksCommonNoun`（`xray_lexicon.dart:167`）一处拦截，**零判定逻辑改动**；用户加词救回优先级已高于常用词表（现有机制兜底）。

与「用户养数据」的关系是**互补不是替代**：预置拦大头（省得用户逐条屏蔽榜首通用词），用户兜长尾。砍掉不影响批2~4。

> ⚠️ 红线：`xray_engine.dart:5-6` 明示 GT 基线挂在现有词表上。**动任何词表资产前必须先扩 GT**——新增「人名召回 GT」（人类简史全书人工标一批）+「通用词噪声 GT」（榜首 20 条含通用词 ≤2 的口径），再换资产，否则批1e golden 失效＝回归裸奔。

## 4. 批2 · X-Ray 词库管理页 + 启用开关（原型先行）

**管理页**「X-Ray 词库管理」（入口：阅读设置「本地阅读器」分组 + X-Ray 面板 ⋯ 菜单行）：

- 数据源 `xray_userdict WHERE scope=GLOBAL`（全局养成层）；
- 列表行：词 / 类型徽 / 动作徽（加词·屏蔽·并词）/ 来源书 / 时间；
- 操作：搜索、按类型筛选、**编辑**（改名/改类型）、删除、并词、屏蔽⇄加词切换、批量操作；
- DAO 补 list/update/delete 接口（现有 `markDeleted`/`mergeInto`/`promoteWordToGlobal` 复用）。

**启用开关** `read.xrUserDict`（全局，管理页 + 面板头快捷两处）：

- 开（默认）＝现状养成视角；
- 关＝**纯预置视角**：展示层过滤 user_added、无视用户屏蔽状态位，后续解析不再叠加用户层；
- 语义钉死：已物化的状态行**不回滚**——关只是「预览原始引擎结果」，重开即恢复，需彻底回纯预置就重置索引。此条随批2 登记进需求清单，防止歧义。

**选区 X-Ray 优先级（批2修③ 用户拍板 2026-10-02）**：命中＝直达面板定位实体（迷你卡中转迭代掉）；未命中＝面板带入搜索＋空态加词入口，屏蔽不前置（收在词条详情与管理页）。

**原型改动清单**（`prototype/index-bookshelf.html`）：①管理页新屏（词库列表+操作+开关行）；②面板 ⋯ 菜单加「词库管理」行；③面板头开关快捷位；④选区未命中弹层二选一形态。校验照 `tools/xraycheck.js` 惯例补断言。

## 5. 批3 · 用户词库导入导出（原型先行）

新分享格式 `.xrwords`（JSON）＝**两部分**结构：

```json
{
  "v": 1,
  "preset": { "version": "…", "files": {"func_words.txt": "<sha>", "…": "<sha>"} },
  "entries": [ { "word": "…", "type": "per", "action": "add", "target": null,
                 "pattern_hint": null, "src": "…", "ts": 0 } ]
}
```

- `preset` 段＝预置词库**只读基准标识**（8 张资产文件名+sha+版本），随文件走供对端比对，不可导入覆盖资产；
- `entries`＝用户养起来的数据（GLOBAL 全量），**只进 GLOBAL 层**、不碰按书覆盖层；
- 导入＝逐条 upsert（撞 `(scope,word,action)` 唯一索引则覆盖并计数），完成报「新增/覆盖/跳过」；
- 与既有 `.xraybak`（单书四表迁移）各走各路互不影响；SAF 钩子复用 `XrayBackupService` 注入模式（widget 测试不触平台通道）。

**交付登记（2026-10-02 · `6f9c3ae`）**：`XrayWordsIoService`（`lib/features/read/data/xray/xray_words_io.dart`）
+ `XrayDao.importGlobalDict`/`XrayDictEntry` + provider `xrayWordsIoProvider` + 管理页 `xrwIoCard`
（`xrwExp`/`xrwImp`，导入走预检弹层 `xrwImpGo` 确认后才落库并回读）+ 原型 `p-xrwords` 导入导出两行
+ xraycheck 批3 断言（**40 绿/0 红**·跑法 `node --experimental-websocket tools/xraycheck.js`，本机 node v20.18 无全局 WebSocket 必须带该 flag）。
测试 11 例（`xray_words_io_test` 6 + `xray_words_page_test` 5）、回归池 29 绿、analyze 本批六文件零新增。
**与本章原稿的三处偏差（有意保留）**：① 预置基准标识落的是 **FNV-1a 63 位非加密指纹**（纯 Dart 零依赖·仅比对用途），
不是原文写的 sha，段形态为 `preset:{id, files}`（`id`＝八表指纹串起来的汇总值，无 `version` 字段）；
② `entries` 不带 `src`（来源只在本机 GLOBAL 行展示，随包无意义），携带 `word/type/action/target/pattern_hint/ts`；
③ 类型归一放在解析层（`parseEntries` 把未收录词类归 `null`），DAO 保持哑存储不校验；
非法动作 `merge_pair` 与空词在两层都计「跳过」，整包一事务不中断。

## 6. 批4 · AI 精化（R8 登记 + 原型先行）

- 能力点 **`read.xray_refine`** 登记（R8 门）；走 `aiRunWithReview` 单入口（R7 门）；`ai_calls` 自动留痕；未配 Key/离线时行为＝现状。
- **每请求体量控制**（本次拍板重点）：新增设置 `read.xraiBatchChars`（单请求字符预算，**默认 3000 字**≈免费 API 4k 上下文安全线，用户可调）；每候选只携带「名+类型+频次+跨章数+1 条 snippet（截 60 字）」，按预算自动切批；**顺序请求并发=1**（对免费 API 温柔）；批间落 checkpoint，支持暂停/续跑/单批失败重试不拖垮全书。
- 流程：面板 ⋯「AI 精化」→ 预检卡（候选数/预计批次数/预估 token）→ 逐批跑 → 汇总审阅弹层（建议删 N 词/改类 M/补 K 个）→ 确认后写 `xray_userdict`（**默认本书 scope，可一键升级全局**）——AI 结果从此归入用户资产，随批3 导出分享。
- 响应防御：JSON 解析失败重试 1 次后跳过该批；超时/断流不阻塞其余批。

**原型交付登记（2026-10-02 · `dd9a5ac`·待确认门）**：`index-bookshelf.html` 落三屏——`sheetXrAiPre` 预检卡（候选/预计批次/tokens 三数 + 单请求预算五档 chips 默认 3000，
就地选即时重算）、面板段内 `#xrAiBar` 逐批进度（条宽=b/n · 暂停↔继续并报断点第几批 · 第 4 批失败行「已重试后跳过，后续批次继续」）、
`sheetXrAiReview` 汇总审阅（删/改类/补三段默认全勾 + 写入范围「仅本书/升级为全局」+「先不写」零写入）；⋯菜单加「X-Ray 精化」行与状态字；深链 `?xr=ai|airun|airev`；
xraycheck 批4 断言 6 条、全量 **46 绿/0 红**。首轮红灯是真缺陷：估算把批次下限钉 6 遮住了预算↔批次联动，已改为按详情体积（900 字/条、tokens≈chars/1.5）现算。
Flutter 侧交付登记（2026-10-02 · `bd59923`）：能力点 `read.xray_refine`（expect=json）+ `ai_validate` **防幻觉钉子**（remove/retype 只能引用送出的批次行首词，模型自编即判输出不合约定）+ 能力矩阵 kAiCapRows 行 + `ai_core_test` 计数 12→13；`xray_refine.dart`＝`XrRefineRunner`（按 `read.xraiBatchChars` 默认 3000 切批·单条超预算自成批不丢词·顺序逐批·pause/resume 只挂起下一批·单批失败重试一次后跳过·**连续两批失败自动中止护额度**）；三类动作零迁移落库（删→markDeleted·改类→新 `setEntityType`+add 登记·补→registerUserWord·库里没有的只计 skipped）；三屏 key 与原型逐一对齐。**R7 口径变更（不静默绕行）**：多批逐批弹审阅会打断流程，故在 core/ai 开第二条出口 `aiGateDenied`/`aiRunJsonBatch`——门控、留痕、结构校验仍全在 AiService 内；审阅由「预检卡拿一次确认 + 写库前结果审阅」两道承担。features 侧不再直取 AiService（R7 守护现场仍红即拒收）。

## 7. 测试与门禁口径
