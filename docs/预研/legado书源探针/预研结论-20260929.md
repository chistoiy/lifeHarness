## 3. 关键实证（影响产品决策的三条）

1. **真站老化是常态，不是异常**：探针日当天，XIU2 纯规则 5 源搜索全挂，得奇路径 404。⇒ 产品必须支持**用户自换源 + 源失效可感知**（源健康态/一键换源），否则首个版本即"打不开"。
2. **规则子集破不了重反爬站**：bilinovel 的 JS 是完整反爬流程（ticket + WebCrypto），需要配套 `java.*` 桥 + WebView。⇒ 不追求"全网可读"，按覆盖率诚实表述。
3. **手写新规则可行且高效**：biqumo 是现场新编纯规则源，四段全通（含 base64 `document.writeln` 混淆定向解码 `_decodeWriteln`）。⇒ 预置少量"经维护的规则源"比依赖公共订阅列表更可控（合规面也更干净，见 §8）。

## 4. 期 4（JS 引擎）技术路线结论

| 事项 | 实测 | 判定 |
|---|---|---|
| JS 语义正确性 | qjs 与 node 对 8 条真实源 `@js` 片段输出 **8/8 一致** | ✅ 路线成立 |
| pub.dev `quickjs` 1.0.1（FFI/native-assets） | **本机不可用**：无 C 工具链（gcc/clang/cl/cmake 全无）+ native-assets 在 Dart 3.10 仍是实验特性 | ❌ 不作为落地路径 |
| Android 侧集成 | 需 NDK 编译（flutter_js aar 或 CMake） | ⏬ **后置独立立项** |
| WebView 渲染腿 | curl 403 的站点在 Chromium 内可完整过墙取 DOM（101 个小说节点） | ◐ `webview_flutter` 可作 D 档，需逐站选活源 |
| Windows 进程桥编码 | `Process.runSync` 默认按 GBK 解码子进程 UTF-8 stdout → 乱码 | 必须 `stdoutEncoding: utf8`（两处踩坑） |

## 5. 采纳（架构与范围 · **后于同日撤销，见 §0**）

**采纳「阅读内核合并 + 书源领域平级隔离」**，明确拒绝「做第二个阅读器」与「把书源分支混进 read 现有文件」两种方案：

```
lib/features/booksource/            ← 新 feature，书源域全收
  data/     规则引擎（legado_lite 拆件）/ JS 桥 / 订阅库 / 抓取调度
  domain/   BookSource / SourceSubscription / ChapterDoc 契约实现 / 源健康态
  presentation/  书源管理页 · 书源搜索页 · 发现页 · 在线开书衔接
lib/features/read/
  仅新增 <100 行 ChapterDoc 契约（EpubDoc 与书源各实现一个）
  reader_page 只改 3 处泛化：开书守卫 / EpubRef 扩 kind:'source' / cfiPrefix 前缀泛化（合计 <15 行）
```

- **依赖方向单向**：`booksource → read 契约`；`read/` 内除开书守卫外**禁止 import booksource 业务**。
- **为什么不是侵染式分支**：read 模块 47 文件 / 32,620 行 = 全项目 27%，且是多会话热点区。侵染会让每个阅读器任务多读 1~2k 行无关上下文（AI 会话写区冲突与混淆主因），而两套相似模型易改错分支。
- **产品数据面不可分裂的依据**：书摘 `cf{c,p0,p1}`、`book_toc_nodes`、`reader.pos` 均**不耦合 epub 路径** ⇒ 同书架、同书、同一套划线/计时/统计账本，在线源与本地 EPUB 天然同源。
- **复用面**：DocStore 段落快照（`snapshot/chapters/<i>.json` 的 title/charCount/paras + `weights.json`）可直接承接抓取正文；foliate `SectionProgress` 字符权重插值已验**单调 + 章间无缝（差约 1e-6）** ⇒ 在线书的翻页/进度语义与 EPUB 一致。
- **范围**：本期 = 期 1 元数据 + 期 2 在线阅读 + 期 3 下载本地化；期 4 JS 引擎后置独立立项。
- **数据层**：DB 现 **v27**；v28 已被 X-Ray（V1.54）预留 ⇒ 书源表取 **v29**（订阅/源/健康态/抓取任务 manifest 落库口径在开发计划中定）。
- **纪律**：移植 `legado_lite`（1388 行）时拆成 ≤800 行三件；测试按域拆 `bs_engine_* / bs_online_* / bs_dl_*`；新用例统一 `import test/helpers.dart`。
- **切换触发判据**：仅当书源引擎需要**跨产品复用**时，才升级为独立 package——目录隔离本身已是现成的搬运单元，不必提前抽包。

**前置状态更新（2026-09-29 复核）**：原「批 0 前置 = 拆分 `reader_page.dart`（当时 2826 行）」**已解除**——该文件现为 1104 行，阅读器已按 `reader_*.dart` 拆件完成。批 0 不再需要结构改造，直接进入期 1。

## 7. 否决

- ❌ **独立第二个阅读器 / 第二套阅读数据模型**：与"同书架同书同一套划线计时账本"的产品前提冲突，且复制 32k 行量级的阅读 UI 无收益。
- ❌ **在 `read/` 内按 `if (isSource)` 侵染分支**：见 §5 理由。
- ❌ **本期引 pub `quickjs` 包**：本机无 C 工具链 + native-assets 未启用，实测不可用。
- ❌ **`encoding` 包做 GBK**：已从 pub 下架，改用 `fast_gbk`。
- ❌ **书源订阅集合作为预置内容入库**：合规与老化双重不可控（见 §8），预置只放少量自编规则源。
- ❌ **本期做 WebView 渲染腿与源登录**：依赖人机验证与 UI 配合，随期 4 一并后置。

## 8. 合规边界（硬约束）

- 仓库内**不入库**第三方书源集合 `shuyuan.json`（22 源订阅）与真站抓取正文 `dl_real/*_txt`（版权内容）。
- 入库范围仅限：探针代码副本、两个 fixture 源定义（`biqumo_src.json` 手写规则 / `fake_source.json` 仿真）、验证报告 HTML。
- 产品侧红线沿用需求清单「运行模式」：**除用户自行配置的订阅与源站点外，无任何内置网络目的地**；书源由用户主动添加，App 不提供源市场。

## 9. 未决（**随 V1.55 撤销全部作废** · 原文保留备重启时续议）

2. **字体反混淆**：本语料 0 个 `fontMap` 源，无真样可验；TTF cmap 解析件是否本期做（PUA 回写管道已验，缺解析）。
3. **人机验证类桥 API**（`getCookie` / `startBrowserAwait` / `getVerificationCode`）：需人工在场 + WebView 配合，交互形态未定 → 随期 4。
4. **卷结构**：酷我 API `volume_name` 已可直接取（876 章 → 2 卷）；HTML 源的分卷规则解析留待有活源再定。

6. **源健康度模型**：老化实证要求"可感知失效"，但探活频率、失败计数阈值、是否合并到设置页统一管理——待原型确认后定。

## 10. 否决（2026-09-29 同日撤销登记）

- **决定**：产品负责人 2026-09-29 晚指令「检查所有需求和记录，移除 legado 阅读器，这个需求不做了」→ V1.55 撤销，本期与后续均不排期；产物删除、预研留档。
- **根因（数据面）**：纯规则子集对活源覆盖率太低——XIU2 22 源中仅 5/22 纯规则，且**验证当日 5 源搜索全部失效**（关站 / 登录墙 / JS 挑战墙 / 连接重置）；要让在线读体验可用必须补期 4（QuickJS/NDK + WebView 渲染腿 + 22 个桥 API + 源登录与人机验证），投入产出比不成立。
- **产品面**：阅读模块定位回归「本地文件导入 + 豆瓣/OpenLibrary 元数据」，不引入第三方源站抓取这一长期维护负担与合规灰区。
- **重启触发判据**：① 用户明确要「在线找书读」而非本地导入；② 愿意批期 4 的引擎与渲染预算；③ 合规口径重新确认（不内置书城与源市场、第三方源与正文不入仓库）。三条同时成立才重评，且**先读本文再动手，勿重做预研**。
- **仍然成立的可复用结论（将来别重测）**：见 §2 / §3 / §4 与 §0 摘要——`fast_gbk`（`encoding` 已下架）、qjs 与 node 8/8 一致、DocStore 段落快照 + foliate `SectionProgress` 字符权重可承接抓取正文、目录倒序需按 chapterList 首字符 `-` 与「第X章」双判据转正、真站需 UA 池 + Referer。
