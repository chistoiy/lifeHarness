## 1. 对原 PRD（X-Ray V2 修订版）的评估结论

原 PRD 主体机制成立（手动触发 / 断点续跑 / 增量解析 / MD5 复用 / 备份导入 / AI 可插拔），但需按实测修正：

| PRD 原文 | 修正 | 依据 |
|---|---|---|
| 「Drift 本地缓存」 | 本项目已定案 **sqflite**（DB 现 v25），勿引 drift | 选型记录 decision-sqflite-over-isar |
| 「CFI 位置绑定」 | 用现有**简化定位：章+段**（同划线书摘 `QuoteCf`），不做官方完整 CFI | 阅读器分页实算体系；引官方 CFI 会与书摘锚点分裂 |
| 「book_task/xray_* 表（修订）」 | 代码中**均不存在**，是新建不是改表 | 全库检索确认 |
| 「GLiNER ONNX 端侧 NER」 | **移出关键路径**。Dart 侧无成熟运行时+tokenizer+性能数据，端侧小时级风险高；本预研证明轻抽取档已能出可用 X-Ray | 见 §2/§3 |
| 「重型任务锁定阅读」+「电量<20% 自动暂停」 | 轻抽取档下**不需要**：全集量级手机外推 <5 分钟。降级为「GLiNER 类重核才需要的可选项」 | §4 功耗实测 |
| 「EPUB 文件 MD5 为主键」 | 成立，但现状**从未算过文件 hash**（现指纹=size\|mtime）。需导入时补算 + 存量书懒回填 | 现状盘点 |
| 「导入时预估全书字数」 | 全文统计较重；改**导入时按 ZIP 字节估、弹层里对选定区间精算** | §4 |

## 2. 三档抽取核实测（同素材、同口径）

档位定义：
- **B 档**＝纯频次基线（姓氏/·翻译名/地名机构后缀/缩写/《》/字符 n-gram 词频）
- **A 档**＝B＋章节 TF-IDF 置信分＋边界熵＋碎片包含抑制＋**称谓人名通道**（先生/教授/警司…）＋停用词
- **C 档**＝jieba 分词＋词性分类＋TF-IDF＋停用词（dart_jieba 的参考实现口径）

量化（GT=人工标准答案；召回取 Top150；噪声=Top40 泛词/残留）：

| 指标 | B | A | C |
|---|---|---|---|
| 简史·地名 | 2/23 | 5/23 | **23/23** |
| 简史·人名 | 1/14 | 2/14 | 1/14 |
| 简史·术语 | 10/25，噪10 | **18/25**，噪3 | 14/25，噪1 |
| 阿加莎·人名 | 4/20 | **13/20** | 1/20（波洛被标成地名，HMM 碎切翻译名） |
| 阿加莎·地名 | 0/12 | 0/12 | 4/12 |
| 全集耗时(桌面) | ~15s | ~20s | ~4min（5M字采样） |

**核心事实：没有任何单档全赢。** A 胜在人名/术语/零依赖/速度；C 胜在地名与词边界；停用词治不了两档各自的结构缺陷（A 的后缀碎片、C 的 POS 误标人名）。

## 2.5 E 档补验（PMI 结合度 / TextRank / 常用词表+称谓路由 / 图谱显示过滤）

因三档面板暴露「共现网络混入非实体词」，追加第四轮验证（`code/e_tier.py`，E＝A 档＋四招后处理）：

| 补验项 | 实测效果 | 判定 |
|---|---|---|
| PMI 结合度阈值 | 仅剪掉低结合拼接碎片；神论/学家这类**内部高结合的后缀碎片拦不住** | ⚠️ 保留为轻量防线，不是碎片主解 |
| TextRank（共现图 PageRank 真身） | 排序微调：简史术语噪声 3→2/40，「世纪/大约」掉出 Top12，召回 18/25 无损 | ✅ 免费带上，作置信分成分 |
| **常用词表＋称谓路由** | 小说术语噪声 **7/40 → 0/40**；「波洛先生/奥利弗夫人/查尔斯爵士」自动归入人名榜且全部真名；阿加莎 E 档人名 Top15 首次全净化 | ✅ **本轮最大增益**，词表必须含裸称谓词 |
| 图谱显示过滤（类型开关+提及阈值） | 网络图非实体词可交互排除 | ✅ UI 层必备 |

**D2 别名合并结论修正**：前轮「0 组、证伪」需更正——「子串+称谓」规则在**称谓组合名**上有效（波洛先生↔波洛、奥利弗夫人↔奥利弗 自动成组，候选 8 条），无效的只是「不同译名变体」（白罗/Poirot 类）。生产口径：称谓组合并＝规则自动；译名变体合并＝AI 层+用户确认。

E 档量化对照（GT 口径同 §2）：简史术语 18/25 噪声 2（=A 召回、更净）；阿加莎术语噪声 0/40、人名 13/20 保持；地名/机构仍走 D4 gazetteer 通道。**最终一期抽取栈：A 档通道 + 常用词表（含裸称谓） + 称谓路由 + TextRank/PMI 并入置信分 + gazetteer + 对白通道。**

## 3. D 组增强实测

| 增强 | 结果 | 判定 |
|---|---|---|
| D1 对白归属（引语+说话动词邻接） | 阿加莎 **334 个角色获得台词归属**，Top=波洛/奥利弗/马普尔/汤米 | ✅ 一期收录（小说价值大、成本=正则通道） |

| D3 共现图 | 小说 400 边可用；社科稀疏、规模化会糊 | ⚠️ 二期做「相关实体」，不做主视图 |
| D4 地名词典 gazetteer（仅 200 词演示表） | 简史**新增 73 地名**（印度/英国/中国/罗马/埃及/希腊…）、阿加莎 60 个（伦敦 2065 次…），**单枪追平 C 档地名** | ✅ **升为第一位增强**：几十 KB 替下 1.9MB jieba |

## 4. 体积 / 功耗 / 内存（实装护栏）

- APK 增量：一期（A档+gazetteer+称谓+停用词表）**≈ +0.3~0.6MB**（词典资源为主，零新依赖）；二期若上 dart_jieba 再 +1.9~3.5MB。
- 每本书索引体积：**0.1~1MB**（实体 500~2000 条＋每实体截断上下文；mention 全量存会到 6~25MB，**必须限流**）。
- 功耗：单本 2~5s、百万字全集外推 2~4 分钟 ≈ 阅读 3 分钟的电量，**不需要锁定阅读/电量暂停**。
- 内存护栏（必做，否则低端机翻车）：按章流式读 DocStore（勿整本驻留）；n-gram 计数先章内低频剪枝再全局合并（demo 峰值 275MB → 目标 30~60MB）；全局单飞串行（复用预载服务幂等先例）。
- 素材画像副产品：阿加莎「正文」1655 万字里 **36% 是泄漏的 HTML 属性文本**——demo 解析层所致，生产 DocStore 走正规 html 解析无此问题，但提醒：任何「段落文本」都必须先过标签/实体清洗再统计。

## 5. 拍板架构（一期）

```
EPUB → DocStore 段落文本（现有） → [并行通道] 
  ①正则通道：·全名 | 姓氏+语境动词 | 称谓+名 | 地名后缀 | 机构后缀 | 大写缩写 | 《》
  ②n-gram 通道：2~5字候选 + 边界熵 + 包含抑制 + 章节TF-IDF + 停用词(中英+称谓词)
  ③gazetteer 通道：国家/城市/地区词表最长匹配 → 地名榜
  ④对白通道：引语↔说话人归属 → 人名榜附加「台词数/代表语录」
→ 跨类型仲裁（同名保留最高置信类别）
→ xray_entity(name,type,mention_count,first_anchor{章,段},score,source_channels,aliases,ai_desc,relation)
→ xray_mention(entity_id, anchor{章,段}, chapter_title, context截断) ——每实体限流
→ 面板：按置信分排序，低分折叠；用户手动增删/合并 → 回流为词表（下次解析直接命中）
```

二期候选（按验证后优先级）：dart_jieba（仅补文本内地名/历史地名）、共现「相关实体」、AI 层（别名合并/释义/缩写展开，走现有 deepseek/Ollama 通道）、`.xraybak` 备份导出。

## 6. 图谱/脉络产品结论

- 对「读者掌控书的脉络」真正有效：**章节×实体分布导图**（`panels/xray_graph.html` 的脉络视图）与**对白/出场节律**；
- 共现网络图＝观赏性彩蛋（好看、信息密度低、规模化糊），不做主视图；
- 触发词/划线联动（D5）上线后，导图个性化热点是差异化卖点（Kindle 没有读者侧数据）。
