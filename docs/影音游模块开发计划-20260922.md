## 三、视觉基线：桌面微拟物（四类卡）

> **⚠️ 2026-09-23 视觉基线反转（以此为准，覆盖本节与 §一 用户指令行、变更单 S-08/S-10 的「微拟物」口径）**
>
> 逐屏高保真过程中，用户明确否掉「桌面微拟物」方向（原话：页面风格不统一、大色块太丑），影音游**改回与主框架一致的扁平卡**：复用 `index.html` 的 `--page/--card/--accent` 令牌，`--mds-*` 全部派生自这三个变量，因此书架自动跟随 app 主题与深色模式，不再是独立的米白亚麻桌面底。本节下文的「桌面底 / 双层阴影 / 悬停微抬 / FC 卡带材质」等**保留为已否决的原始设想**，Flutter 落地**不实现**。当前事实源见 `prototype/index-media.html` 的扁平 `.mds-item` 卡集（电影=2:3 竖版海报、剧集=同类、音乐=黑胶碟形态、游戏=16:10 横向 key-art）。
>
> **三类记录模型（2026-09-23 定案，覆盖 §二/§三 中「四类同构进度」的旧口径）**：
> 1. **音乐＝轻量化「听后感」流**，不建 `media_items` 目录、不强制逐曲打卡、无进度/计时。书架「音乐」分区渲染为：`＋ 记一条听后感` + `导入歌单` 两个按钮 → 横向歌单轨道（`MPLISTS`，可导入网易云/Spotify/QQ音乐/Apple Music）→ 听后感时间流（`MMOMENTS`，每条 = 歌名 + 歌手 + 一段感受 + 关联歌单 + 时间；同一首歌可多次追加，展示为不同日期的多条）。类型 chip 的音乐计数 = 听后感条数。
> 2. **影视（电影/剧集）＝记录作品本身**，看完/追完后录入，有明确起止点与进度。保持 `media_items` + `media_sessions` 模型。
> 3. **游戏＝作品为主体，每次游玩追加日志（`glogs`）**。**「和谁玩」是每类游戏的通用日志字段**——单机/主机/派对合作/网游 都能在一条游玩日志里记 `who（谁一起玩：朋友/搭档/一个人）+ hrs（时长）+ what（这次玩了什么）+ when（日期）`；不存在「只有网游才和谁玩」：**主机游戏（如《双人成行》《马力欧赛车》）同样是和朋友一起玩**。而 **进度（主线%/支线%/全成就%/周目/通关）是可选聚合，只在该作品有剧情进度时才显示**（`mProg` 依据 `x.mainPct` 是否存在返回百分比或 null，不再以 `mode==='网游'` 作为分支门）：王者荣耀等竞技网游无通关%→不显示进度条；原神/主机剧情作有→显示。**段位/场次仍判为无价值、不记录**（这条不变）。`mode` 仅作展示标签（主机/派对/网游…），不参与字段门控。进度弹层与详情页的游戏分支据此统一。演示数据含《双人成行》（主机合作·有进度·和女朋友）直接证伪旧口径。


**桌面底**：米白偏暖亚麻纹理（`#f7f1e6` + 4px 交叉纹）；深色模式 = 深胡桃木纹（`#2d1f14` + 竖向细木纹）。整页统一 `--mds-desk-bg` 令牌。

**光影规范**（全 kind 通用）：主光源左上前 45°；卡片双层阴影——第一层"接触阴影"（0 2px 4px rgba(0,0,0,.28)），第二层"环境阴影"（8px 20px 36px rgba(0,0,0,.12)）。悬停 `translateY(-6px)` + 阴影扩大；点击 `translateY(0→-3 回弹)`。CSS 变量 `--mds-shadow-soft` / `--mds-shadow-lift`。

**字体**：中文标题思源宋体 / 霞鹜文楷（复古），英文 grotesque；卡带侧面/BOX 书脊用等宽字体（模拟工业丝印）。CSS 变量 `--mds-font-title` / `--mds-font-mono`。

## 六、导入与去重规范

**渠道矩阵**（原型 `M_IMP` 列 13 家，分五类）：

- **授权**：Goodreads · Letterboxd · Steam（OpenID）· Spotify（Web API）· Apple Music
- **电脑端配对**：网易云音乐（本地数据库）· B 站追番（导出工具）
- **API**：IMDb（第三方镜像）· TMDB · TVMAZE · MusicBrainz · IGDB
- **文件**：Letterboxd Diary CSV · IMDb ratings CSV · Steam playtime CSV · Douban 片单导出 · Apple TV .xml · 网易云 m3u8 · Spotify playlist .txt · Discogs Collection CSV · IGDB JSON · B 站 JSON · Jellyfin/Emby 库导出 XML · Plex Watch List CSV · 微信读书式剪贴板
- **剪贴板**（按来源模板自动识别 8 家：豆瓣 / IMDb / Letterboxd / TVMAZE / RateYourMusic / Discogs / Steam / 网易云）

**规范**：
- 格式表以**解析器数据包**（`assets/media_import/*.json`）随包（渠道 id · 字段映射 · 去重键 · 示例片段），符合需求清单 V1.15 插件化方向。
- **三级去重**：`external_ids.<source>` → `title + creator + release_year` 归一化 → 笔记 `dedup_hash = sha1(itemKey + at_min + normalize(body))`。命中即跳过并在预览里标「已存在」。
- 解析兜底：失败提示走 AI 识别格式（AI 能力矩阵「导入解析兜底」），不可用则跳过不崩。
- 导入写库**整批事务**，UI 提供「撤销本批」。
- 导入的原文与想法若来自同一记录，落 `media_notes` 一行两字段；`origin` 记渠道，便于二次清洗。

## 八、跨模块联动

- **L4 时间账本**：`media_sessions` 结束即写流水（分类=娱乐），回填 `txn_id`；删除会话同事务删流水；计时明细被改（时长/日期/起终点或补记）按差量更新同一条流水（`txn_id` 复用不新建，补记走 `origin='手动补记'`）；游戏内购/OST 购买费默认生成"影音-购买"支出流水（`media_items.fee` 字段本版本暂不落，与书籍购书费同批讨论）。
- **L5**：名场面卡「→日记」插入今日日记草稿；「→待办」生成任务（无截止日，遵守「截止日当天不算逾期」既有口径）。
- **L7 目标**：每日观影分钟 + 每周听歌小时 + 每月游戏时长 + 每年看完数 + 每周影音天数 + 每月名场面数 六路汇聚；周报与仪表盘卡引用。
- **收集箱**：每条收集箱可分流为「影音笔记」，落库 `origin='收集箱'`。
- **与阅读的关系（2026-09-22 定案：不共表）**：`media_sessions` 独立建表，字段与 `book_sessions` 同构（起止/时长/倍速/进度区间/来源/`txn_id`）；`media_dict` 与 `book_dict` 各自独立，即使 name 相同也不跨库合并。**代码层共用**：`SessionRepository` 抽象基类 + L4 流水写入器同一实现；`WheelPicker`/`SectionCard`/`AppToast` 等 UI 组件从 `lib/shared/widgets/ui_kit.dart` 复用。理由：① 阅读位置/百分比/章节 与 影音时间点/集号/曲目/周目 口径完全不同；② 账本分类不同（阅读 vs 娱乐）；③ 影音游后续可能整块插件化，分表便于随插件卸载清理。
- **插件化**：影音游整体是**插件化第一波试点**（需求清单 V1.15）——数据表 `media_*` 前缀、宿主能力 API（Shelf/Timer/Dict）走同一实现；解析器数据包独立发布。

## 九、风险与未决

1. **倍速折算 vs 播放时长**（需求侧未决）：观影倍速时（2x）实际花 30min 但内容长度 60min——落 `minutes` 是 30 还是 60？默认走 `speedFold=true` 折算成 60min 便于跨天比较，但会让「今日时长」和真实生活时间对不上账。**原型阶段用屏来定**：在 `m-sheet-sess` 计时明细里显示两列（真实 30 / 折算 60），让用户选择保留哪列作为账本金额；**已定案 2026-10-07（批4 开工当场·产品选推荐项）**：明细行与汇总**同时显示真实与折算两列**，**账本（L4 娱乐块）金额吃真实耗时**，折算只在读侧算，`media.speedFold` 提供整体切到折算的开关（生效点随设置批）；1x 行不重复显示折算列。规格＝`docs/handoff/交棒话术-20261007-影音游批4资料页与计时明细.md` §0。
2. **微拟物 CSS 性能**：径向 `repeating-conic-gradient` 黑胶 + 双层阴影 + 悬停 `filter:blur` 桌面底 · 60 条目同屏时低端机（Snapdragon 6 系列）可能掉帧。Flutter 侧对应 `CustomPainter` + `RepaintBoundary` 隔离，每卡独立层；原型阶段先在 Chrome 100 条压力测试；性能不达预期时降级方案：脊视图不渲染 3D 效果，桌面视图仅悬停时才展开渐变。
3. **封面来源与版权**：真实条目海报/专辑封面从 TMDB/Spotify API 拉取有版权边界，原型用色板 + 标题字面渲染兜底；Flutter 侧走用户本地上传 + 「无封面时按 `color_idx` 显示脊纹」的降级路径（与书籍 `BS_COV` 色板机制同构）。
4. **OCR 依赖**：Android ML Kit 需额外原生库，本机网络受限时装不上——批3 先做「手动粘贴 + 图片附件」，OCR 作为可选插件包，装不上时入口置灰而非隐藏。
5. **综艺归属**（**已定案 2026-09-22**）：现有 `sheetAddMedia` 类型 chips 含「综艺」；新原型四类（电影/剧集/音乐/游戏）无综艺位。**决定**：综艺归并至「剧集」，BOX 卡副标可显示 "Variety"；如后续需要独立卡型（如透明亚克力立牌），走需求变更流程另批。
6. **动漫与播客**：动漫作为剧集 `subType`（不落独立 kind）；播客 V1.x（`kind=podcast` 预留但不实现，与需求清单 V1.25 一致）。
7. **共享面回灌时机**：§〇 S-01 记录页第四 tab 内容区改造牵动 `#recMedia` 现有 3 条卡片 → 收口人回灌前，本副本内的「工作台」屏 `p-records` tab 只在 `recTab==='media'` 时切换到本副本的 m- 工作台；index.html 侧保持不变。批1 结束前完成回灌。
8. **视觉规范与 index.html 便当格漂移**：本副本内 m- 前缀屏走桌面微拟物；同一 app 内两种视觉风格并存是**有意为之**（阅读/日记/笔记 = 便当格 · 影音游 = 微拟物）。收口人不需为共享面（我的/设置）引入微拟物；只在 S-05 计时条文案/图标处按 kind 切换。
