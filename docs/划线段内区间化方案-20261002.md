# 划线段内区间化 · 方案与工单（对标微信阅读 · 2026-10-02 立案）

> 现象（产品负责人真机反馈）：选中一句话划线，落库后**整段**都被画上；目标是「选多少画多少」，
> 全面对标微信阅读的段内任意区间划线。
> 本文件是立案与拆解，**未动任何代码**；按红线：先改原型 → 逐屏确认 → 再进 Flutter。

## 一、根因（已定位到行）

划线命中判定与渲染都是**段粒度**，不是字符粒度：

- 数据：`book_quotes.cf` 存的是 `{c:章, p0:起段, p1:止段}`（`reader_models.dart:30` 注释即此语义），
  **没有段内字符偏移**；
- 渲染：`reader_page.dart`/`reader_sel_ops.dart:168-185` 用 `cf.covers(ci, pi)` 判断某段是否被划线覆盖，
  命中即整段套色 → 用户看到的「整段画线」；
- 对比：选中态的精确子串高亮走 `reader_chrome.dart:318 _subSpan(th, p, q0, q1)`（轮4③ 落的段内子串渲染），
  所以**选中的时候是准的，保存后就变整段** —— 两条路径粒度不一致，这才是「不正常」的地方；
- 删除互清（`reader_sel_ops.dart:267` 起）也按 `p0/p1` 全等匹配，段内区间化后必须改成区间重叠语义。

## 二、数据口径（零迁移）

`cf` 是 TEXT 列存 JSON，扩两个字段即可，**不加列不抬 DB 版本**：

```
{ "c": 12, "p0": 3, "p1": 5, "o0": 18, "o1": 42 }
```

- `o0` = 起段内起始字符偏移；`o1` = 止段内结束字符偏移（半开区间 `[o0, o1)`）；
- **缺 `o0/o1` 的行＝旧数据**，按整段解释（`p0` 从 0 起、`p1` 到段尾）——老库不改写、不回填，
  下次用户重划自然升级；
- 跨段选区：中间段整段（`o0=0`、`o1=len`），首尾段用偏移；
- 与 X-Ray 锚点（章+段）互不影响：X-Ray 出场锚点本就是段级，不做字符级。

## 三、渲染改造点

1. `covers(ci,pi)` 之外新增 `rangesIn(ci,pi) → List<(int,int)>?`（返回该段内要上色的若干区间；
   不在本段返回 null），`reader_chrome.dart` 的段渲染把 `_localHl/_hlQuotes` 命中从「整段套色」
   改成「按区间套色」，复用 `_subSpan` 已有的子串着色与缩进不吞逻辑（缩进前缀恒普通文本，见 2026-09-28 真机反馈）；
2. 一段内多条划线：区间并集上色，颜色冲突时取**后画的**（与微信阅读一致），并在行内分段成多个 span；
3. 段闪烁定位（X-Ray 跳转）与搜索命中底色（`markStyle`）与划线底色互不覆盖：叠色顺序固定
   划线 → 搜索命中 → 选区，选区永远在最上。

## 四、重叠与编辑规则（**已由产品拍板 · 以《交棒话术-20261002-真机轮3-四条》R3-4 为准**）

> 2026-10-02 拍板：**不允许重叠，重叠以后者为准**。下表原写「合并成一条」的三条**作废**，
> 改为「旧行裁剪/裂段、新行独立」，完整规则表见 R3-4。保留本表仅为留痕。

| 场景 | 微信阅读行为 | 本方案采纳 |
|---|---|---|
| 新划线与旧划线**完全相同** | 取消该划线 | 采纳（同区间再点＝撤销，已有语义） |
| 新划线**被旧划线包含** | 合并成一条，颜色取新的 | 采纳：旧行改写为新区间，颜色/分类取新的 |
| 新划线与旧划线**部分交叠** | 合并成一条覆盖并集 | 采纳：并集写回旧行，其余重叠行删除（一条划线=一行书摘，避免同句多行） |
| 新划线**跨段**且中间段已有划线 | 连续成一条 | 采纳：一条 `cf` 表达跨段区间 |
| 同一段内**不相交**两处 | 各自独立两条 | 采纳 |

删除：选区删除＝删与选区**完全相同**的行（保守）；重叠裁剪不做（微信阅读也没有「擦除一段里的一小条」）。

## 五、影响面清单（改这一处要一起回归的）

- 书摘库/划线列表（`/read/quotes`）：文本预览按区间截取，不再显示整段；
- L5 联动（划线=书摘）、`attachCfOnDup`（同键撞车补 cf，v33 局部唯一索引那套）：判重键仍 `(book,cf,text)`，
  cf 变了以后**同段不同区间不再互相判重**——这是期望行为，但 `idx_bq_dedup` 的键组成要复核；
- 划线自动存为书摘开关 `read.brSync` 关态：`reader.hl` KV 里的 `_LocalHl.cf` 同步扩字段（`encode/decode` 兼容缺省）；
- 阅读器「本书书摘与划线 N 条」计数、统计页按章/段钻取；
- 测试：`reader_select_test` / `reader_ui_test` / `read_data_test`（划线判重与 v33/v34 链）必须补
  「段内两条不相交划线各自成色」「重叠合并后条数守恒」两类用例。

## 六、选区手柄样式（同批并入 · 对标微信阅读）

现状：Flutter 侧走 Material 默认 `TextSelectionHandle`（圆球 + 粗杆，随主题色），视觉厚重、且与
本 App 的线性极简语言不搭；微信阅读是**竖向细杆 + 端点小圆帽**，起止两枚形态不同（上端帽在杆顶、
下端帽在杆底），随正文色/主题色，拖起来不挡字。

本批要改成（原型先行，逐屏确认后落地）：

- 形态：杆宽 2px、圆帽直径 8px，杆高＝当前行高；上柄圆帽朝上、下柄圆帽朝下（镜像），
  颜色取主题 accent（关＝正文灰阶最深档，跟随多套主题）；
- 热区：视觉纤细但命中区放大到 **24×44 逻辑像素**（沿用 V1.53.2 轮5 的 15px 手柄放大经验，
  避免「看得见点不着」）；
- 行为不变：拖拽跨页翻页（V1.53.4①）、粒度默认选字（V1.53.4④）、选区弹层跟随；
- 与划线的关系：拖完直接落段内区间（第二节口径），手柄位置即区间端点，不再"吸附到段首段尾"；
- 禁用 emoji/图标字体，纯 CustomPainter 画杆与帽（与 `brHandlePlace` 同一处改）。

## 七、批次切法（原型先行）

- **轮 A 原型**（`prototype/index-bookshelf.html` 阅读器演示区）：①段内局部划线渲染态（同段两条、颜色不同）；
  ②重叠合并后的态；③划线列表按区间截取的预览；④**新样式选区手柄**（起止两枚 · 细杆圆帽 · 拖拽中态）；
  ⑤深链 `?hl=range`，`tools/xraycheck.js` 或新建 `hlcheck.js` 断言。
- **轮 B 数据与渲染**：`cf` 扩字段 + `rangesIn()` + 段渲染套区间（含旧数据整段回落）+ 手柄 CustomPainter 换形。
- **轮 C 交互**：重叠合并/撤销规则 + 删除互清改区间语义 + 书摘库预览截取。
- 每轮门禁按两档流程：批内只跑受影响文件，收口才全量 + 三包（发版需另行授权）。
