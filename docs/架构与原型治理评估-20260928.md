## 1. 背景与目标

代码量持续增长（lib 122,696 行 / 281 文件；prototype 72,685 行 / 18 个 HTML），
单文件过大与全局汇聚文件导致：①人工维护困难；②AI 开发会话每次定点改动都要吞
数千行无关内容，浪费 token 且易误伤。治理目标：分开管理、缩小单文件、清理归档，
且**保证既有功能不被改坏**。

## 2. 评估结论（代码侧）

### 2.1 现状健康的部分（不动）

- `lib/features/*` 全部为 data/domain/presentation 垂直切片，交叉验证
  （package 路径 + 相对路径两种 grep）确认**特征互零 import**。
- 跨模块联动已收敛于 `lib/shared/linkage/`（923 行，8 文件），为设计好的唯一交汇层。
- `core/host/`（module_registry / event_bus / mount_point）插件化骨架符合
  大模块插件化治理决策；包级多 package（melos）拆分**否决**：边界已干净，
  import 全量重写成本远大于收益（另见模块插拔化调研结论）。

## 3. 评估结论（高保真原型侧）

- **单文件 SPA 交付形态保留**（深链逐屏验收与无头回归挂在其上）；
  问题在壳层约 4,800 行被复制 15+ 份（index-bookshelf 7,800 行/901KB），
  base64 图标仅占 6~9% 且为同一组品牌图标重复内嵌。
- **版本堆积无归档**：habitcheck 3 份、被否的 index-V3/V4、已降级的 index-reader、
  非本会话产物的 v2.html/index-v2.html（勿动）、diary-batch2-preview、index-sync 平铺。
- **tools/ 杂草化**：16,665 行 JS 中长活校验器不足三成；一次性 patch、日志、
  `tools/reader/.chrome-probe/`（浏览器缓存）混住；根目录躺 APK/log/tmp_bs.js。
- **正确样板已存在**：`tools/health/` 片段管线（v2_css/v2_pages/v2_sheets/v2_js
  + patch2 装配 + check2 全文件校验）＝维护在片段、交付仍单文件。
- 建议：A 归档区 `prototype/archive/`（git mv + 引用扫描）；B 片段管线仅推广到
  **还在改的专版**（bookshelf/kits/sync…），已收口验收的不回炉；C 存量主区大文件
  加屏索引（屏→锚点→行号段）；D tools 分箱 `tools/check/`、`tools/attic/`；
  E 所有权规则不变（产物仍单一 `prototype/x.html`，共享面唯一写者 index.html）。
