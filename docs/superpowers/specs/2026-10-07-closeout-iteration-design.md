## 1 · 范围边界

### 1.1 本版做

- **A 影音游线**：资料屏与计时明细屏实现 → 影音笔记库与名场面复习 → 统计/轨迹/目标/影音单 → 设置全键生效与四家样本导入 → 线收口发预发布。
- **B 健康线**：批2 喝水＋睡眠＋工作台骨架 → 体征五类 → 身体数据与目标 → 症状与报告 → 运动 → 用药 → 趋势/周报/设置 → 共享面挂载与线收口。
- **C 收口人**：共享面唯一写者＋编号分配＋错峰表＋两次发版与双端推送（每次先取得产品同意）。
- **验收背包**：两次人工逐屏轮（A5、B8 各一次）＋每批新增屏真机读数当场补上。

### 1.2 本版明确不做（写死，中途长出即属范围变更，需另立批次过门）

1. 插件平台全部（计划书 M4：manifest/签名/声明式 UI 渲染/沙箱权限内核/插件中心/物品与影音游双试点迁移）。
2. 影音游导入的**无样本九家**（Spotify·Apple Music·TVMAZE·MusicBrainz·IGDB·Discogs·B 站·Jellyfin/Emby·Plex）与任何需第三方 API Key 的在线补全／新番新专续作提醒（`media.notify*` 三键本版只落存储与设置行，**不接网络**）。
3. 健康批8（服药/测量/复诊三类提醒真排程接通知通道＋AI 小结）——延后项原样保留。
4. 「明示延后至 V1.x」长尾：全局搜索五处占位、待办两级子任务/重复规则/分组管理、字号调节（无障碍）、日记语音附件、笔记 PDF 导出与 `.enex` 导入、摘录库图片卡片。

## 9 · 施工流程整改（2026-10-07 拍板）

本节只治「同一个收口轮里墙钟被非施工动作吃掉」这一条，不动范围、不动质量闸。

**实测病灶（按占比排序，时间戳取自本仓 git log）**

1. 派发形态错配（最大项）：19:47→20:34 设计＋计划＋B1 滚轮 47 分钟；20:34→21:52 B2 一屏 78 分钟；21:52→22:56 A1＋A2 64 分钟。对照 23:05→23:38 内联 1818 行 42 分钟——同一个人写的同类件，派发吞吐约为内联的 1/9。原因是子代理要自行重建仓库上下文（STATUS／同类页／API 事实），而主线程在等期间因写区互斥无事可做。
2. 计划文档预写了用例代码：481 行计划里凭空写出的东西被实跑否证四处（`time_blocks.duration_min` 列不存在、`sessionById`、`MediaSession.copyWith(patch)`、`test/dashboard_page_test.dart` 不存在）——错误计划不省时，只把时间换成「实现者发现→回来问→改计划→重发」的回路（22:42 那枚提交就是这条回路的账单）。
3. 门禁重复执行：实现者跑过的增量测试被主线程复跑，变异后又补一轮「确认绿」，违反同一收口轮全量只跑一遍与「复跑先取得同意」。
4. 自造文档红灯：变更日志长行 889>800、两条从未存在的脚本路径死链、自审粘连行——修自己写坏的文件纯属损耗。
5. 超长会话本身：五小时以上的会话后期在重复载入同一批文件（工单与计划被多次重读），压缩/恢复也计在墙钟里。
6. 机器与网络**不是**主因：`flutter analyze lib test` 31 秒，批内增量 18 文件 117 绿属常规时长，本会话从未跑独占全量（约 12 分钟）。

**整改（本迭代生效）**

- R1 实现批主线程内联直写，不派发（细则已入《开发计划书》§7.5「派发边界」）；派发只留给可真并行的审计／走查／工装。
- R2 计划与工单只写「事实＋边界＋验收判据」，不预写用例代码；写入的每个列名／方法名／文件路径必须先 grep 证实存在。
- R3 一波门禁：每线一次 analyze＋面板点名增量一次＋≤3 刀＋doclint，复跑需先取得同意。
- R4 文档只改该改那一段（长表按锚点 grep 取段），不整读三件套；新立文档不引用未创建路径。
- R5 批次收口即开新会话，不让会话无限延长。
