# v0.2.15-nfc（预发布 · release split-per-abi · **只挂一枚 arm64**）

钉版提交 `38d355a7`（`0.2.15+6173`）· 从这一枚在新开 worktree `lh-rel38d355a7` 里构建 · 分包形态 arm64 抬偏移：**装机 versionCode 期望 8173**（出包后以 `aapt2 dump badging` 实测为准）。

**本枚是 NFC 卡片模块的整体发行**：自上一个已挂预发布 `v0.2.15-desktop-b1`（6144）之后，NFC 卡片模块从建表到贴卡回执的整条链路（批1～批3f，11 提交）只装过复测包、没挂过预发布；本枚把它们一起挂出。
数据库 **v49**（本模块新增 `nfc_cards` 表与三列；自更早版本覆盖安装按迁移链自动升级，数据不丢、无需卸载）。

机上若是 6163～6173 之间的同签名包 → 本包为正常升级路径，覆盖安装即可。

## 本版本内容

### 一、贴卡零闪现（批3～批3d）

- 贴卡走**透明中转界面**：系统把 NDEF 派发给一个不可见的中转 Activity，它把标签内容直投给已经在跑的 App 引擎，**主界面全程不出现**——桌面贴卡只看到回执，不会被拉到 App。
- 引擎**常驻**（随进程活、不随界面销毁），中转界面每次都走直投通道；真机 logcat 可验 `relay → dart：已投递（引擎活着）`。
- 冷启动场景（App 没在跑）等根路由就绪再取路由（≤640ms 重试），不再「闪一下然后什么都没发生」。

### 二、贴卡回执：自绘悬浮横幅（批3e～批3f）

- 后台贴卡（App 不在前台）时，在屏幕顶部弹一条**自绘悬浮横幅**：圆角卡片＋左侧圆点＋一句话结果，2.6 秒自动消失，不挡点击、不抢焦点。
- 为什么不用系统横幅：真机（HyperOS）上 `Importance.high` 渠道的通知**只进通知栏、不上浮**（`dumpsys` 里 importance=4 已核），系统层无强制手段；自绘悬浮窗与悬浮胶囊同一套机制，可证可用。
- **滑入动效**：整条卡片从屏幕一侧滑进来、停 2.6 秒后往反方向滑出去，**进场方向逐次交替**（第一次左→右、第二次右→左），连贴两张有来回穿梭的节奏。
- **通知栏不留条目**：横幅弹成功即止，不再补静默记录；系统通知只在「横幅弹不出来」（没给悬浮窗权限／ROM 拒绝加窗）时兜底。
- 前台贴卡仍是应用内 toast，最轻、不打扰。

### 三、NFC 卡片管理与写卡（批1～批2）

- 管理屏按五段大类组织（快捷动作／打卡／呵护宝宝／计时分类／阅读书目），列表双节点＝卡＋目标，卡片带自选色与备注。
- 写卡走标准 NDEF **RTD-URI**（`lh://nfc/<cardId>`）＋ Android Application Record，写完即「贴一下就能用」；内容工具可读／改／清空标签，改写本 App 网址时自动补 AAR。
- 一张卡绑一个目标：计时分类（开始/结束）、阅读书目（开始/结束计时）、习惯打卡、呵护记录、快捷动作。

## 已具备能力

- 贴卡触发全链路：总闸 → 去抖 3s → 校验 → 查表 → 失效判定 → 确认 → 执行 → 回执。
- 卡失效／未绑定有明确回执，未绑定落 `/nfc` 绑定引导。
- 备份／回收站／DB 迁移链与既有模块同规（`nfc_cards` 已纳入备份排除名单校验）。

## 已知项（非缺陷）

- **横幅在 HyperOS 上呈半透明（80%）**：系统把第三方 `TYPE_APPLICATION_OVERLAY` 窗口强制调暗，App 侧参数回读 1.0、系统侧仍 0.8，`updateViewLayout` 重设无效——这是 ROM 行为，不是渲染 bug。要实心只能改「透明 Activity 画横条」路线。
- 通知栏默认**零条目**（含静默留档也不写）；升级后旧版本留下的「贴卡记录」条目与渠道会在首次启动时自动清掉。
- **卡复制能力**（同一事件多张卡触发，如卧室一张、厕所一张）可行性已确认、零架构改动，但**本轮未实现**，登记在排期池 #19，待点名开工。
- 写卡需要手机支持 NFC 且有可写标签（NTAG213/215/216 等）；标签被系统其它 App 占用时按系统选择器走。

## 安装要求

- Android 8.0+（minSdk 26）· arm64 设备 · 纯本地无账号。
- 首次使用需授予「显示在其他应用上层」权限才有悬浮横幅；不授予则回执退回系统通知（横幅没了，但功能不受影响）。
- **覆盖安装即可，勿卸载**（卸载＝清库，本地数据全丢）。
