# V1.52.1 时间模块真机修复批（预发布 · 取代 v0.1.29-m1.time-v152）

本包在 V1.52 时间模块改造（统一编辑弹层 / 单一计时态 / 拆分合并撤销 / 时间账本 L4）之上，
修掉真机逐屏验收第二轮反馈的四条。功能全量说明见上一版发布正文。

## 一、合并丢块（P0·数据损失）
「⇧ 与上一个合并」原先会把两段一起弄没（真机截图：合并后 16:47 段消失，16:50 段仍是原时长）。
根因＝合并块的身份归**较早那段**（与原型 `tpMerge` 一致：保留早者的分类与备注），
而实现无条件删掉传入的邻段，等于先删掉合并块要写回的那一行，随后的 update 命中 0 行。
现在写死为：**删的是非存活段**，存活段区间取两段并集（起始取早、结束取晚），轴/块/日/周与时间账本同步。

## 二、撤销当帧生效
点「撤销」原先要再操作一次（例如再添加一个事件）才看到画面恢复。
根因＝撤销闭包用的是弹层自己的 `ref`，而弹层在提示条出现前就已关闭，`ref` 随 State 一起 dispose，
`invalidate` 静默失效（数据其实回了，画面没刷）。现在闭包只依赖随 App 存活的根容器与日期，撤销落库后立即重刷。

## 三、提示条一定自动退场
带「撤销」按钮的提示条会一直挂着。根因在框架：`SnackBar.persist` 的默认值就是「有没有 action」，
带按钮即永挂。现在显式 `persist: false`，撤销条 5 秒退场（比原型的 2.8 秒宽裕，保证来得及点撤销）。

## 四、弹层内反馈改在弹层内显示
校验拒绝类提示（补录结束晚于计时中起始、时长不足 2 分钟无法拆分、上下没有 30 分钟内可合并段、
标签取所选分类默认标签）原先借道页面提示条——在模态弹层下既被遮在弹层后头、又不会退场。
现在写在弹层标题下方的一行提示里（✕ 红 / ✔ 主题色），点分类或再次操作即清。

## 五、时间滚轮可视 3 行
`CupertinoPicker` 默认 `squeeze = 1.45`（框架注释「visually mimic iOS」）会把可见行数放大成
高度 ÷ 行高 × 1.45，于是 78px 高显示成 5 行。现在锁 `squeeze: 1.0`，与原型等距 3 行一致。

## 六、一级分类显示名称
6 列窄格（约 48dp）下 `ChoiceChip` 会把文字挤到 0 宽（屏幕上只剩一个色点），
并且选中时把色点替换成 ✓，与原型「色点 + 名称 · 选中为强调色实底白字」不符。
现在改自绘胶囊：色点 7×7 + 名称（放不下才省略号），一级格最多 3 行、超出可滚；
子分组用同一组件，色点沿用父级分类色 60% 透明度。
