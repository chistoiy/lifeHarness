# v0.1.31-ai（预发布）· AI 服务商可增删改 + AI 使用记录

版本 `0.1.31+4029` · 数据库 **v26**（新增 `ai_calls` 表，老库自动升级） · 分支 `feat/m0-skeleton`

## 这批修了什么 / 多了什么

### 1. AI 服务商不再是写死的三行（V1.53.1）
之前端点地址与模型名基本写死，本地 Ollama 换 IP 要改代码、中转站没法接。现在：

- **服务商列表可增、可改、可删、可切换**。预置 7 条（DeepSeek / OpenAI / Anthropic / Kimi / 通义千问 / 智谱 GLM / Ollama）只是**首次种子**，改过之后不再被覆盖。
- 每条服务商自带 **名称 · Base URL · 模型名 · 协议 · 独立 API Key**。中转站/自建网关可以带 `/v1/api` 这类自定义后缀；协议二选一（OpenAI 兼容 / Anthropic Messages）。
- **局域网明文端点允许**：`http://192.168.x.x:11434/v1` 这种能存，但保存前必须在表单里确认「是局域网/回环地址」，列表行标黄提示。
- **Key 各存各的**：系统加密区按 `ai_key:<服务商>` 分槽，中转站和官方端点不再共用一把 Key。升级前的旧全局 Key 自动作为回落，不用重填。
- 表单里可直接**测试连接**：向该地址发一次最小请求，回真实状态与归因（401 Key 无效 / 404 路径或模型名不对 / 429 限流 / 未送达）。
- **当前使用中的服务商不给删**（防止把唯一可用配置删没），删其他条目会连带清除它的 Key。
- API Key 输入框**默认掩码**，点右侧眼睛看明文；编辑已有条目时把已存 Key 掩码预填并提示末 4 位。
- 模型名从「Key 配置」卡挪进服务商编辑（模型属于端点），「Key 配置」卡只显当前端点摘要。

### 2. AI 使用记录：发出去了什么、回来了什么，都能回看（V1.53）
之前每次 AI 调用只留下 token 聚合和日志流水，**发送内容与返回正文调用结束即丢弃**。现在每次调用在本机 `ai_calls` 表落一行：

- 一行＝时间 · 状态（成功 / 失败 / 取消 / 未启用）· 模块 · 能力点 · 入出 token · 耗时，**点行内联展开** System / User / 输出三段全文，失败行给原因段。
- 全屏页 **设置 → AI 增强 → AI 使用记录 → 全屏查看**：无底栏、列表通底；顶部一行统计 + 记录设置 / 复制 / 删除筛选结果；筛选收成 **时间 / 状态 / 模块** 三个胶囊，**点某个胶囊才横向弹出该组选项**，选完即生效并自动收起；关键词可跨正文搜索。
- 行内可复制输入 / 输出 / 整条，可删除本条；**长按行**复制该行摘要。删除类动作一律二次确认。
- **记录设置**：① 停记正文（关闭后新调用只记用量，已存正文不被自动删）② 保留天数 7/15/30/90/不限（默认 30 天，改完即刻裁剪超期）③ 单条正文上限 8000 字（超出截断并标「已截断」）④ 清除已存正文（保留用量）⑤ 清空全部记录。
- 门控拒绝（总开关没开 / 能力没授权 / 该端点没 Key）与用户取消**同样入账**，这样「为什么这条没发出去」也查得到。
- **API Key 永不入库**、不进日志、不进备份明文；记录表在本机数据库内，随 `.lhbak` 本地备份与云同步快照一起走。

### 3. 接法规范固化 + 机器守护（R7 / R8）
- **R7 接入门**：全应用调用 AI 只许一个入口 `aiRunWithReview(taskId, vars)`，业务模块不感知端点/模型/协议/Key/门控/审阅/留痕。阅读侧此前的绕行已改走统一入口，豁免清单清零。
- **R8 登记闭环**：提示词资产里的能力点必须在 AI 增强页能力矩阵有授权行（漏登记＝用户开不了＝功能静默不可用），反向也禁「死行」；能力点六项字段非空；业务模块不许直读端点/Key 的 prefs 键。
- 规范全文见《需求清单》§六 原则 8/9/10。
